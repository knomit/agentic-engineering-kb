# Mini Shai-Hulud and Miasma (May-Jun 2026): the worm's execution layer was the AI coding tool's config directory — opening a cloned repository ran the payload with no install step, uninstalling the package did not remove the planted hook, and valid build provenance did not flag either wave

One self-propagating supply-chain worm lineage in two waves, recorded in OWASP's Q3 2026 exploit roundup: Mini Shai-Hulud, 2026-05-10 to 05-12, and the Miasma/Hades waves from mid-May to early June 2026. What makes it a pack fact rather than a registry-compromise story is the execution mechanism: both waves used the configuration files of AI coding tools as the way code ran.

**The three properties that defeat the usual defences:**

1. **Opening a repository is an execution event.** Miasma compromised Red Hat's published `@redhat-cloud-services` npm packages and added configuration files for Claude Code, Gemini CLI, Cursor and VS Code that could execute when a repository was opened. The roundup states the user-facing consequence directly: opening a cloned repository in an AI coding tool can execute code without an installation step. The conventional mental model — that `npm install` is the dangerous moment — does not cover this.
2. **Persistence outlives the dependency.** Mini Shai-Hulud entered through a stale OIDC trust relationship in TanStack's CI, harvested cloud, CI and npm credentials, and planted a Claude Code hook and a VS Code task that uninstalling the affected package did not remove. Removing the compromised dependency is therefore not remediation; the agent-configuration directories have to be checked separately.
3. **Attestation did not help.** Both waves defeated build-provenance attestation: registries were compromised at scale while the legitimate provenance mechanisms gave no indication of malicious content. Valid provenance or attestation alone is not proof that an artifact is safe.

**Reported scale and blast radius.** The May wave compromised more than 170 packages with over 518 million downloads, affecting TanStack, OpenAI and Mistral AI. OpenAI confirmed that two employee devices were compromised and that limited credential material, including material relating to code-signing certificates, was exfiltrated, which prompted full certificate rotation. The June wave backdoored 32 Red Hat cloud-services packages and led GitHub to disable 73 Microsoft repositories.

OPERATIONAL CONSEQUENCE: put the AI coding tools' configuration directories under file-integrity monitoring, review any change that introduces or modifies an agent-configuration file as a code change, and assume developer-workstation credential theft in your registry-compromise playbook. Pin dependencies with integrity hashes and prefer short-lived OIDC publishing.

WHAT THIS DOES NOT MEAN. The download figure is a measure of the compromised packages' total reach, not of how many installations executed the payload, and the roundup does not quantify the latter. "Two waves" is one lineage, not two independent campaigns — the roundup says so explicitly, so it must not be counted as two data points for how often this happens. And this is a different mechanism from a poisoned skill or memory file ([[7bd6c6c9]]): here the planted file is the tool's own configuration, which is why uninstalling the carrier leaves it in place.
