# Tampered Claude Code extension on the Cursor marketplace (Oct 2026): the injected loader ran before the extension's own code, used only built-in OS tools, and wrote its SSH persistence outside the install directory — so removing the extension did not remediate

SCOPE FIRST, because this incident is easy to over-report. "On October 29, 2026, Cursor reported that a tampered copy of Claude Code extension" "(anthropic.claude-code, versions 2.1.313 and 2.1.312)" "was available and served in the Cursor extension marketplace for a few hours" — "Cursor reports that it was live from about 2:27 AM to 1:35 PM Pacific Daylight Time (PDT)." "Anthropic confirmed to Microsoft that their systems were not compromised" and "they did not develop the malicious package posted in Cursor marketplace"; "the malicious packages found on Cursor marketplace were never published nor distributed from" "Microsoft Visual Studio Marketplace and from npm @anthropic-ai/claude-code." "At this time, all evidence suggests that the incident is limited to Cursor marketplace." There is no CVE and no actor attribution — Microsoft states its hunting results "do not establish attribution to a particular threat actor."

THE EXECUTION MODEL IS THE FIRST ENGINEERING LESSON: THE AGENT NEVER HAS TO BE USED. The package "included a JavaScript function that executed before the extension’s expected code," and "[t]he injected loader runs when the extension module loads." So no agent feature, tool call or prompt was required — loading the module was the trigger. "The loader uses embedded components and built-in system tools to establish persistent access" "without downloading another executable," and "[i]t suppresses command output and silently catches errors to conceal failures and malicious activity." A detection strategy built on second-stage downloads or on noisy failures therefore has nothing to bite on.

WHAT IT TOOK AND WHAT IT DID NOT. Reconnaissance collected "the hostname, username, operating system, architecture, home directory," "working directory, and global Git email," plus "environment-variable names containing terms such as KEY, TOKEN, SECRET, PASS, AWS, or GCP." Critically, "[t]he callback sends matching environment-variable names, not values" — a secrets INVENTORY rather than a secrets theft, which is a targeting step and which egress monitoring keyed to credential-shaped payloads will not see.

THE ACCESS MECHANISM. "First, the loader checks the user’s authorized_keys file for the comment svc-telemetry"; "[i]f the marker is missing, it appends an embedded Ed25519 public key." It then runs an outbound tunnel with the arguments "-N -R '*:0:localhost:22'", which "forwards connections through the tunnel to port 22 on the victim’s loopback interface," and "disables ordinary host-key checking, bypasses the normal known-hosts file." "On Unix-like systems it prefers autossh, falling back to ssh; on Windows it uses a hidden PowerShell loop," and "[t]he loops wait sixty seconds after SSH exits before retrying." Microsoft is careful about what a live process proves: "A running SSH process does not necessarily mean the attacker gained access."

PERSISTENCE LANDS OUTSIDE THE EXTENSION, AND THAT IS THE OPERATIONAL CRUX. The mechanisms are a macOS "User LaunchAgent with RunAtLoad and KeepAlive" (artifacts "~/Library/LaunchAgents/com.apple.sysmond.plist, ~/.config/.smt,"), a Linux "User-crontab @reboot entry," and on Windows an "Attempted SysMon scheduled task requesting SYSTEM execution" with a Startup-folder fallback at "%APPDATA%\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\sysmon.cmd". They are deliberately camouflaged with "names such as SysMon and com.apple.sysmond, which resemble monitoring components." Hence the two statements a responder must act on: "Removing or updating the extension does not remove artifacts written outside its installation directory," and "Cursor’s reported server takedown does not remove artifacts already present on a device." This is the second independently documented instance of that shape in the AI-coding-tool supply chain: a separate npm and PyPI worm pair is recorded in which uninstalling the package likewise left the planted hook behind in the AI coding tool's config directory — so for agent tooling, treat uninstall and vendor takedown as containment of DISTRIBUTION only, never as remediation of a host.

THE CONTROLS THE POST NAMES, AND THEY ARE CHEAP. Hardening: "restricting extensions to approved publishers and configuring an extension installation cooldown." A cooldown is the control matched to this threat's actual shape, because the exposure window was roughly eleven hours — a delay before any newly published version may be installed converts a short-lived poisoned release into a non-event without requiring anyone to detect it. For response, the order matters: "Preserve the extension package, modified SSH authorization files, generated keys and scripts," then "Isolate devices with evidence of loader execution or backdoor installation," then "Confirm the key against the fingerprint in Indicators of Compromise before removing the exact unauthorized entry," and "Inspect each startup object’s configured action before removal; names alone are not sufficient." Credential rotation is conditional rather than automatic: "Rotate credentials and revoke sessions from a known-clean device when telemetry indicates credential access."

THE INDICATORS, for anyone who needs to hunt this specific event: the configured remote destination "134.209.82[.]225" and beacon URL "hxxp://134[.]209[.]82[.]225:8099/beacon"; the authorized-key fingerprint "SHA256:0Z6R+DF64Do2nwQic8a7kkfDLNNk4IiK+2U2Rci4htk"; the tunnel identity filename pattern ".stk_[0-9a-f]{10}"; and the JavaScript entry-point hash "ecb58cb29078d9646ad1dcdbe51526f2d9cfea06be5fb2ab183e8ecc3ab6bf15", which Microsoft flags as "not a Visual Studio extension (VSIX) package hash" — matching it against VSIX hashes will find nothing. Microsoft's own caveat on hunting output applies: "A result is an investigative lead, not proof of compromise."

A SECOND VENDOR'S ACCOUNT ADDS THE POPULATION AND THE COMPROMISE POINT. Cognition's November 2026 security guidance reports that "Cursor reported that fewer than 5,000 users installed the malicious extension" — a bounded figure, attributed to Cursor, and a count of users who INSTALLED rather than of devices on which the loader ran or the backdoor was established. On where the tampering happened, the same account states that "the version of the extension differed from what was published on the Open VSX registry (the open extension registry that Cursor uses)" and concludes "This suggests that the adversary compromised the extension publishing process downstream of Open VSX." Note the modality: "suggests", not established, and no actor is named there either.

The operational reading of that compromise point is the part worth keeping. The divergence between what the registry had published and what was served is what exposed the tampering, which means registry-level provenance was not the control that failed and would not have caught this: a check that verifies only that a package came from the expected registry does not cover the publishing path between that registry and the client. The same account also supplies the delivery vector the cooldown control exists for — "As extensions auto-update, this means that users could have received the malicious extension without taking any actions" — and recommends the control in the same terms as the primary, "Maintain an allowlist of approved Chrome extensions (e.g., via Chrome Enterprise) and VS Code extensions, and configure an auto-update delay for extensions", while giving no length for the delay.
