# Unit 42's "Double Agent": a Vertex AI agent inherited excessive permissions through a GOOGLE-managed service account, so the over-privileged identity was one the operator never created and could not see in its own IAM review

Unit 42's "Double Agent" research, disclosed 31 March and 1 April 2026, recorded in OWASP's Q1 2026 exploit roundup. A deployed agent on Google Cloud's Vertex AI Agent Engine, built with ADK, inherited excessive default permissions through a GOOGLE-MANAGED service account. The researchers extracted credentials, acted AS the service agent, reached resources in the consumer project, and accessed restricted container images and source code in a producer project. No CVE was assigned; Google's response was to revise its documentation.

The transferable finding is about who authored the identity. A managed agent runtime attaches a service identity the operator did not create, does not enumerate in its own least-privilege review, and whose default grants were set for the platform's convenience rather than against the operator's threat model. The review covers the permissions you granted; this identity is not among them, and it is nevertheless inside the agent's blast radius.

Two consequences, and the second is the one usually skipped: scope service-agent permissions PER DEPLOYMENT rather than accepting the platform default, and treat the cross-project direction as reachable — the path here ran from a consumer project into the PRODUCER project that supplied the images and source, a trust boundary most deployments assume runs one way only.

OWASP's other stated mitigations: short-lived credentials, isolated agent execution contexts, policy-engine validation of tool and identity usage, and mandatory least-privilege defaults.

Note what the vendor response does and does not do. A documentation revision changes guidance for the next reader; it does not re-scope an identity on a deployment that already exists, and nothing notifies the operators of those deployments. Do not read "Google revised its documentation" as remediation.
