# An agentic pen-test framework drove a 151,000-failure password spray at 2,900 failures a minute and never authenticated once — while the same actor's stolen multi-tenant app credentials reached privileged cloud access in under 3 hours

Microsoft Threat Intelligence reports that Storm-0940, a China-state-aligned actor active since 2021, used ARTEX — "a system of LLM-driven agents that run an autonomous penetration test", operating "with little needed human interaction" — to scale attacks against hundreds of organisations from September 2026. "in this case the actor used ARTEX to accelerate the activity to machine speed."

THE CAMPAIGN HAD TWO ACCESS PATHS WITH OPPOSITE PROFILES, AND THE LOUD ONE IS THE ONE THAT FAILED. Keep them apart; they are not two views of the same event.

**The spray, October 10–14, peaking October 11.** "Storm-0940 used ARTEX to attempt to sign-in to more than 2,250 tenants." Within that, the spray was "targeting 327 accounts across eight organizations to gain access to Microsoft 365 and Exchange Online". "Microsoft telemetry captured 151,000+ failed logon events", with "activity peaking on October 11 at 2,900 failures per minute" and more than 111,000 in a single day; 48 accounts saw more than 1,000 failures each, and "lockout responses represented nearly 98% of all activity". The outcome: "Despite the scale, no successful authentication, token issuance, Graph call, or directory change was observed."

**The supply-chain path, which did work.** "Microsoft assesses that Storm-0940 was responsible for the recently disclosed ConnectWise supply chain compromise of a multi-tenant application" — a cloud backup application — and the attackers used that application's credentials to reach downstream Microsoft 365 tenants. There, the campaign ran "over 200 sign-ins in under 4 minutes using 4 application credentials", "including multiple instances where the time from initial targeting to privileged access was less than 3 hours". Follow-on Microsoft Graph activity in some environments covered reconnaissance, application credential changes and privilege changes. ConnectWise's compromise was publicly reported on October 15 and advised on October 16 — after the downstream access had already happened.

**What an operator should take from the two profiles.** A credential-guessing phase driven by an agentic framework produces a volume and a lockout ratio that no human campaign produces, so rate and lockout-ratio alerting catches it — and catching it is nearly worthless here, because it achieved nothing. The path that succeeded generated 200 authorised sign-ins in four minutes with valid application credentials: no failures, no lockouts, nothing for a volume threshold to fire on. Detection effort spent on the loud signal bought no coverage of the quiet one. The agents "can work around the clock, on weekends, and on holidays and attempt multiple breach paths simultaneously", so both profiles can be live at once and the quiet path can complete inside the window in which the loud one is still being triaged.

**A READING TRAP IN THE SOURCE.** The mitigation guidance says "Inventory all four application IDs listed in this profile and record the local service-principal Object ID in each tenant", but the hunting queries list three application IDs. Do not report four IDs on the strength of the queries, or three on the strength of the instruction; reconcile against the indicator table before acting.

Scope: this is one vendor's telemetry and its own attribution assessment of an actor and of the ConnectWise incident, published as an assessment rather than as a confirmed account. The article does not state how much human oversight Storm-0940 applied, so the degree of autonomy in the operation is not established — only that the tooling is built to run with little of it.
