# Claude web_fetch nested-link exfiltration (July 2026): the allowlist had an escape hatch

Reported by Ayush Paul, July 2026. Anthropic's web_fetch tool already had the obvious defence: it would not visit URLs the MODEL constructed, nor arbitrary attacker-specified ones. But it WOULD follow links discovered inside content it had already fetched. That exception was the whole vulnerability.

The chain: an attacker stood up a honeypot presenting as a service needing sign-in, which instructed Claude to browse user profiles alphabetically via a sequence of generated links. Each fetched page served the next URL, so every hop was a link "found in content" rather than one the model invented — formally inside the rules the entire way. Combined with Claude's access to memories from past sessions, the model was induced to encode private details into the URLs it followed, leaking the user's name, home city, and employer.

Anthropic's fix was to remove link-following from fetched content entirely.

The transferable lesson is about how egress allowlists fail. The control was framed as "the model cannot choose the destination", which sounds airtight; the attacker simply supplied the destinations one at a time from a server the model was permitted to read. Any channel where attacker-controlled content can specify the NEXT fetch is a full exfiltration channel, however constrained each individual hop looks. When auditing the third leg of the lethal trifecta, count indirect and chained egress — not just whether the agent can call an arbitrary URL directly.
