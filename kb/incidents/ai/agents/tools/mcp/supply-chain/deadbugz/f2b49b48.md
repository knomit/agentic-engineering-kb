# Deadbugz (Aug 2026): an MCP server behaved normally for its first three tool calls, then rewrote its own tool metadata to point the connected agent at SSH keys, AWS credentials, shell history and Kubernetes config — it never read the files itself

An active malicious-MCP distribution campaign, recorded in OWASP's Q3 2026 exploit roundup. A productivity-suite MCP server was promoted through 23 GitHub pull requests to prominent AI projects, all submitted within a 74-minute window on 2026-08-10 and disclosed on 2026-08-12. No pull request was merged, so there is no confirmed downstream compromise; the significance is the technique.

The technique has two parts, and both are needed to see why ordinary controls miss it.

**It waited.** The server behaved normally for its first three tool calls, then changed its tool metadata to direct the connected agent toward SSH keys, AWS credentials, shell history and Kubernetes configuration, while concealing the activity from the operator. Approval of an MCP server is therefore a judgement about its behaviour at approval time, and tool metadata is mutable afterwards: the roundup's own characterisation is a runtime trust failure in an already approved server. Any review, scan or human check that happens at install or first use is positioned before the payload exists.

**It used the agent as the retriever.** Rather than reading the secrets itself, it steered the trusted agent into collecting them. So the server never touches the sensitive paths, and controls that watch what the SERVER does — its filesystem access, its egress — see nothing: the reads are the agent's, from the agent's own host, with the agent's own authority. The detection surface is the tool-description change and the agent's resulting behaviour, not the server's.

OPERATIONAL CONSEQUENCE: treat a tool's advertised metadata as mutable, attacker-controlled input on every call rather than as a property fixed at connection time. Pin or hash the tool definitions you approved and alert when a connected server's descriptions change mid-session; and judge an MCP server by the actions it induces in the agent, not only by the actions it takes itself. This is the mechanism behind the general claim that the agentic supply chain's payload lives in the metadata ([[78ab92f2]]), instantiated with a dated campaign and a specific delay.

WHAT THIS DOES NOT MEAN. No confirmed compromise occurred — "23 pull requests" is the attempted distribution, not a victim count, and the roundup classes it as an active attempted campaign. And three tool calls is this sample's delay, not a threshold: nothing makes the fourth call the dangerous one. The transferable property is that the delay exists at all, which is the same time-shifted activation that makes session-scoped monitoring blind to skill- and memory-file poisoning ([[7bd6c6c9]]).
