CONTRADICTIONS: none between crawled sources this run. One TENSION worth naming rather than
flattening, and it is now recorded inside the two facts concerned rather than as a separate
decisions fact, because both sides are correct at different layers: SESSION AFFINITY IS BOTH
REQUIRED AND DANGEROUS. Azure requires pinning for stateful model APIs (and says to return 429
rather than silently reroute a pinned client to a backend with no history). Anthropic's routing
incident shows stickiness is exactly what amplified a 16% per-request defect into ~30% of users
affected. The resolution is that pinning concentrates both correctness and failure onto the
same client: it is mandatory when the backend holds state, and it obliges you to measure defect
rates per SESSION rather than per request. No fact in the kb contradicts another as a result.
