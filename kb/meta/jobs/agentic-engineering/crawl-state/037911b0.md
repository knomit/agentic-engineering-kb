THE RUN'S MAIN FINDING — THE MCP PROTOCOL MOVED UNDERNEATH THE PACK AND NOTHING FLAGGED IT.
The versioning page now names 2026-07-28 as Current, superseding 2025-11-25. This is a large
backwards-INCOMPATIBLE revision: protocol sessions and Mcp-Session-Id removed; the
initialize/initialized handshake removed (version and capabilities now ride per-request in
_meta); a mandatory server/discover RPC; SSE resumability removed; ping, logging/setLevel and
notifications/roots/list_changed removed; tasks moved out of core into an extension;
server-initiated requests (roots/sampling/elicitation) replaced by Multi Round-Trip Requests;
Roots, Sampling and Logging DEPRECATED; OAuth DCR deprecated for Client ID Metadata Documents;
error codes renumbered under a new allocation policy.
Read as one decision rather than a list: every piece of per-connection state was deleted so a
tool call is fully self-contained. What it buys is stateless load balancing. What it costs is
that state moved UP into tool arguments (model-visible, injection-reachable) and at-least-once
delivery moved up into the application. That trade is the reusable insight, not the change list.
NOTE HOW IT WAS CAUGHT: not from the MCP feed, but from an AWS ML blog TITLE naming the spec
date — on an index that had never been swept. Cheap tripwires beat deep reading.

CONTRADICTIONS: none between crawled sources. One live THREE-WAY disagreement was found and
recorded as a decisions fact rather than flattened — b8db449a. Azure says pin sessions and
return 429 rather than reroute; Anthropic's postmortem shows stickiness turned a 16%
per-request defect into ~30% of users; MCP 2026-07-28 deletes sessions entirely. The condition
that separates them is whether the state can be made EXPLICIT and addressable from outside the
connection. Implicit state (a vendor-held thread, a warm in-process cache) forces pinning;
explicit state (a server-minted handle, an event log) lets you delete the affinity requirement.
The operational corollary holds under all three: wherever you pin, the pin is your blast-radius
boundary, so measure defect rates per SESSION, not per request.
