# "If you know the words, grep beats an embedding lookup" — the condition that decides it is whether the corpus uses your query's vocabulary, not how big the corpus is

LangChain's position for agent retrieval is lexical-first: "If you know the words, grep beats an embedding lookup." The shape it recommends is filesystem tools the agent drives itself — glob to find files by name pattern, grep to match literal text inside files without loading them — checking names and keywords before opening anything, then read_file to page the file that matters.

The condition that decides against grep is vocabulary mismatch, and the source names it with a case rather than abstractly: "If our agent greps for "Company A funding," it will miss an article titled "Company A closes $50M Ser[ies B]". A semantic tool backed by a vector store — or, the source notes, by a SQL database, a search API or an MCP server — returning a handful of hits per query ("similarity_search(query, k=4)") is what covers that case.

So the decision is per-query, not per-system. The agent should hold both tools, and the routing rule in its instructions should turn on how confident you are that the corpus words match the query words. This is NOT a claim that embeddings are unnecessary: the same source keeps the semantic tool and says to save it for the cases that need it.

Two boundary conditions travel with this. First, the source prefers agentic retrieval — the agent deciding when, what, and whether to search again — over a single up-front search, reserving the one-shot two-step RAG shape for FAQ-style questions where one query is enough. Second, whatever route retrieved it, "retrieved text is data, not instructions" and "no prompt or delimiter strategy fully prevents this" injection risk; the mitigation offered is output validation, checking that an answer cites the sources you expected and that its claims match them. Stale or off-topic retrieved text is called out as the same hazard in a quieter form, because it reads as credibly as correct text and propagates into later steps.
