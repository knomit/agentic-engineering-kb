# A reasoning-effort setting fails at layer boundaries, not at hard problems — a test that crosses the boundary buys the same correctness as raising effort, and keeps it

The characteristic medium-effort failure in a coding agent is not a hard problem answered badly; it is a change that is correct inside one layer and wrong across two. Anthropic's cost guide for Claude Opus 5.5 gives the shape: on a renamed field at medium effort, the model updates the handler, the handler's tests pass, and the client still sends the old field.

Two fixes buy the same correctness and they are not equivalent. Raising effort to high finds it, and keeps costing more on every later turn of every later task. Adding a test that goes through the client catches the same bug at medium, on the turn it was written, and keeps catching it afterwards without the per-turn premium.

Consequence: when an agent's misses cluster at contract boundaries between components rather than on genuinely hard reasoning, spend the fix on test coverage that crosses the boundary before spending it on a permanently higher effort level. Treat a recurring need for high effort on routine work as a signal that verification is scoped inside a single component.

This does not mean effort levels are a substitute for tests or the reverse in general. It is specifically the layer-boundary class of miss where the two are interchangeable in outcome and very different in standing cost.
