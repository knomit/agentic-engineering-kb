# OpenAI shipped Habitat in Python as "a strategic incursion of technical debt", betting its own coding models would make the rewrite cheap — and in Q2 2026 two engineers with Codex and GPT-5.5 rewrote it in Rust at 6x CPU and 15x memory efficiency

Habitat moved from a client-side Python library to a standalone service in mid-2025 and deliberately stayed in Python, even though the team judged that "the inefficiencies of Python would not be acceptable at 100x scale, making an eventual rewrite almost certain."

The framing was explicit: "we viewed this as a strategic incursion of technical debt", where "Our primary objective then was not cost or resource optimization, but rather unblocking product developers and achieving platform stability." And the deferral rested partly on a bet about tooling that did not exist yet in the form needed: "We also made a calculated wager that the rapid advancement of our own coding models would simplify the technical path in the future. We bet that by the time a full migration off Python was required, Codex and GPT would make that migration achievable. That bet eventually proved correct."

The outcome, as reported: "In Q2 2026, with just 2 engineers, Codex, and GPT-5.5, we were able to rewrite the entire service in Rust." The Rust service "is now handling 95% of our production requests", and "Our data shows the Rust service is 6x more CPU efficient and 15x more memory efficient than the Python version, with significantly lower average and tail latencies." At its peak the Python service served "more than 20 million requests every second"; Habitat overall serves "more than 500 petabytes" and "over 70 million requests every second".

What this supports, and what it does not. The rewrite had three properties that are not general: the interface was already frozen behind a deliberately constrained API the same team controlled, the target was a performance-equivalent reimplementation rather than a redesign, and the reference implementation was live in production and could be shadowed against. It is a single case, self-reported by the vendor of the coding models credited, with no comparison against a human-only rewrite and no engineer-month figure beyond the headcount and the quarter. So it supports "a port behind a stable interface you own is now cheap enough to be worth deferring deliberately" and not "rewrites are cheap now" — and the efficiency multiples are Rust-versus-Python for this workload, not an effect of the models.
