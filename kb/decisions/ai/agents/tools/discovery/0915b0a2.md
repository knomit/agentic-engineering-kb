# Defer tool definitions behind a search tool above ~10K tokens or ~10 tools — below that it costs more than it saves

Anthropic's Tool Search Tool marks tools `defer_loading: true` so their definitions stay out of the initial context; only the search tool itself loads upfront, at roughly 500 tokens. It ships behind the beta header `advanced-tool-use-2025-11-20` and is still published as beta. The docs' example targets `claude-sonnet-4-5-20250929`; they state no minimum model and give no supported-model list, so do not treat Sonnet 4.5 as a floor — check availability for the model you actually deploy. Implementations can be regex-based, BM25-based, or embedding-based.

The measured effect on MCP tool-selection accuracy: Opus 4 went from 49% to 74%, and Opus 4.5 from 79.5% to 88.1%. In their comparison example, deferring preserved 191,300 tokens of usable context versus 122,800 — described as an 85% reduction in definition overhead. These figures are anchored to the Opus 4 and Opus 4.5 generations and are point-in-time: the gain comes from relieving a selection-accuracy problem, so a model that suffers less from that problem has less to gain, and the break-even moves with it.

The numbers that make this a real decision rather than a default: tool definitions are expensive at realistic scale. GitHub's 35 tools cost ~26K tokens, Slack's 11 tools ~21K, Jira alone ~17K, and Anthropic reports an observed worst case of 134K tokens of definitions before optimisation.

Use it when definitions exceed ~10K tokens, when you have 10+ tools, when you are seeing selection-accuracy problems, or when multiple MCP servers are connected. Do NOT use it when the library is under 10 tools, or when every tool is used in essentially every session — there the deferral buys nothing and adds a search round-trip plus the risk that the right tool is never surfaced. The ~10K-token and 10-tool thresholds are Anthropic's stated guidance, not a published measurement.

This is a different mechanism from code-execution-with-MCP, which also removes definitions from context but does so by having the model write code against a filesystem-like tool tree. Tool Search keeps the normal tool-call loop and only changes when definitions materialise.

Deferring a definition is also distinct from deleting one that is already in the prompt: deferral keeps the cached prefix stable, whereas removing a definition mid-session rewrites the prefix and forfeits cache reuse from that point on.
