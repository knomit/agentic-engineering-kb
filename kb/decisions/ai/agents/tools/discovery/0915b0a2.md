# Defer tool definitions behind a search tool above ~10K tokens or ~10 tools — below that it costs more than it saves

Anthropic's Tool Search Tool (beta header `advanced-tool-use-2025-11-20`, Sonnet 4.5 minimum) marks tools `defer_loading: true` so their definitions stay out of the initial context; only the search tool itself loads upfront, at roughly 500 tokens. Implementations can be regex-based, BM25-based, or embedding-based.

The measured effect on MCP tool-selection accuracy: Opus 4 went from 49% to 74%, and Opus 4.5 from 79.5% to 88.1%. In their comparison example, deferring preserved 191,300 tokens of usable context versus 122,800 — described as an 85% reduction in definition overhead.

The numbers that make this a real decision rather than a default: tool definitions are expensive at realistic scale. GitHub's 35 tools cost ~26K tokens, Slack's 11 tools ~21K, Jira alone ~17K, and Anthropic reports an observed worst case of 134K tokens of definitions before optimisation.

Use it when definitions exceed ~10K tokens, when you have 10+ tools, when you are seeing selection-accuracy problems, or when multiple MCP servers are connected. Do NOT use it when the library is under 10 tools, or when every tool is used in essentially every session — there the deferral buys nothing and adds a search round-trip plus the risk that the right tool is never surfaced.

This is a different mechanism from code-execution-with-MCP, which also removes definitions from context but does so by having the model write code against a filesystem-like tool tree. Tool Search keeps the normal tool-call loop and only changes when definitions materialise.
