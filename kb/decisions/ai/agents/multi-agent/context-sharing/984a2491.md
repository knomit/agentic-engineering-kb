# Whether a second agent WRITES decides how much context to give it — share everything with actors, isolate advisors

Six facts in this pack give apparently conflicting advice about how much context to hand a second agent. Cognition says share FULL traces, not individual messages. Anthropic's review loop says the evaluator must start from COMPLETELY CLEAN context, no shared briefing. Cognition's own model-pairing work says fork the primary's full context to the consultant. These are not in conflict once you see the variable that separates them, and it is not task size or agent count.

THE RESOLVING VARIABLE IS WHETHER THE SECOND AGENT WRITES.

Agents that ACT need maximal shared context. Every action carries implicit decisions, and decisions made without sight of the other agent's reasoning conflict at integration time. Cognition's illustration: Flappy Bird built by two subagents produced a Super Mario Bros. background from one and an inconsistent bird from the other. Nothing errored — the failure surfaced only at integration, which is what made it expensive. The same root cause shows up in manager-child topologies, where managers 'assume they share state with their children when they don't', and Cognition attributes this to models not having been trained in environments where cross-agent communication was required, so it does not happen by default and cannot be fixed by telling the manager to be thorough.

Agents that only ADVISE do better with isolated context. Anthropic's reviewer sees the diff and nothing else, deliberately, because the generator's context is long by the time an artifact exists and inherited length degrades the reviewer's attention — context rot. A reviewer starting clean re-discovers only what it needs. This is the specific case where isolation beats sharing, and it works BECAUSE review is read-only.

Cognition themselves narrowed their 2025 anti-multi-agent position on exactly this line in April 2026: multi-agent systems work 'when writes stay single-threaded and the additional agents contribute intelligence rather than actions.' So the 2025 post should not be read as a general case against subagents — it is the case against parallel agents that each mutate shared artifacts.

The model-pairing result is the same rule again: the consultant receives a fork of the primary's full context, but returns broad questions guiding the primary back to the answer rather than a finished result — the primary stays the one that acts. Note the separate and load-bearing constraint there, which does NOT follow from the write rule: the capability gap between the two models must be SMALL. Cognition's SWE-1.5-primary with Sonnet-4.5-consultant FAILED, and their stated wording is 'The gap between it and Sonnet 4.5 was too wide', with the mechanism given as 'the cost and speed wins were real, but the quality ceiling was set by the primary, and the primary wasn't strong enough.' The reason the PRIMARY sets the ceiling is that it is the one that must recognise its own limits, decide to escalate, formulate a useful question, and act on the answer — all frontier capabilities. So a large gap defeats the pattern rather than justifying it, inverting the naive cost argument. Reliably training a weaker model to know when to escalate was still open as of April 2026 — do not design an asymmetric pairing that depends on it.

It is not theirs — it was this pack's paraphrase. The source's own wording and mechanism are quoted above instead. The claim was correct; the attribution was not.)

THE PRACTICAL RULE: before wiring up a second agent, ask whether it will WRITE. If yes, give it everything the first agent saw and serialize the writes. If it only reads and reports, give it the artifact and nothing else, and put a filter on the return path.

That last clause is not optional. Anthropic's evaluator loop requires the generator to filter evaluator feedback against the ORIGINAL USER INTENT before acting on it; without that filter the loop degrades into looping, scope creep, and the generator following the evaluator into work the user never asked for. An unfiltered evaluator-to-generator channel is where the pattern fails, not the review itself. It compounds with the separately documented finding that a reviewer agent asked to find gaps will report some on sound work, because that was the task it was given.

COSTS, which bound all of this. Multi-agent research systems run ~15x the tokens of a chat interaction (agents alone ~4x); on BrowseComp token volume explained ~80% of performance variance, with tool-call count and model choice another ~15% — so the orchestrator-worker architecture wins by buying a way to spend more tokens in parallel across separate context windows, NOT by reasoning better. The generator-evaluator loop measured $9 solo versus $200 for a three-agent harness on a 20-minute task, roughly 20x.

WHAT THIS DOES NOT MEAN. Not a claim that more context sharing is always safer for writers: the boundary conditions still apply, and Anthropic names subtasks needing shared context or having heavy interdependencies as explicitly unsuitable for multi-agent — most coding tasks fall on that side of the line. Not a claim the advisor pattern is permanent either: its value DECAYS as models improve, and Anthropic measured the evaluator becoming 'unnecessary overhead' at Opus 4.6 for tasks inside the model's native capability, remaining cost-justified only at the boundary of it — so re-benchmark on each model upgrade rather than treating the harness as fixed. Also note the corollary that upgrading the model beat doubling the token budget on the older model: reach for multi-agent only after model choice is maxed. Across trust boundaries the write rule cannot be applied at all, because trace-sharing is unavailable at any price — there you accept the coordination risk and compensate with narrow verifiable task contracts and validation of returned artifacts.

STALENESS: the +90.2% figure is anchored to Claude Opus 4 leading Claude Sonnet 4 subagents, both several generations superseded, and the single-agent baseline has moved most, so treat the margin as a point-in-time result rather than the current gap. What does not depend on model generation is the write-versus-advise rule and the finding that token volume explains most of the variance. One thing HAS changed materially: current models orchestrate subagents natively and over-delegate without being asked, spawning them where a single tool call would do — so the deliberate architectural choice described here is no longer the only way subagents enter your system, and the first tuning problem is now damping delegation rather than enabling it.
