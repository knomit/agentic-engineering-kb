# Three distinct single-context failure modes motivate subagent isolation, and only one of them is about context size — self-preferential bias means a model is not a valid verifier of its own output in the same context

Anthropic's dynamic-workflow guidance gives three named ways work inside one context window fails, and the point of giving separate subagents their own context windows and their own isolated goals is to counter them:

- **Agentic laziness** — stopping after partial progress and reporting as if finished (the example given is completing 35 of 50 items).
- **Self-preferential bias** — favouring its own findings when asked to verify them.
- **Goal drift** — losing the original constraints through repeated, lossy compaction.

The three have different mechanisms and therefore different fixes, which is why collapsing them into "long contexts degrade" loses the useful part. Goal drift is the only one that is about context length; agentic laziness is about the stopping rule, and self-preferential bias is about who is judging.

The operational consequence sits on the second one. If a model favours its own findings when verifying them, then a "review your work" second pass inside the same context is not verification — it is the same agent agreeing with itself, and it will pass output that an independent check would reject. The fix is a separate agent instance with the output and the rubric but not the authoring context, which is what the adversarial-verification pattern does; this pack's independent measurement of review convergence between separate reviewers ([[e4e6823a]]) is the same claim from the other direction. The corresponding fix for agentic laziness is an externally checkable completion condition rather than a longer prompt (see [[519ec939]]), and for goal drift it is carrying the constraints outside the compactable context.

WHAT THIS DOES NOT MEAN. It is not an argument that more agents are better. The same source says workflows can use significantly more tokens and that parallelism and specialisation have to justify their coordination cost; and this pack's deciding condition for multi-agent versus single-threaded is whether subtask outputs must be mutually consistent ([[f7dee43a]]), which these three failure modes do not override. Isolation buys independence of judgement, not throughput.
