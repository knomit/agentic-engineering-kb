# Anthropic's own two reports pull opposite ways on parallel agents writing code — what separates them is a per-unit mechanical verifier plus an exclusive claim, not whether the agents write at all

Two published positions from the same organisation point in opposite directions, and both are load-bearing for anyone deciding whether to fan out coding work.

Anthropic's multi-agent research system post names shared-context, heavily-interdependent work, and coding specifically, as unsuitable for an orchestrator-worker fan-out; Cognition's case against subagents says the same thing more strongly. Anthropic's C-compiler report is 16 agents concurrently WRITING a 100,000-line compiler over two weeks, reaching a 99% pass rate on most compiler test suites and compiling Linux 6.9 on x86, ARM and RISC-V. Read-only-ness cannot be the whole deciding variable, because these agents mutated shared code and it worked.

TWO CONDITIONS TOGETHER separate the working case from the failing one, and dropping either is how this becomes a false slogan:

(1) EVERY UNIT OF WORK HAS A MECHANICAL VERIFIER THAT DOES NOT REQUIRE READING A SIBLING'S WORK. A compiler has one: a test suite per language feature, plus GCC used as an online known-good reference. That is what makes a write independently checkable, which is the property the read-only heuristic was standing in for. An agent whose unit passes its own check has not silently diverged from its siblings, because the check, not the sibling, defines correct.

(2) A UNIT CAN BE CLAIMED EXCLUSIVELY BEFORE WORK STARTS. The mechanism actually used was a claim file committed to the repository; it and the run's cost envelope are at [[kb/architecture/ai/agents/multi-agent/task-claiming/2318b57c]].

WHERE IT BROKE, AND THE FAILURE IS NOT THE ONE THE EARLIER SOURCES PREDICT. Aimed at compiling the Linux kernel as one target, the report is explicit: "Every agent would hit the same bug, fix that bug, and then overwrite each other's changes. Having 16 agents running didn't help." The failure of an unpartitioned target is CONVERGENCE — sixteen agents doing one agent's work and then clobbering each other — not the divergence into incompatible artifacts that Cognition and the research-system post describe. Both failures exist, they are different, and they call for different fixes. Divergence is fixed by keeping writes single-threaded. Convergence is fixed by partitioning the target, and here the partitioner was again the oracle: GCC was used to carve the kernel into smaller independently solvable units.

OPERATIONAL CONSEQUENCE. Before fanning out write work, ask what checks each unit and what stops two agents taking the same unit. If you cannot answer both, fan-out buys nothing and may cost you a clobbered tree; build the verifier first, because it is also the partitioner. Do NOT read this as "coding parallelises fine after all" — the same report notes the fleet "frequently broke existing functionality" when adding features.

The reconciliation across these sources is this pack's analysis; the failure quotation and the successful outcome are the C-compiler report's own.
