# Workflow vs agent: fix the path in code unless you cannot enumerate the steps

Anthropic draws the line precisely: a workflow orchestrates LLMs and tools through predefined code paths; an agent lets the model direct its own process and tool use. The question is not sophistication, it is who decides the sequence — and you should prefer code deciding, because a fixed path is debuggable, cheap, and cannot loop.

The selecting condition for each named pattern is the useful part:
- Prompt chaining — the task decomposes into FIXED subtasks known ahead of time. Trades latency for accuracy per call.
- Routing — TWO conditions, both required, and the second is the one that gets dropped: "Routing works well for complex tasks where there are distinct categories that are better handled separately," "and where classification can be handled accurately, either by an LLM or a more traditional classification model/algorithm." Distinct categories alone are not the trigger; without accurate classification the router is a new failure point that misdirects work no single prompt would have got wrong. Pack reading: if one prompt handles all the categories adequately, routing only adds that failure point for nothing.
- Parallelization — sectioning when independent subtasks can run concurrently; voting when you want several attempts at the SAME task for confidence.
- Orchestrator-workers — use only when you cannot predict what the subtasks will be. This is what distinguishes it from parallelization; if you can enumerate them, you do not need a model to.
- Evaluator-optimizer — requires two things to both hold: "The two signs of good fit are, first, that LLM responses can be demonstrably improved when a human articulates their feedback" "and second, that the LLM can provide such feedback." Note the asymmetry in the first sign: the demonstration is that HUMAN-articulated feedback improves the output, which is what makes it plausible that machine-articulated feedback will too. Neither sign is automatic, and looping without them just burns tokens.

Agents cost latency, money, and compounding errors from autonomous action. For many applications a single well-retrieved call with in-context examples is enough; only add autonomy where it demonstrably improves the outcome.
