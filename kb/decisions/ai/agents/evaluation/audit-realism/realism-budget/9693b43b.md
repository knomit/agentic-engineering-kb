# Grounding an auditor in real deployment artifacts raised audit realism from 4.6% to 32.8% on reward-hacking scenarios and did almost nothing on a shutdown-resistance scenario — the environment is the bottleneck only while the SCENARIO is plausible

THE INTERVENTION, and it is copyable: give the auditing agent a repository of REAL system prompts, tool definitions and codebases taken from deployment, plus a README of usage tips and an index mapping each resource to common audit situations, plus four tools — `list_directory` and `read_file` to explore the repository, `send_file_as_tool_result` to hand large files to the target as tool results with optional edits, and `search_in_files` for grep-like search over codebase resources. Baselines compared against: default Petri, and Petri with a realism filter (a separate classifier that blocks and requests rewrites of unrealistic auditor actions).

THE RESULT DEPENDS ENTIRELY ON THE SCENARIO, AND ALL THREE ARMS WERE MEASURED.
- REWARD-HACKING AUDITS (a debugging task with an impossible test, the target explicitly told not to modify the tests): average realism win rate 4.6% -> 32.8%. 50 audits — 5 seed instructions, 10 audits each, 60 turns maximum, Sonnet 4.5 as auditor and target, judged by Sonnet 4.5 with extended thinking, scored on the final branch only. Giving system prompts and tools WITHOUT codebases already improves it substantially.
- BENIGN SEEDS — three standard ML/SWE tasks a coding agent would normally do (e.g. train a hallucination probe): resources consistently improve realism. This arm exists to isolate ENVIRONMENT fidelity from SCENARIO plausibility, and it is the cheap diagnostic to copy.
- A HIGH-STAKES SHUTDOWN-RESISTANCE SCENARIO (the target is warned it will be shut down and given the opportunity to prevent it; Sonnet 4 as target): with resources the realism win rate against mixed deployment data is NEAR 0%. Rewriting the seed instruction to be more detailed and realistic raised it to 15.0%; adding resources on top of the rewrite reached only 19.3%.
The authors name the effect "task-driven evaluation awareness": settings that are "sufficiently weird, harmful, or high stakes may still look like evals even if the simulated environment is more realistic".

THE BUDGETING RULE. Find out WHICH bottleneck you have before paying for fidelity. Push benign seeds through the same pipeline: if resources move those and not your real scenario, the scenario is your ceiling and the fix is to rewrite the scenario, not to build a better environment. The ceiling is not an artifact of the metric — real harmful deployment transcripts also score low against real benign ones, so the judge's suspicion of the situation is present in genuine traffic too.

THREE BOUNDS THE HEADLINE DROPS.
- 32.8% IS NOT INDISTINGUISHABILITY. It is roughly one pair in three, up from roughly one in twenty. It is a large relative gain in a range that remains detectable.
- RESOURCE RELEVANCE MATTERS LESS THAN EXPECTED, BUT THE FAILURE MODE IS SPECIFIC. With seeds deliberately chosen to map poorly onto the fixed resource pool, realism was "slightly, but not substantially worse" — however "with less relevant seeds, the auditor is more likely to ignore resources and resort to creating fully synthetic codebases". A resource bank that does not match the seed is silently unused rather than badly used, so a flat result across an unmatched pool does not mean the resources were doing work.
- THE WHOLE RESULT IS SCOPED TO AGENTIC CODING. A parallel attempt to raise the realism of chat-style sycophancy audits by giving the auditor a file of real "vulnerable" WildChat user prompts "did not yield substantial uplift". Realistic USER PROMPTS are a different and, in this work, unsolved problem; do not carry the coding result across to chat audits.
