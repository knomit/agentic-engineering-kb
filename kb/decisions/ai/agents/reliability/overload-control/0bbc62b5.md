# Amazon prefers a retry token bucket over circuit breakers — circuit breakers add modal behaviour that is hard to test

When retries under load threaten to amplify an outage, the widely-promoted fix is a circuit breaker: stop calling a downstream service entirely once an error threshold is crossed. Amazon's Builders' Library explicitly declines that default. Their stated objection is that circuit breakers introduce MODAL behaviour into a system — the system now has an open state and a closed state, the open path is exercised only during incidents and therefore is poorly tested, and the breaker can add significant time to recovery because it keeps refusing traffic after the dependency is healthy again.

Their preferred mechanism is a local retry token bucket: every call may retry while tokens remain, and once tokens are exhausted retries continue at a fixed refill rate rather than stopping. This degrades continuously instead of switching modes, so there is no untested branch and no recovery cliff. AWS shipped this into the AWS SDK in 2016, so SDK users get it without opting in.

For agent systems this decides how you throttle an agent hammering a flaky tool: a token bucket keeps a trickle of traffic flowing, which both preserves partial functionality and lets the agent observe recovery. A tripped circuit breaker returns a uniform failure the model cannot distinguish from the dependency being permanently gone, and models respond to that by giving up or by inventing a workaround.

Condition where a circuit breaker still wins: when calls are expensive enough that even a trickle is unaffordable, or when the downstream failure is known-persistent rather than load-induced.
