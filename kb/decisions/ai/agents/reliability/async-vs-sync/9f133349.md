# Putting a queue in front of agent work trades a fast outage for a slow one — and the recovery arithmetic is brutal

A queue-based agent system is BIMODAL, and that is the property to decide on. With no backlog it is in fast mode and latency is low. Once arrival rate exceeds processing rate — from a dependency outage, a load spike, or work turning out more expensive than predicted — it flips into a second mode where end-to-end latency climbs and stays climbing until the backlog drains. Work completes too late to be useful, which is exactly the availability loss the queue was added to prevent.

The arithmetic, stated by Amazon and worth memorising because it is counter-intuitive:

- An outage of one hour requires DOUBLE the system's steady-state capacity for a further hour just to return to normal — independent of the absolute rate.
- If an unthrottled spike queues 10x what the consumer fleet is scaled for, draining takes 10x as long. Amazon's worked example: a 30-minute noisy-neighbour spike that takes an operator 30 minutes to notice and mitigate produces a 300-minute drain. A half-hour incident becomes a five-hour outage.

The decision this drives: a SYNCHRONOUS agent service drops requests during an outage and recovers the moment the dependency returns. An ASYNCHRONOUS one preserves every request and pays for it with a recovery window proportional to the outage times the overload ratio. Choose async when losing the request is worse than serving it very late — durable background jobs, long-running agent runs that must survive a restart. Choose sync when a stale answer is worthless, which is most interactive agent work.

The misreading to avoid: 'asynchronous means latency doesn't matter'. Amazon is explicit that in practice even async systems are expected to hit subsecond latency, and that the durability-for-latency tradeoff is easy to accept without noticing you have also accepted an unbounded recovery time. If you choose a queue, you own backlog management — see the sidelining, backpressure and message-TTL patterns that follow from it.
