# An attack-search pipeline cannot be both the hardening tool and the measurement, and its failure to find an attack was never a safety bound

Redwood Research states two limits on its Screwtape monitor-evasion search, and together they decide what such a pipeline can be used for.

First, a null result is not a measurement: "the absence of found attacks provides little information about safety", because the search covers only part of the attack space. Most Screwtape runs found no evading attack at all, and the authors do not read that as evidence the monitors are robust. The search is also easier than reality in a way that cuts the same direction: the attacker is shown full transcripts and the monitor's own feedback, which a deployed agent normally is not.

Second, the two uses are in tension: "Using Screwtape for improvement presumably makes it less useful for evaluation", because a later evaluation run would search the same part of the attack space that the hardening run already mined. Hardening consumes the instrument.

Operational consequence: budget a separate, held-out evasion search for the measurement, or accept that after hardening you have a monitor you believe in and no number to support it. Report what a search found, never what it failed to find.

What this does NOT mean: it is not an argument against hardening, and it is not the "hold out the attacker" point about adversarial training — the attacker here is not trained at all. The tension is between two uses of one search procedure over one attack space.
