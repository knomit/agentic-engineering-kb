# Anthropic's guidance splits extended thinking and the 'think' tool by tool-use complexity rather than replacing one with the other — and in the airline domain most of the tool's measured gain came from the prompt bundled with it

WHAT THE SOURCE ACTUALLY RECOMMENDS, quoted in full because the split is the content and a shortened version of it inverts the advice: "We recommend using extended thinking for simpler tool use scenarios like non-sequential tool calls or straightforward instruction following. Extended thinking is also useful for use cases, like coding, math, and physics, when you don't need Claude to call tools. The 'think' tool is better suited for when Claude needs to call complex tools, analyze tool outputs carefully in long chains of tool calls, navigate policy-heavy environments with detailed guidelines, or make sequential decisions where each step builds on previous ones and mistakes are costly."

So this is a conditional split by tool-use complexity, not a deprecation. Do NOT compress it to "use extended thinking instead of a think tool": that drops every condition on the right-hand side, which is where the tool is still the recommended choice. The page also carries an update noting that extended thinking capabilities improved after the tool's March 2025 introduction, so the default for a SIMPLE loop has moved to extended thinking — but a long, policy-heavy, error-compounding chain is the case the source still points at the tool.

The mechanism behind the split: the think tool is a tool that does nothing. Calling it appends the model's reasoning to the transcript. It differs from extended thinking by WHEN it fires — extended thinking happens before generation begins, while the think tool creates a reasoning step in the MIDDLE of a tool-use loop, giving the model a scratchpad for information it only discovered mid-run. That mid-loop position is the whole argument for it, and it is exactly what the "long chains of tool calls" and "each step builds on previous ones" conditions describe.

THE MEASUREMENTS, AND A TRAP IN QUOTING THEM. The source states two different number pairs for the same airline comparison: its prose gives baseline 0.370 and think-with-optimised-prompt 0.570 ("a 54% relative improvement"), while its table gives baseline 0.332 and Think+Prompt 0.584 at k=1. The table's other two rows are think tool alone 0.404 and extended thinking 0.412. Cite one set or the other and say which — an arithmetic conclusion built by taking the baseline from the prose and the tool-alone figure from the table is not a result the source states.

Within the table alone, the ordering is what matters and it is robust to that ambiguity: think tool alone (0.404) sat slightly BELOW extended thinking (0.412), and think-plus-optimised-prompt (0.584) sat far above both. The prompt in that configuration contained worked examples. The operational reading: a scratchpad tool is a place to put domain reasoning instructions, and in this domain the instructions carried most of the gain. If you got a win from adding a think tool, test whether you keep it by moving those instructions into the system prompt and turning the tool off.

THE SCOPE OF THAT PROMPT CLAIM IS THE AIRLINE DOMAIN ONLY. In retail the source reports the think tool reaching "the highest pass^1 score of 0.812 even without additional prompting", so the prompt was not the active ingredient there. On SWE-bench "the isolated effects of including this tool improved performance by 1.6% on average" — small, and the source reports it as statistically significant.

VERSION SCOPE: the evaluated model was Claude 3.7 Sonnet, with a footnote that Claude 3.5 Sonnet (New) achieved gains on the same configuration, on the 2024-era tau-bench. Those are several model generations behind current releases, so the absolute values are stale and should be re-measured before being quoted as magnitudes. The conditional split and the prompt-versus-tool decomposition are the parts that do not depend on the model generation.
