# Both AutoGen and Semantic Kernel are superseded by Microsoft Agent Framework as of 2026 — and GroupChat/actor code does not port linearly

A framework-selection fact that expires, recorded with its date. As of mid-2026 BOTH of Microsoft's agent frameworks have been folded into Microsoft Agent Framework (MAF), confirmed from each repository's own README:

- **microsoft/autogen** states the project is in MAINTENANCE MODE — bug fixes, security patches and documentation only, no new features, community-managed going forward. New projects are directed to MAF.
- **microsoft/semantic-kernel** carries a prominent notice that 'Semantic Kernel is now Microsoft Agent Framework', describing MAF as the enterprise-ready SUCCESSOR, available at version 1.0 as a production release, and links an official Semantic Kernel migration guide.

So neither is a live choice for new work. This resolves what had been a confusing overlap in Microsoft's own portfolio, where AutoGen and Semantic Kernel were separate, competing answers to the same question — the resolution was to retire both brands into one.

MAF is the merger of the two lineages rather than a rename of either: AutoGen's abstractions for single- and multi-agent patterns, combined with Semantic Kernel's enterprise-side features — session-based state management, type safety, filters, telemetry, and broader model/embedding support. Version 1.0 reached general availability on 2026-04-02 with Python and .NET releases. Semantic Kernel additionally contributed a 'Process Framework' for structured long-running business workflows, and shipped Python, .NET and Java implementations, so Java users should verify MAF language coverage before planning a migration.

The part that changes a decision rather than just a dependency: reporting on the migration indicates that for codebases with substantial GroupChat or actor-model code, moving to MAF is closer to an architectural rewrite than a linear port. AutoGen's Core layer is built on event-driven agents with message passing over a local or distributed runtime — an actor model — and code written against that abstraction does not translate mechanically. So the cost of staying is a frozen framework; the cost of leaving scales with how deeply you adopted the actor/GroupChat layer rather than the higher-level AgentChat API.

Practical reading: do not start new work on AutoGen or Semantic Kernel. If you have existing AutoGen code, the migration estimate depends on which of its three layers you built against — Core (actor model, distributed runtime), AgentChat (the opinionated two-agent and group-chat API), or Extensions — with Core-level adoption being the expensive case. Semantic Kernel users have a first-party migration guide, which AutoGen users effectively do not.
