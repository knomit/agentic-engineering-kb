# AutoGen is in maintenance mode as of 2026 — Microsoft Agent Framework is the successor, and GroupChat code does not port linearly

A framework-selection fact that expires, recorded with its date. As of mid-2026 the microsoft/autogen README states the project is in MAINTENANCE MODE: bug fixes, security patches and documentation only, no new features, community-managed going forward. New projects are directed to Microsoft Agent Framework (MAF) instead.

MAF is the merger of two lineages rather than a rename of one: AutoGen's abstractions for single- and multi-agent patterns, combined with Semantic Kernel's enterprise-side features — session-based state management, type safety, filters, telemetry, and broader model/embedding support. Version 1.0 reached general availability on 2026-04-02 with Python and .NET releases. This also resolves what had been a confusing overlap in Microsoft's own portfolio, where AutoGen and Semantic Kernel were separate, competing answers to the same question.

The part that changes a decision rather than just a dependency: reporting on the migration indicates that for codebases with substantial GroupChat or actor-model code, moving to MAF is closer to an architectural rewrite than a linear port. AutoGen's Core layer is built on event-driven agents with message passing over a local or distributed runtime — an actor model — and code written against that abstraction does not translate mechanically. So the cost of staying is a frozen framework; the cost of leaving scales with how deeply you adopted the actor/GroupChat layer rather than the higher-level AgentChat API.

Practical reading: do not start new work on AutoGen. If you have existing AutoGen code, the migration estimate depends on which of its three layers you built against — Core (actor model, distributed runtime), AgentChat (the opinionated two-agent and group-chat API), or Extensions — with Core-level adoption being the expensive case.
