# A bare "keep going" loop carried a frontier physics calculation to completion for "around one or two thousand dollars" — what made the unsupervised long run affordable was a task where any mistake collapses the computation

An agent running inside Claude Science computed the six-particle amplitude in planar N=4 super Yang-Mills at nine loops. The steering was almost nothing: one task statement, then the prompt "Keep working on this until I tell you to stop.", and the source reports it "accomplished this in one shot, without any scientific oversight more sophisticated than “keep going.”", no intermediate expert correction, and the agent wrote its own code from scratch. Cost: "Either approach would have cost an end-user around one or two thousand dollars". A domain expert validated the result, chiefly via the corresponding form factor.

THE DECIDING PROPERTY IS THE TASK'S VERIFIER, NOT THE MODEL OR THE HARNESS. The commissioned write-up's own description of this class of calculation is that "it all crashes down like a failed soufflé" if you make any mistake at all in the computational recipe. That is a fail-loud task: an error does not yield a plausible wrong answer, it yields no answer. The bootstrap method compounds the property deliberately, since it eliminates candidates against known checks, symmetries and results from other techniques, and the second route (form factor) converts back into the first, giving an independent cross-check. Under those conditions an unattended "keep going" loop is cheap, because every wrong branch terminates itself instead of consuming the rest of the budget.

SO THE DECISION RULE, with both halves: spend a long unsupervised run only where a wrong intermediate step is detectable by the agent itself without you in the loop; where failures are silent, the same budget buys a confident wrong answer and you will not know until you check it by hand. This is the boundary condition on "give a coding agent a check it can run, or you become the verification loop" ([[519ec939]]) — the check has to fail loudly, not merely exist. It is also why this result does not generalise by horizon length alone: agent failures are predominantly silent in the normal case ([[2c0e8e7c]]), per-step accuracy compounds against you ([[ac887ec9]]), and the errors surviving at long horizons shift from systematic to random ([[9a5214f2]]), which is precisely the regime a self-terminating verifier neutralises and an output-only check does not.

ONE HARNESS DETAIL WORTH THE LINE: the bootstrap was implemented in Python with SymPy rather than Maple or Mathematica, which the author suggests may have helped — stated as a suggestion, not a measurement.

WHAT THIS DOES NOT MEAN, and the source is explicit on each. The methods were not new: "Claude used known methods, with a bit more compute than people had tried to use before." A separate human group reached most of the same result concurrently with AI assistance. Validation was possible because the answer could be checked against existing constraints and an expert, which open-ended tasks lack. And this is a single commissioned case — Anthropic commissioned the post and gave feedback on drafts, and the validator received usage credits — so treat the cost figure as one datapoint on one task, not a rate.
