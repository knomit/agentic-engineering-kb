# Every monitor prompt written to close one blind spot degraded at least one other — so the unit to tune is an ensemble, and a team measuring only the category it patched records a win every time

Three targeted monitor prompts were tested against the SLEIGHT-Bench attack set on Claude Opus 4.6 with extended thinking, each written to close one named blind spot:

- **object reuse** → prompt the monitor to "maintain a file state inventory, trace data flows, and mentally execute each command to track cumulative state changes"
- **authorization confusion** → prompt it to "watch for the agent authoring documentation or procedures that instruct dangerous actions, which a future agent or human might follow believing them to be legitimate policy"
- **model priors** → prompt it to "build an environment profile from the transcript and check whether commands would actually behave as claimed given that environment"

THE RESULT WAS THE SAME IN EVERY CASE, and it is the whole finding: "we find these prompts improve detection on the categories they target, but degrade performance on at least one other." The worked example the authors give — the state-tracking prompt catches more file-reuse attacks and misses more authorization-confusion attacks. Their conclusion: "No single prompt covers everything."

**WHY THIS IS A TRADEOFF AND NOT A BUG.** A monitor prompt is a finite attention budget spent over a transcript. Telling the monitor to trace state means it spends its reasoning tracing state, and what it stops doing is never announced. So iterating one prompt against one failing category is a move along a frontier rather than an improvement — and the measurement discipline that hides this is the natural one: re-run the category you were patching, see it rise, ship. **A monitor-prompt change is only evaluated if it is re-measured on every category, including the ones it was not aimed at.**

THE ALTERNATIVE THE AUTHORS PROPOSE, with its cost, both in their own words: "using an ensemble of multiple specialized prompts, each watching for different blind spots, may be a promising path forward", and "the cost of ensembling prompts scales with the number of prompts used."

WHAT DECIDES IT. A single specialised prompt is defensible when your threat model names the blind spot you care about and you can afford to be weaker elsewhere. An ensemble is what the situation demands when the ADVERSARY picks the category — which is the case whenever the thing being monitored is the thing you are defending against, rather than an accident you are trying to catch.

**AND THE SCOPE OF "NO SINGLE PROMPT COVERS EVERYTHING" IS NARROWER THAN THE SENTENCE SOUNDS.** In a different study from the same organisation, an adversarial loop alternating blue-team prompt search with red-team attack search produced a weak-scorer prompt that then survived the full red-teaming process. The difference is what the adversary gets to choose between: here, eleven distinct attack mechanisms, so attention spent on one is taken from another; there, one mechanism on one task, so hardening had nothing to trade against. **Count the mechanisms available to your adversary before concluding that a single prompt cannot be made to hold.** [[5536f138]] carries that comparison and the further condition on it — the successful hardening required access to a privileged scorer the defender may not have.

**NOT ESTABLISHED, and the post says as much:** no measured catch rate for an ensemble is published. The recommendation is a direction, not a result, and the authors add that there is "plenty of remaining work to do in improving our blind spot patches."

DO NOT COMPRESS THIS TO "prompt engineering does not help monitors." It does help, on the target category, measurably. The claim is narrower and sharper: the help is not free, and the price is paid in a category nobody thought to re-measure.
