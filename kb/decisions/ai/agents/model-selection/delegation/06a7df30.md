# A small model's mistake is paid for by the big one, so route the small model to work where a mistake is cheap to spot — and downgrade effort, not the model, for mechanical edits

The failure mode that decides where a cheaper model can be used is not that it writes worse code; it is that its errors travel upstream. As Anthropic's cost guide for Claude Opus 5.5 puts it, a small model that misreads a search result sends the main model after the wrong file, and the main model pays for the detour — so the saving on the lookup is wiped out by the turns the detour costs.

That gives a usable line. Route Sonnet or Haiku to work where a mistake is cheap to spot: finding files, reading logs and test output, running tests, subagents that search and summarise, and "where is this defined" questions. Keep code writing and judgment calls on the main model.

The second half matters as much as the first: when a task is large but mechanical — the same edit across many files — the lever is not the model but the effort dial. Keep the frontier model and set effort to low, rather than moving the work to a smaller model to make it cheap.

What this does NOT mean: it is not a claim that small models are unreliable, nor a blanket rule against delegating, and it is not a rule about model SIZING — which tier clears your eval bar is a separate question, see [[2b74037b]]. The deciding variable here is the cost of detecting the mistake downstream, so a small model on a step whose output is immediately checkable is a good trade even for work that looks hard.
