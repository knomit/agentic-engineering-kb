# A minimum package age is only a control if the build also installs from the lockfile — the age floor buys the window in which malicious releases get pulled, and fresh resolution on every build hands it straight back

Cognition's November 2026 security guidance states both halves as a single control: "Set a minimum package age of at least 7 days for npm, PyPI, and any other package manager you use", and "make CI install from the lockfile instead of resolving fresh versions on every build." The stated mechanism for the number is detection latency rather than caution in general: "malicious releases are usually caught and pulled within that window."

BOTH COMPONENTS, OR NEITHER. A seven-day floor enforced only at a developer's install step is defeated by a build that resolves versions afresh, because that build is free to pick up a release published minutes earlier. Equally, lockfile-only installs with no age floor still admit a poisoned version at the moment someone updates the lock. The control is the pair, and a summary that keeps only the memorable half — "use a seven-day package delay" — describes something that does not work.

What this does NOT mean: the window is a statistical property of how quickly bad releases are noticed, not a guarantee. The source says malicious releases are "usually" caught within it, so the floor lowers exposure to the common case and does nothing against a release that stays undetected past seven days. It is also a vendor's recommended posture rather than a measured result: the post reports no measurement of its own and gives no figure for how often the window catches a release, so treat the seven days as a published default to adopt and tune, not as a validated threshold.

PACK ANALYSIS, not the source's claim: the party that resolves a fresh version is increasingly an autonomous coding agent running an install step, which is why this control has to live in the build and registry configuration where the agent cannot route around it rather than in the instructions handed to the agent. That is the same placement argument that applies to branch protection — enforce at the layer being protected, not inside the thing being constrained.
