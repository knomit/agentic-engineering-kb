# Give a coding agent a check it can run, or you become the verification loop

An agent stops when the work looks done. Absent a check it can execute itself, "looks done" is the only available signal and every mistake waits for a human to notice it. Supplying something that returns pass/fail — a test suite, a build exit code, a linter, a script diffing against a fixture, a screenshot compared to a design — closes the loop: the agent works, runs the check, reads the result, iterates.

This is the difference between a session you must watch and one you can walk away from, and it is why the concrete-verification version of a prompt beats the vague one: "write validateEmail; example cases: user@example.com true, invalid false, user@.com false; run the tests after implementing" versus "implement email validation".

Escalating strength of gate, trading setup effort for attention:
1. Ask for the check and iteration in the same prompt — works today, on any task.
2. A session-level goal condition re-evaluated after every turn.
3. A deterministic stop hook that blocks the turn from ending until a script passes (Claude Code overrides after 8 consecutive blocks, so it is a gate, not an infinite loop).
4. A separate verification subagent with fresh context, so the agent that did the work is not the one grading it.

Also require evidence rather than assertion — the actual test output, the command and its return, the screenshot. Reviewing evidence is faster than re-running the verification yourself, and it is the only thing that works for a session you were not watching.
