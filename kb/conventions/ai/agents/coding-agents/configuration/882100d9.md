# Mine your own transcripts for correction phrases — they are the backlog for agent configuration

A concrete, repeatable method for deciding what to put in an agent's configuration, instead of guessing: mine your own past transcripts for the phrases you use when correcting the agent.

The method, in the source's words: 'Mine your transcripts for config updates. Have the model read past session transcripts to find gaps.' The reported instance gives it scale — scanning roughly 2,500 past user turns, 'a sizable percentage contained phrases like "can you also…", "did you check…", "still wrong"'.

Why those phrases specifically: each one marks a point where the agent should have acted unprompted and did not. 'can you also…' is a missing default. 'did you check…' is a missing verification step. 'still wrong' is a missing rule that has already failed at least twice. Every occurrence is evidence you paid for once and can stop paying for.

The translation step is the point: turn the recurring patterns into configuration — rules in the instruction file, a skill, or a hook — rather than repeating the correction. This makes agent configuration a data-driven backlog with a natural priority order (frequency) instead of a wishlist assembled from memory of recent annoyances, which systematically over-weights whatever went wrong yesterday.

A prerequisite that is easy to miss and changes what you should do day to day: make your corrections INSIDE the session, so the transcript captures the before-and-after pair. A correction you make silently in your own head, or by editing the file yourself without telling the agent, leaves no trace and cannot be mined later. The transcript is only training data for this process if you actually wrote the correction down in it.
