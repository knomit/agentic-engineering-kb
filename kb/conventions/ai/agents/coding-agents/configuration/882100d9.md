# Mine your own transcripts for correction phrases — they are the backlog for agent configuration

A concrete, repeatable method for deciding what to put in a CLAUDE.md, a skill, or a hook, instead of guessing: scan past sessions for the phrases you keep typing. 'Can you also…', 'did you check…', 'still wrong'. Each recurring correction is evidence of exactly one of two gaps — a behaviour the agent should have performed proactively, or a verification step that exists but is not working. Both are fixable in configuration; neither is fixable by correcting again next time.

Supporting practices from the same source, chosen because each has a stated trigger rather than being general advice:

- Promote a task to a SKILL once you do it at least weekly. Bootstrap it by doing the task interactively once, asking the model to convert the session into a skill, testing the skill, correcting it in-session so the corrections land in the transcript, then having the model merge that feedback back into the skill file.
- Annotate index files. An INDEX.md of bare URLs forces the model to open every link; URLs with an owner and an explanatory paragraph let it choose. The annotation is the retrieval signal.
- Split an overgrown CLAUDE.md into topic guides loaded conditionally rather than eagerly imported, so the context cost is paid only when relevant.
- Separate the two memory layers by what changes: durable facts and project state in a knowledge store, preferences and workflow taste in the agent's own config directory.
- Audit for conflicts as configuration grows. Each rule should live in exactly one place; duplicated rules drift apart and then contradict each other.

The framing worth keeping: agent configuration is a closed loop fed by your own correction history, not a document you write once.
