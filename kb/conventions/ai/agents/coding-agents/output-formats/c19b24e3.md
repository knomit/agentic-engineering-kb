# One Claude Code engineer's case for HTML over Markdown as the agent's report-back format: the keepable parts are the defects Markdown forces and the rule that an interactive artifact must end with an export

A Claude Code engineer, writing in a personal capacity and self-describing as "far on the HTML maximalist side of things," reports preferring HTML over Markdown as the format an agent uses to report back to a human. Read the preference as a practitioner's taste with no benchmark behind it. Three parts of it are specific enough to act on.

**The defects Markdown forces are concrete, not aesthetic.** Asked for visual content in Markdown the model does "more inefficient things... like ASCII diagrams or, my favorite, estimating colors with unicode characters" — it spends tokens approximating a medium it does not have. And the sharing path is worse than it looks: browsers do not render a .md file natively, so the artifact travels as an attachment while an HTML file travels as a link. The author's own admission is the consequence that matters — he does not read more than about a 100-line Markdown file himself, and cannot get colleagues to read a long one.

**An interactive HTML artifact must end with an export.** A "copy as JSON" or "copy as prompt" button turns the human's work on the artifact — sliders, knobs, a triage decision — back into input the agent can consume. Without it the artifact is a dead end and the human's adjustments have to be retyped. This is the transferable rule in the post.

**The workflow is a web of files, not one document.** Exploration, then mockups, then an implementation plan, each its own HTML file; then a NEW session that takes those files as input for the implementation, and the same files handed to the verification agent.

**The cost condition is explicit and bounds the advice.** "While Markdown often uses fewer tokens," and the author judges the trade worth it because of a large context window — his words: "With the 1MM context window in Opus 4.7, the increased token usage is not really noticeable." On a tight context budget this is not the arithmetic he is doing.

What is NOT established: the post defines no case where Markdown is preferred, offers no measurement of either format's effect on task outcomes, and its central "I feel more in the loop" claim is explicitly subjective. The claim is about whether a human reads and acts on the agent's output, not about whether the agent performs better.
