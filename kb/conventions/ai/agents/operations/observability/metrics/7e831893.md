# Emit 1 for success and 0 for failure so the metric's AVERAGE is availability — and emit the zeros deliberately so silence becomes detectable

A small technique with two distinct payoffs, both stated by Amazon.

**Availability as an average.** Instead of counting errors, emit a data point of 1 when a request succeeds and 0 when it fails. The 'average' statistic of that metric IS the availability rate, directly, with no ratio arithmetic in the dashboard or alarm and no need for the error count and total count to arrive at the same aggregation interval. Error counts alone give you an absolute number; the percentage is usually what you want to alarm on.

**Intentional zeros make absence observable.** The second and less obvious use: emit a 0 in the negative case specifically so that a process which stops emitting ANYTHING is distinguishable from a process which is fine. Amazon's example is leader election — a process periodically emits 1 while it is the leader and 0 while it is not, so a follower that stops emitting 0s reveals that something in it is broken and it will not be able to take over if the leader fails. Without the deliberate zero, a healthy follower and a dead follower produce identical telemetry: nothing.

This is the standing fix for the silent-failure problem in agent fleets. A worker that has stopped polling, a background evaluator that has crashed, a scheduled agent that never fired — all of these look exactly like 'nothing to report' unless something was already emitting a zero on the quiet path. Every standby, follower, or idle-by-design component in an agent system should be emitting its zeros.
