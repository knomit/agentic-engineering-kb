# A standard whose adoption nobody can measure is not a standard — ship a new engineering rule as a warning in the tool, then enforce it, and keep a sanctioned exemption

Amazon's continuous-delivery account names the failure mode of documented best practice without equivocation: practices spread through best-effort channels, so not everyone learns them AND leaders cannot verify adoption. The second half is the operative one — a rule that lives in a document has no adoption signal, so nobody can tell the difference between a team that complies and a team that never read it.

The mechanism that replaced it has three stages, and all three matter. A new practice first appears as a WARNING in engineers' own tools, which produces a count of how often it would have fired before anything breaks. It then becomes an enforced check, configurable at the organization level rather than per team, so the enforcing body is the one that owns the standard. And teams can obtain opt-outs, permanent or temporary.

The exemption is load-bearing, not a concession: without a sanctioned way to be exempt, a team with a real reason routes around the check, and the measurement that justified enforcing it goes dark again. An opt-out that is recorded keeps the exception visible; a workaround does not.

The transfer to agent fleets is direct. The equivalent of a best-practice document for agents is a check in the harness — a lint, a required tool call, a policy evaluated at runtime — because that is the only form whose adoption can be counted. A convention written into a prompt or a README has the same measurement problem as the wiki page this account replaced, which is a separate problem from whether the model follows it.

Scope: an account of one organization's internal practice, with no figure attached to the warn-then-enforce sequence itself.
