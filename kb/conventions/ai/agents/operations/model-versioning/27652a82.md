# Pin model versions and run a shadow pipeline; expect ~10% swing between versions

Pin a specific dated model version rather than a floating alias. Practitioners report roughly 10% performance variance between model versions, and prompts do not migrate for free — re-tuning across a version bump is genuine work, not a config change.

The operational pattern: keep a shadow pipeline running the newest version against the same traffic, compare it on your evals, and promote deliberately. This makes the upgrade an evaluated decision instead of an unannounced regression appearing in production.

Related skew detection worth wiring up at the same time: monitor input and output lengths and format-compliance rates (does the JSON still parse?), cluster embeddings to catch semantic drift, and include production's real typos and fragments in the hold-out set rather than clean synthetic inputs. Run the pipeline more than once on the same input to expose nondeterministic failures — a single passing run proves less than it appears to.
