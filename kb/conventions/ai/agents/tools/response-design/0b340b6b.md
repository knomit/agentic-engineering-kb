# Budget tool responses in tokens: cap, paginate, and offer a concise mode

Tool results are the largest uncontrolled consumer of an agent's context, so treat response size as a designed parameter rather than whatever the API returns. Anthropic's specific number: "For Claude Code, we restrict tool responses to 25,000 tokens by default." Tools should ship pagination, range selection, filtering, or truncation with sensible defaults already set — not as opt-in parameters the model must think to use.

WHEN YOU TRUNCATE, SEND INSTRUCTIONS WITH THE TRUNCATION, NOT JUST NOTICE OF IT. The source: "If you choose to truncate responses, be sure to steer agents with helpful instructions. You can directly encourage agents to pursue more token-efficient strategies, like making many small and targeted searches instead of a single, broad search for a knowledge retrieval task." Note the shape of Anthropic's own example — it redirects the agent's STRATEGY (decompose one broad search into several narrow ones), which is a larger correction than telling it to re-run the same call with a tighter filter. (This pack's addition, and marked as such: a bare "...truncated" carries no instruction at all, so the agent has nothing to act on and the obvious next move is to repeat the call. Anthropic does not make that claim; it is the reason its advice is worth following.)

Offering a ResponseFormat enum of "concise" vs "detailed" is cheap and large: their Slack example labels a "Detailed tool response (206 tokens)" against a "concise tool response (72 tokens)", roughly a third. Give the model the choice rather than picking one globally, since the same tool serves both scanning and drill-down.
