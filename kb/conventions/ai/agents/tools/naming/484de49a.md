# Return semantic identifiers, not UUIDs, from agent tools

Resolving opaque alphanumeric UUIDs to human-meaningful names before returning them measurably improves retrieval precision and reduces hallucination — Anthropic reports this from their own tool evals. The mechanism: a model cannot pattern-match, deduplicate, or sanity-check `a4f9c2e1-...`, so it copies IDs approximately and invents plausible ones; it can do all three with `channel: #eng-platform`.

When a downstream call genuinely needs the raw ID, do not choose — expose both, gated behind a response-format parameter, so the readable form drives the model's reasoning and the technical form is available for the call.

Related naming guidance from the same source: namespace related tools by a shared prefix (`asana_search`, `asana_projects_search`, `jira_search`). The choice between prefix- and suffix-based namespacing has non-trivial, measurable effects on tool-use accuracy, so it is worth evaluating rather than assuming.
