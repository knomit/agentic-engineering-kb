# Offload oversized inputs to a file instead of truncating — Deep Agents ships 20,000 tokens for a tool result, 50,000 for a user message, and 85% window usage for summarization

LangChain's Deep Agents implements context control as middleware hooked into the agent loop at three points — before the run starts, around each model call, and around each tool call — and ships concrete defaults for each mechanism.

Offloading, with two thresholds. "When a tool result exceeds roughly 20,000 tokens, the full result is written to /large_tool_results/", at the path /large_tool_results/{tool_call_id}; the model receives that path plus a preview of the first and last few lines, and pages the rest with read_file (100 lines per call by default, with offset and limit). Oversized user messages "get the same treatment at a higher threshold (50,000 tokens)" and go to /conversation_history/. The stated rule is "Large inputs should be offloaded, not truncated." because "Truncation is lossy; offloading keeps it retrievable."

Summarization, with a third. It runs before each model call and "once usage hits 85%, older messages are condensed into a summary" by a separate model call. The most recent messages are kept verbatim rather than paraphrased, and the full history is written to /conversation_history/{session_id}.md so detail stays recoverable. The design rule behind that file is "Compaction should be recoverable."

The operational consequence: a tool that can return an unbounded payload needs a destination and a pager, not a cap. A cap that truncates destroys the only copy of what it cut, while an offload leaves the agent able to go back for the part it turns out to need.

All three numbers are one framework's defaults, not measured optima, and the source says so: "Thresholds that suit one task rarely suit every task." and "Defaults should be customizable." Two specifics not to lose in compression — the 85% figure is a fraction of window USAGE, not a fixed token count, so it moves with whichever model is running; and the tool-result and user-message thresholds are different numbers (20,000 and 50,000) for different message kinds, not one global limit.
