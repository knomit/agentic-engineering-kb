# A fork out of a live conversation — compaction above all — gets zero cache unless it reuses the parent's exact prefix, and the uncached version costs more the longer the history it is summarising

A side call an agent makes out of its own conversation — compaction, a summary, a classification of the history so far — gets no cache benefit at all unless it is built from the parent's exact prefix. Prompt caching matches byte for byte from the start of the request, so a summarisation call issued the natural way, with its own purpose-built system prompt and no tool definitions, makes "the prefixes diverge at the very first token and none of the cache applies."

The cost shape is the trap, because it inverts the intuition that a summary call is small: the uncached call re-bills the entire history it is summarising at full input price, so "the longer the conversation... the more expensive that one call becomes" — which is exactly when compaction is reached for. Anthropic's Claude Code team reports that a forked compaction call reusing the parent prefix instead "reuses the same prefix for a cache hit at one tenth the price."

The construction has three parts and all three are load-bearing: the fork sends the SAME system prompt, the SAME user and system context, and the SAME tool definitions as the parent, and appends the fork's own instruction as a final USER message. Dropping the tool definitions because a summariser will not call anything, or moving the instruction into the system prompt where it reads more naturally, each rewrites the prefix and forfeits the whole discount.

Two consequences for the surrounding design. Reserve a compaction buffer in the context window — room for the compaction message plus the summary output, around 20k tokens of summary in the team's example — because a context window filled to the limit cannot run the call that would relieve it. And the same construction is what makes any branch-per-subtask shape affordable: a background task forked off a live conversation is the same operation as compaction, with the same prefix requirement.

What this does NOT mean: a fork is not free. It still pays for its own output tokens and for whatever it appends, so compaction remains an investment with a payback period rather than a saving; the rule here lowers the price of the call, it does not remove it.
