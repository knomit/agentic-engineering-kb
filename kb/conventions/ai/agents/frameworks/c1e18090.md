# Own your prompts, context window, and control flow rather than inheriting framework defaults

The 12-factor-agents argument against leaning on agent frameworks, stated as what each default actually costs:

- Own your prompts (Factor 2): a framework-supplied prompt you cannot see is a quality ceiling you cannot debug. When output is wrong you need to edit the exact tokens, not a config knob two abstractions away.
- Own your context window (Factor 3): frameworks that auto-assemble context pad it with material you did not choose, spending attention budget and degrading decisions. Context assembly is the highest-leverage thing you control; delegating it is delegating the outcome.
- Own your control flow (Factor 8): specify explicitly when the loop continues, branches, and terminates. A generic "loop until done" hides the decision that determines cost and termination behaviour — and it is the one that produces runaway runs.
- Compact errors into context (Factor 9): summarise errors into a minimal actionable form. Both extremes fail — dumping a full stack trace burns context on frames the model cannot use, and swallowing the error leaves it blind.
- Tools are just structured outputs (Factor 4): a tool call is the model emitting JSON that your deterministic code then acts on. Nothing about it is magical, and treating it as such leads to expecting the model to "handle" execution concerns that belong in your code.

The useful reading is not "never use a framework" — it is that these five are the things to keep in your own codebase even when you do, because they are where quality lives.
