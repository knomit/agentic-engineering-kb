# Keep an unattended agent's rules in a store it cannot write, re-read them fresh every run, and stop rather than fall back to defaults when the read fails

The reference design splits memory in two by write permission, not by content type: a `preferences` store the agent can only read (channels, repos, exclusions, length cap, destination, stop conditions) and a `state` store it can read and write (bookmarks, ledger, run records, source-behaviour notes).

Three rules hang off that split:
- "Have the agent read the file fresh every run." A copy baked into the system prompt keeps applying rules the file no longer contains, and the symptom is a retired topic reappearing rather than an error.
- If the preferences file cannot be read, stop and say so rather than running on defaults. A default-configured unattended run is a different agent doing a similar-looking job.
- Feedback the agent wants to keep goes into `state` as a PROPOSED preference change, for a human to promote. The agent can therefore learn across runs without being able to rewrite the rules that bound it.

A fourth, operational: creating the store does not seed its contents, so the preferences file has to exist before the first run or the first run is the default-configured one.

Operational consequence: the write boundary is the enforcement. A prompt instruction not to change its own rules is not the same control, because the text that reaches an unattended agent includes other people's messages.
