# The intern test: decide between more context, decomposition, and debugging

A diagnostic for a task an agent is failing at. Ask: could a relevant college student, given the same inputs, complete this task — and how long would it take them?

- If NO, they could not do it with these inputs → the problem is context. "If the answer is no because the LLM lacks the required knowledge, consider ways to enrich the context." More prompting will not conjure information that is absent.
- If NO **and the context cannot be improved** → this is the source's fourth outcome and it is not a fix at all: "If the answer is no and we simply can't improve the context to fix it, then we may have hit a task that's too hard for contemporary LLMs." Reading the test as three remedies is what turns a feasibility verdict into another round of prompt work.
- If YES but it would take them a long time → the problem is scope: "we can try to reduce the complexity of the task." Decomposition into steps is one way; standardising the task's templatable parts is another.
- If YES and quickly → context and scope are fine, so the problem is in your pipeline. Go look at the failure traces.

The source's own name for this is the "intern test," and its framing is "an average college student in the relevant major."

The value is that it separates three fixes and one non-fix that look identical from the outside — an agent producing a wrong answer gives no signal about which one it needs, and teams default to prompt-tweaking regardless of which of the three is actually broken.
