# A monitor reading agent-authored text can be fed forged conversation turns — frame each real turn with an unguessable per-process identifier and escape the content, so a forgery cannot close the frame

When a monitor is shown the agent's transcript, everything the agent wrote is attacker-controlled text that arrives inside the monitor's own prompt. The red-teaming of Claude Code's Auto Mode and Codex's Guardian found this to be one of four working attack classes: content the agent authored fooled the monitor, including by forging turns that never happened.

THE MITIGATION THAT WORKED was not better monitor instructions. It was making the frame around each turn unforgeable: heredoc-style delimiting where the delimiter is "a 48-bit hex string derived from the turn under a per-process key", plus escaping of the content inside it. The agent cannot predict the delimiter, so it cannot write text that closes one frame and opens another; the authors report this substantially mitigated monitor injection.

THE OPERATIONAL RULE. Treat the monitor's prompt as a parser with a quoting problem, not as a reader with a judgement problem. Derive the delimiter per turn from a secret the monitored process does not hold, make it long enough that guessing is hopeless, and escape the payload anyway so a collision is not a bypass. A fixed string, a constant tag name, or a delimiter the agent can read out of its own context buys nothing.

WHAT THIS DOES NOT FIX. Unforgeable framing addresses injection only. It does nothing for the three other classes measured in the same work: edits the monitor never sees, attacks split across sessions or compactions so no single monitor view contains the whole thing, and a prompted policy that simply does not name the harmful behaviour. The same work concluded that "robustly preventing multi-context attacks at an acceptable cost remains an open problem", so a team that lands the framing fix should not record the monitor-evasion problem as closed.
