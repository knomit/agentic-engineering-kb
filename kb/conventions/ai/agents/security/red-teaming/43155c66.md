# Memory poisoning and rogue-agent probing belong in continuous operations, not pre-release testing — OWASP's red-team landscape places them by lifecycle stage

OWASP's Q2 2026 red-teaming landscape organises AI security capabilities across nine lifecycle stages (Scope & Plan, Augment/Fine-Tune Data, Develop & Experiment, Test & Evaluate, Release, Deploy, Operate, Monitor, Govern) crossed with four roles — Red (attack simulation), Blue (defense/detection/response), Purple (**continuous attack–defense fusion**, closed-loop feedback so adversarial findings directly improve controls), and Shared (inventory, telemetry, provenance, metrics, audit artifacts).

Most of the catalogue is generic security capability. **What is worth extracting is where the agent-specific attack classes are placed**, because the placement carries a claim:

- **Operate (continuous), not Test & Evaluate** — autonomous red bots, continuous prompt fuzzing, **memory poisoning**, anomaly and drift detection, trust-boundary alerting, auto guardrail patching. The stated principle for this stage is "continuous security rather than point-in-time testing."
- **Test & Evaluate** — automated adversarial suites, prompt-chaining attacks, multi-turn attacks, **protocol attacks (A2A, MCP)**, RAG-poison scenario runners, guardrail conformance testing, **hallucination vs misalignment labeling**, CI hooks.
- **Deploy** — tool-chain/plug-in misuse simulation, agent privilege-escalation emulation, cross-tenant data exposure testing, live traffic chaos simulation, real-time policy shadow mode, **protocol spoofing (MCP/A2A)**, cost-impact tracking.
- **Monitor** — synthetic user and **rogue-agent generation** to test whether detection actually fires, UEBA for agent signals, agent behavior analytics, **model-drift vs threat-drift analysis**.
- **Develop** — agent-logic corruption testing, reasoning-trace capture.

**Three placements that are actual guidance rather than taxonomy:**

1. **Memory poisoning sits in Operate, not in pre-release testing.** That follows from its mechanism: the attack is persistent and cross-session, so a pre-release test suite runs against a clean memory and cannot reproduce it. Testing it once before launch measures nothing.
2. **Rogue-agent generation is a Monitor-stage activity aimed at your detection stack, not your agent.** You inject synthetic rogue agents to verify the alerting fires — testing the detector, not the system under test. Detection that has never been exercised against a real signal is unverified.
3. **"Hallucination vs misalignment labeling" is called out as a distinct required capability.** Treating those two as one bucket is common and wrong: a hallucination is a capability failure to be fixed with grounding or retrieval; misalignment is a behavioural failure requiring containment and policy. The same wrong output demands opposite responses, so the label determines the fix.

Source caveat, and it matters here: this is a **vendor-landscape document with gold and silver sponsors**, and the capability taxonomy doubles as a market map for products sold into each cell. Read the stage/role structure as useful; do not read the completeness of any cell as evidence that the capability is necessary or that tooling is the right answer. No measurements, thresholds or efficacy data are offered anywhere in it.
