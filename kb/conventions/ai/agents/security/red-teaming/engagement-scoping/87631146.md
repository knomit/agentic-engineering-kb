# Scoping an agent red-team: over-refusal is a mandatory oracle, production tests carry their own quotas, and the attack corpus must not flow into training automatically

Five scoping rules from OWASP's GenAI Red Teaming Manual v1.0 that change how an engagement against an agent system is run, each of which an engagement designed around "can we make it misbehave" gets wrong.

Over-refusal is not an optional domain. Among roughly thirty testing domains the manual lists for the exploitation phase, over-refusal is called "a mandatory oracle". An engagement that measures only induced misbehaviour will pass a system that has been hardened into uselessness, and that outcome is a finding the manual requires you to produce.

Production testing is budgeted, not merely permitted. Testing against production "must enforce conservative rate limits, token quotas, and concurrency caps", must be non-destructive and non-persistent, and must avoid altering shared state. For multi-tenant systems, "Request at least two distinct, isolated user accounts" — one account cannot demonstrate cross-tenant leakage. Every credential issued carries a recorded expiration date and an offboarding checklist.

Authorized traffic has to be distinguishable from an attack. The manual puts attribution tags, such as a test header, in the access plan so a SOC can tell testing from a live incident; without one, a successful red-team finding also produces a false incident.

The attack corpus is not training data by default: "collected attack data should not enter training pipelines automatically". The corpus is a labelled set of attacks already known to work on this system, so an automatic path from it into fine-tuning data is an unreviewed decision about what the model learns to expect.

A finding is not closed by the report. The deliverable package the manual specifies is an executive summary, technical walkthroughs, PoC replay scripts and a remediation verification timeline, and it states "Assign an owner to verify each fix and report the retest outcome." The replay script and the named owner are what make the retest possible; a prose finding without either cannot be verified as fixed.

Scope note: this is the manual's prescribed process, not a measured outcome — the document states what an engagement should produce, and reports no data on engagements that followed it.
