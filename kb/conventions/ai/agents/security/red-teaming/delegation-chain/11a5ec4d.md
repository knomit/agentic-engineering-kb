# The authority ceiling in a delegation chain is the originating user, and the test for it is a compromised peer — one approval at the top of a chain also leaves a time-of-check/time-of-use gap

OWASP's GenAI Red Teaming Manual v1.0 states the test that settles whether a multi-agent system's permissions mean anything: whether a compromised peer agent can make another agent exceed the ORIGINATING USER's authority. That is the ceiling — not the called agent's own grant, and not the orchestrator's. A chain in which every hop is individually within its own permissions can still carry a request past the ceiling, and no single hop's permission check sees that.

The tests that exercise the chain, as the manual names them: delegation depth; confused-deputy paths; stale or inherited credentials; high-impact action confirmation; and denied-call tests against runtime policy enforcement rather than against tool descriptions.

The second finding is about WHEN authorization is checked. The manual names time-of-check/time-of-use gaps as an agent-specific class and gives per-action reauthorization as the remedy. One approval taken at the top of a chain is a check against state that may have changed by the time the action lands, so an approval that was honest when granted can authorize something else by the time it is used. The consequence for design: carry the authorization decision down to each consequential action, rather than minting a chain-wide token at the start.

What this does not say: that per-action reauthorization means a human prompt per action. The reauthorization is against policy; a human confirmation is a separate control the manual lists for high-impact actions only, and conflating them produces the approval fatigue that makes operators disable both.

A trap when recording findings from this: the manual requires the taxonomy EDITION to be recorded with every tag, as in "LLM03:2026", and the AIVSS (or other) severity score to be stored "separately from the OWASP taxonomy tag". The Top 10 numbering is re-cut between editions, so a bare ASI or LLM number in a tracker cannot be resolved later, and a score merged into the tag field cannot be re-scored without rewriting the finding's classification.
