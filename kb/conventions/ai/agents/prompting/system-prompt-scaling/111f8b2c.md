# System prompts should SHRINK as models improve — Claude Code removed over 80% of its own for Claude Opus 5 and Claude Fable 5 with no measurable loss on its coding evals

The Claude Code team maintains DIFFERENT SYSTEM PROMPTS PER MODEL rather than one prompt behind a model switch. The team's own account states the scale and the result together: "We removed over 80% of Claude Code's system prompt for models like Claude Opus 5 and Claude Fable 5 with no measurable loss on our coding evaluations." Older models keep the fuller instructions because they have less judgment to fall back on. The eval clause is the load-bearing half of that sentence: the cut was measured against their coding evaluations and found not to cost anything, which is what separates this from an aesthetic preference for short prompts. The practical consequence: a prompt is tuned to a model's capability level, so carrying last year's prompt onto a new model is not a neutral default — it is applying scaffolding to a model that no longer needs it, and the scaffolding costs you.

Three specific things they removed, each counter to common practice:

1. EXAMPLES. Removing them "was extremely helpful, because it was just more creative than the examples we gave it." Few-shot examples set a ceiling as much as a floor — on a strong model they collapse the output distribution toward the samples you happened to write.

2. "DO NOT DO X" DIRECTIVES. Negative constraints "can be extremely confusing to Claude" when they conflict with what the user is actually asking for. The model is left arbitrating between your prohibition and the user's request, and that arbitration is a failure mode you introduced.

3. INSTRUCTIONS THAT ARE ONLY 90% TRUE. Their example: "always verify front-end changes" is wrong for a one-word copy change, so they replaced it with contextual guidance. A rule with unstated exceptions teaches the model that your rules have unstated exceptions, which devalues the ones that are absolute.

The testable heuristic: on a model upgrade, try DELETING prompt material before adding any, and treat every "always" and "never" in an existing prompt as a claim to be checked for the 10% case. This is the same direction as the documented inversion where emphatic anti-laziness tool instructions start causing overtriggering on newer models — both say that prompt scaffolding written for a weaker model becomes actively harmful rather than merely redundant.

The team's stated DIAGNOSIS of why so much could go names a mechanism rather than redundancy: they had overconstrained the model, and instructions from the system prompt, from skills, and from the user's own request were competing against one another inside the same context. On that reading, prompt debt on a stronger model does not present as wasted tokens — it presents as the model arbitrating between your constraints and the user's intent, which is failure mode 2 above generalised from one directive to the whole context.

The material also did not simply vanish, and reading the 80% as "a frontier model needs almost no instruction" is the available misreading. What replaced it: judgement-shaped instructions keyed to observable context in place of absolutes — "default to writing no comments" became "Write code that reads like the surrounding code: match its comment density, naming, and idiom"; expressive tool parameters in place of long usage examples in tool descriptions; progressive disclosure, with code review and verification moved out into separate skills and tools loaded on demand through a tool-search step rather than all declared upfront; and tool usage instructions living in the tool description instead of being restated in the system prompt. The 80% measures how much left the always-loaded system prompt, not how much guidance the harness now runs on.

Source modality: the figure, the eval result, the diagnosis and the replacements are the team's own published account. The three removal categories numbered above, and their quotations, come from a conference-talk summary of the same team's practice.

The harness ships a `/doctor` command intended to help rightsize an existing system prompt, skills and CLAUDE.md against this advice.
