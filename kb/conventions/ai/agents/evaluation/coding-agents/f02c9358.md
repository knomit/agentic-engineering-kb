# For a coding agent, the reliable check is running the repository's own tests after the run — and every run needs its own clean copy of the repo

Rather than have a judge read what the agent said it did, "the reliable check is to run the repo's tests after the agent finishes." The agent's reply is a report; the tests score the artefact. A judge grading the reply is measuring the agent's description of its own work, which is exactly the channel most likely to be confidently wrong.

The isolation requirement comes with it and is not hygiene: "For that to work, every test run needs its own clean copy of the repo so runs don't affect each other." With a shared checkout, one run's edits decide another run's result, and the damage does not announce itself as an error — it appears as unexplained variance in the score, which is the hardest kind of eval defect to notice, because a noisy suite looks like a flaky agent.

This is the same move as scoring a text-to-SQL agent on the executed result rather than the query text ([[9c0087aa]]): when the agent produces a checkable artefact, check the artefact. The generalisation is that an LLM judge is for qualities with no executable check, not a default.
