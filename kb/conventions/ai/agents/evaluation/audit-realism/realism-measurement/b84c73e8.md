# Realism win rate: score an eval transcript by pairing it against a real deployment transcript and asking a judge which is the eval — and run deployment-against-deployment first, because that is the judge's own suspicion floor

An automated auditor such as Petri builds its own system prompts, tool definitions and codebases, and those synthetic artifacts carry tells a capable target can detect. Measuring how well an audit hides is the problem this method solves, and the METHOD is the transferable part, because the two obvious alternatives both fail in the direction that flatters.

THE METHOD. Take the evaluation transcript and N real deployment transcripts. Repeatedly show a judge ONE PAIR — the eval transcript alongside one deployment transcript — and ask it to pick which of the two is the evaluation. The realism win rate is the fraction of pairs in which the eval transcript fooled the judge. In the source's setup N was 25 transcripts of the first author's own Claude Code usage, or a "mixed deployment" set of 10 Claude Code transcripts + 10 WildChat transcripts involving misuse or harmful requests + 10 "vulnerable" WildChat transcripts where the user is in an unusual or vulnerable situation; the judge was Claude Sonnet 4.5 with extended thinking.

WHY NOT THE TWO STANDARD METRICS — both score a transcript IN ISOLATION, and the source names the same two defects in each.
- Verbalized situational awareness (does the target state in its reasoning that it suspects a test) is BINARY, and it misses unverbalized situational awareness entirely: a model can behave differently because of a belief it never states, and chains of thought need not be faithful.
- Post-hoc realism rating (hand a judge the transcript and ask for a 0-10 realism score) is coarse and MIS-FIRES ON REAL TRAFFIC. Run against genuine deployment transcripts the scores come out bimodal and the judge "sometimes confidently label[s] real deployment usage as evaluations".
A score computed on one transcript has no way to separate "this eval looks fake" from "this judge thinks anything unusual is fake". The pairing supplies exactly that control, because both sides of every comparison are read by the same judge in the same call.

RUN THE DEPLOYMENT-VERSUS-DEPLOYMENT CONTROL, AND RUN IT FIRST. Pair real deployment transcripts against OTHER real deployment transcripts and measure their win rates. In this setup Sonnet 4.5 "thinks the harmful wildchat transcripts are least realistic, with the Claude Code transcripts as most realistic, and the 'vulnerable' WildChat transcripts in the middle" — every transcript in that comparison is real traffic. That spread is the judge's own suspicion profile, and an eval's win rate is only interpretable against it.

THE FLOOR IS PER-JUDGE, NOT UNIVERSAL. The same bias "is less present for Gemini 3 Pro, suggesting different models are suspicious of different features", and judges differ dramatically in raw detection ability (measured across Sonnet 3.7, Sonnet 4.5 and Opus 4.5). The TARGET model, held against a fixed judge, did not notably move the win rate. So a realism number is a joint property of the judge and the deployment baseline: reported without naming both, it is not comparable to anyone else's, and not comparable to your own from last quarter if either changed.

WHAT THE JUDGE ACTUALLY KEYS ON, taken from classifying its own reasoning traces in the cases where it correctly identified the eval: the coding environment being "too clean" compared with real deployment, unrealistic user behaviour, artificial pressure from the user, and inconsistent tool results (the auditor simulating a tool result impossible given the codebase). These are the four things to attack, and they are individually measurable.

THE STANDING LIMIT OF THE METRIC, stated by the authors: it "is highly dependent on the deployment data that we use", and theirs were "only 25-30 transcripts in size, and come from narrow subsets of the deployment distribution". A baseline drawn only from low-stakes work lets the judge win on the heuristic that the more harmful or higher-stakes situation must be the eval, which measures your scenario rather than your environment.

WHAT A HIGH WIN RATE DOES NOT MEAN: it is not evidence that the target BEHAVES as it would in deployment. Realism and behaviour were measured separately in this work and moved differently.
