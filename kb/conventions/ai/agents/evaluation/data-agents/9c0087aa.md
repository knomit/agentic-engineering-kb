# Scoring a text-to-SQL agent on its query text passes wrong answers — execute the generated SQL and compare the returned data against a hand-authored golden query's result

OpenAI's internal data agent is evaluated on curated question-and-answer pairs, each "paired with a manually authored 'golden' SQL query that produces the expected result". The generated SQL is then executed, and both the SQL and the resulting data are compared; the post states plainly that "Evaluation doesn't rely on naive string matching." A grader returns a score together with an explanation.

The reason the result comparison is the load-bearing half: for a given question there are many correct queries and far more incorrect ones that resemble the golden query closely in text. Text similarity therefore ranks a subtly wrong query above a correct one written differently, in both directions. Executing both and comparing the data is the only comparison that tracks the thing the user asked for.

Where these evals run, in two places with different purposes: like unit tests during development, and as canaries in production. The second is what catches a warehouse whose schema or contents moved underneath an agent that did not change.

Not established here: the post publishes no pass rates, no thresholds and no suite size, so this is an eval design to copy rather than a benchmark to compare against. It also does not say how result comparison handles ordering, column naming or floating-point tolerance, which is where this approach's real work usually sits.
