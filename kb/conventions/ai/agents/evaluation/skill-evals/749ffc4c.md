# A skill eval asserts five different things and only three of them leave an artifact — triggering needs negative controls, and 10 to 20 prompts is enough to start

Testing an agent skill means asserting five separable things, each with its own evidence source, and treating them as one "does the skill work" score hides the two failure modes that cost the most.

- Triggering: was the skill selected at all? Exercised with explicit invocation, implicit invocation, contextual prompts, and NEGATIVE CONTROLS — prompts that must not fire it. The name and description in `SKILL.md` are the signals under test.
- Trajectory: what did the run actually do? Read from `codex exec --json` JSONL events — whether a setup step such as `npm install` ran, the order of commands, and the command COUNT, which is what catches looping.
- Outcome: artifacts on disk, extended later with a build, a smoke test and a clean `git status --porcelain`.
- Output quality: a read-only rubric pass through `--output-schema`, returning `overall_pass`, an integer `score` from 0 to 100 and per-check `id`/`pass`/`notes`.
- Efficiency: `usage.input_tokens` and `usage.output_tokens` from `turn.completed`, compared across skill versions to catch prompt bloat.

Ordering that matters: deterministic graders first because they are debuggable and explain their failures, and a model-based rubric only for the qualitative requirements file checks cannot express. Keep the must-pass list small.

Sizing: "a small set of 10-20 prompts is enough to surface regressions and confirm improvements early" for a single skill, held as a CSV of `id`, `should_trigger`, `prompt`, and grown from real failures rather than designed up front. The worked example runs four cases — explicit, implicit, contextual, and one `should_trigger=false` control.

The consequence of leaving the negative control out: over-triggering is invisible. The named example is a generic "add Tailwind styling to my existing React app" prompt activating a project-scaffolding skill, which then scaffolds a new project where the user wanted an incremental change. A suite built only from prompts that should fire scores that run as a pass.

What this does NOT mean: the five classes are not five scores to average. Triggering and trajectory are gates — a run that did not fire the skill, or fired it and skipped a required step, has no meaningful output score to report.
