# Run security-relevant agent evals both with and without defenses — the gap is the number that matters

From a survey of seven cybersecurity agent benchmarks: measure capability twice, once against a bare target and once with realistic protections (ASLR, sandboxing) enabled. The single-number version of why: on ExploitGym, Claude Mythos exploited 157 of 898 instances against undefended targets, and 45 with defenses in place. Reporting either number alone misleads — the first overstates real-world risk, the second hides the raw capability that a defense regression would expose.

The same discipline applies outside security. Any agent eval run against a permissive environment measures something different from the same eval run against the guardrails you actually ship. Report both, and treat the ratio as the value your defenses are providing.

Two further measurement rules from the same survey, both about not fooling yourself:
- Use DETERMINISTIC graders keyed on outcomes — a sanitizer crash, a captured flag — rather than validating the method the agent used. Outcome graders survive an agent that finds a better route; method graders do not.
- Control for contamination by separating post-training-cutoff tasks. Public exploits and their writeups leak into training data, so a benchmark built from known CVEs measures recall as much as capability.

Calibration figure worth carrying: transcript audits in this survey found reward-hacking risk to be real, with 94% agreement between independent auditors on whether a solve was legitimate — so human transcript review is reproducible enough to be worth doing, not merely subjective.
