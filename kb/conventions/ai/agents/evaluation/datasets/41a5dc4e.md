# What keeps an agent eval dataset comparable is evaluator identity, not size — one dataset per behaviour-plus-evaluator-set, and ten to twenty examples is enough to start one

The partition rule is about the evaluators rather than the examples. Examples belong in the SAME dataset when they test the same behaviour with the same evaluators, which is what makes two experiments on it comparable. A NEW dataset is called for when the input shape differs (single requests versus full conversations), when the evaluators differ, or when the purpose differs — the post's contrast being a small set run on every pull request against a larger set run before a release.

The consequence, and the mistake it prevents: the instrument has to be fixed for the comparison to mean anything, so folding a second behaviour into an existing dataset to get a larger N destroys the trend line the dataset existed to produce. If two behaviours need different evaluators they are different datasets, however related they look.

The starting recipe that goes with it is deliberately small. Pick ONE behaviour (their example is whether a travel assistant books the requested dates and price range) and build its dataset from real traces, because "Ten to twenty examples of a behavior is enough to start". Run the current agent over it and SAVE that run as an experiment, so it is the baseline later versions are measured against rather than a number nobody kept. Every later failure, in production or in testing, becomes a new example in that dataset; before an agent is live, trusted testers using it supply the traces instead.

Note that this is a different quantity from the 5–10 human-labelled ground-truth examples the same vendor's docs give as a floor ([[47f5445a]]): that count is labelled references, this one is examples of a behaviour. Neither has a measurement behind it. Both exist to defeat the same objection — that an eval set must be large before it is worth having — and neither is a sufficient suite size.
