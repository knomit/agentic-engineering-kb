# Carry the grader's identity as a coefficient inside the evaluation model instead of validating it in a separate step — the published interval then contains the grader's error instead of discarding it

UK AISI's proposed framework for autograder-based evaluation: fit a Bayesian generalised linear model whose linear predictor includes a term for grader identity, so you "use autograders for model evaluations, while simultaneously assessing the quality of those autograders." An individual coefficient represents "the impact of using a human vs an LLM grader"; a link function puts the outcome "in a scale that is suitable for the properties of our data"; the fit returns a posterior — "a range of possible values and their respective probabilities" — rather than a point estimate. Binomial, Poisson and other distributions cover the shapes evaluation outcomes actually take: binary pass/fail, ordinal scores such as a 1-10 coherence rating, and counts such as a mistake tally.

WHY THE STRUCTURE MATTERS MORE THAN THE STATISTICS. The common practice is validate-then-trust: measure grader-human agreement on a sample, accept the grader, then run the evaluation and report its result. That pipeline drops the grader's residual disagreement at the handoff, so the interval around the headline number reflects only sampling noise and omits the largest systematic term in the measurement. Putting grader identity in the model as a covariate propagates it instead, which is the difference between a result that knows which grader produced it and one that does not.

AISI's stated motivation is that grader choice is systematic rather than noise: autograders "tend to grade outputs from models of the same family more highly" and "can also have preferences for longer outputs, or ones written in a particular style or containing certain keywords". Same-family preference in particular does not average out of a cross-model comparison — it moves the comparison in a fixed direction — so a grader drawn from one of the families under test is a confound, not a noise source. The bias list corroborates [[38c06627]].

WHAT IS NOT ESTABLISHED. The post publishes no measured results, no sample sizes and no worked thresholds; it describes the framework and points to open-source code. It is a proposed method, not a validated one, and the pack holds no evidence here that a GLM-based estimate tracks ground truth better than a validated point estimate does. AISI claims suitability "particularly where data is noisy or limited, which is not uncommon in LLM evaluations" — an argument from the method's properties, not a demonstration. Treat the bias list as the evidenced claim and the estimator as a design option worth the implementation cost only where the grader's error is plausibly larger than the effect being measured.
