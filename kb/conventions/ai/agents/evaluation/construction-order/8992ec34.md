# State when an alignment evaluation was built relative to training, and state the negative too — three Astra evaluations disclose construction-after-training, and the honeypot one additionally discloses that no training environments were built to target it

An alignment evaluation's result is only interpretable alongside its construction order: whether the evaluation existed before training finished, and therefore whether the model could have been optimised against it. OpenAI's GPT-6 Astra safeguards card makes this disclosure inline, per evaluation rather than once in a methods note. Respecting Auto-Review: "This evaluation was constructed after Astra had completed training and was not used during training." Respecting Warnings: "Like Circumventing Auto-Review, this evaluation was constructed after Astra completed training."

THE STRONGER FORM IS THE NEGATIVE, AND IT IS A SEPARATE CLAIM. For the Declining to Exploit Honeypot evaluation — built in response to the Hugging Face incident — the card states: "We developed this evaluation following the Hugging Face incident. We did not construct honeypot training environments specifically to target this evaluation or reproduce the incident." Construction order alone says the test postdates training. The negative says nobody built training data aimed at the behaviour the test measures. A team can satisfy the first and violate the second by writing the eval last and the targeted training environments first, so the two disclosures are not interchangeable and a card carrying only the first has not ruled out the second.

WHAT THIS DOES NOT MEAN. Constructed-after-training is not a claim that the result generalises, and it is not a claim of independence: the same organisation still wrote both the training curriculum and the test, so this rules out direct optimisation against the specific eval and nothing more. Nor does it transfer across a model family — the disclosure is scoped to one model's training run, so an inherited evaluation reused on a successor has to be re-qualified against that successor's training.

OPERATIONALLY, for anyone reading or publishing agent safety evaluations: treat an undated evaluation as one that may have been trained against, and ask for both statements rather than one. This is the same hazard [[kb/conventions/ai/agents/evaluation/incident-derived/a8635d4d.md]] names from the other direction — an eval built from an incident is a regression test, and a detector built by hillclimbing on that incident's own artifacts measures nothing.
