# Verify computer-use agents against database state, not screen output — and build the world you train against, because live sites cannot be re-run

Microsoft Research's stated reason for building synthetic training worlds rather than using real sites is an evaluation-methodology argument, and it is the part worth keeping: live websites are unstable and constantly changing, which makes them unsuitable for repeated runs, and they give an agent nowhere safe to practise login-gated, write-heavy workflows — exactly the workflows that matter commercially and that you cannot rehearse against someone's production account.

Two design choices generalise to anyone evaluating an agent that acts on a UI:

- **Ground the verification in database state, not in the interface.** Echoverse scores tasks against database truth rather than against what the screen or the agent's transcript says. This is the computer-use analogue of the trajectory-vs-output-scoring rule: an agent can narrate success, or land on a page that looks right, without the write having happened. The assertion belongs where the state actually changed.
- **Treat a failed run as possible evidence against the environment.** Their pipeline runs analyser and fixer agents over failures and loops them back 'to improve the world itself, not just the model', repairing generated apps until they 'pass machine-checkable claims' about routes, state and behaviour. Pair this with the standing rule that an environment failure rate above ~5% is a harness problem rather than a model problem — same principle, applied as a build loop.

Reported numbers, as an indication of what a purpose-built environment is worth: a 9-billion-parameter model trained on these worlds went from **36.5% to 67.1%**, landing 'within fourteen points of GPT-5.4' (80.7%) on the synthetic domains; reinforcement learning against the environments lifted held-out performance from **58% to 69%**; and the gains transferred to live-web benchmarks (WebVoyager, Online-Mind2Web) despite no live-web training data.

Read the numbers with care and the method with more confidence than the scores. This is a research-blog announcement from the team that built the system, the headline gains are measured largely on the same synthetic domains the model trained on — the live-web transfer is described qualitatively rather than quantified — and no independent replication exists. The methodological claims (database-grounded verification, environment repair loops, capability-isolating worlds for specific UI interactions such as date pickers and nested filters) are the durable part; treat the percentages as the authors' own.
