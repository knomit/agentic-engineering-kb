# Agent instruction files are concatenated, not overridden: a nearer file does not win, two contradictory rules resolve arbitrarily, and splitting one into imports does not reduce what it costs

Claude Code discovers instruction files by "walking up the directory tree from your current working directory, checking each directory along the way for `CLAUDE.md` and `CLAUDE.local.md` files". What it then does with them is the part that gets compressed wrongly: "All discovered files are concatenated into context rather than overriding each other."

There is a documented ORDER — managed policy, then user, then project, then local, "from broadest scope to most specific"; across the tree "content is ordered from the filesystem root down to your working directory"; and within a directory "`CLAUDE.local.md` is appended after `CLAUDE.md`". Order is not precedence. The same page states that "if two rules contradict each other, Claude may pick one arbitrarily".

CONSEQUENCE. You cannot override an inherited rule by restating it in a nearer or later-loaded file. The nearer statement is appended, both statements sit in context, and which one the model follows is undetermined. To change an inherited rule, edit or delete the original. The same reasoning applies to a repository that inherits a user-level or organization-level file: adding a contradicting project rule does not neutralise it.

WHAT THIS DOES NOT MEAN. Documented load order does not imply last-write-wins, and it does not imply first-write-wins either. Nothing in the documentation assigns a winner between two concatenated contradictory instructions.

THE TENSION TO KNOW ABOUT. For the `.claude/rules/` mechanism the same page DOES assert precedence — "User-level rules are loaded before project rules, giving project rules higher priority" — while denying override semantics for CLAUDE.md files, and it does not reconcile the two. Treat rule priority as claimed and CLAUDE.md precedence as absent.

SIZE AND SPLITTING. "CLAUDE.md files are loaded in full regardless of length, though shorter files produce better adherence", and the stated aim is to "target under 200 lines per CLAUDE.md file". Splitting a long file does not help: "Splitting into `@path` imports helps organization but does not reduce context, since imported files load at launch", with imports recursive to "a maximum depth of four hops". Two mechanisms do defer loading, and they are the only ones named: a CLAUDE.md in a subdirectory, where "Instead of loading them at launch, they are included when Claude reads files in those subdirectories", and a path-scoped rule, which "trigger[s] when Claude reads files matching the pattern, not on every tool use". A CLAUDE.md in an additionally configured working directory is not loaded at all by default.
