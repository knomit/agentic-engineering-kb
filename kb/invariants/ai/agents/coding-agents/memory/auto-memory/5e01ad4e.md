# Auto memory loads the first 200 lines of MEMORY.md OR the first 25KB, whichever comes first, and is machine-local — the identical 200 for CLAUDE.md is a soft target on a file that always loads in full

Two documented limits in Claude Code's memory system share the number 200 and are not the same kind of limit. Confusing them is how a hard truncation gets read as a style guideline.

THE HARD ONE, on auto memory: "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation." Both halves of that disjunction are load-bearing: 150 long lines can exceed 25KB and be cut, and 200 short lines can be under 25KB and survive. Content past whichever threshold hits first "is not loaded at session start", so a fact written at the end of a grown MEMORY.md is on disk and not in context.

THE SOFT ONE, on project instructions: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence", and separately "CLAUDE.md files are loaded in full regardless of length". Nothing truncates a CLAUDE.md. Exceeding the target costs attention, not content.

SCOPE. "Auto memory is machine-local." It does not follow the repository, so it is not a channel for team conventions and it is not present on a CI runner, a cloud session or a colleague's machine. Anything another machine must know belongs in a checked-in instruction file.

CONSEQUENCE for a self-writing memory: an append-only MEMORY.md silently stops being read past its cap rather than erroring, so the mechanism that keeps it useful is pruning or promotion at write time, not a review later.
