# Enforce branch protection at the repository layer, not in the agent's config — and expect agent-authored commits to regress your SLSA provenance level

Two claims from OWASP's 2026 state-of-agentic-security report, both easy to get wrong in exactly the direction that feels convenient.

**1. Removing human review from the merge path silently downgrades a supply-chain attestation.** Agent-generated commits that bypass human review *regress an organization's SLSA provenance level*, eliminating the attestation guarantees manual review workflows provide. So agent autonomy in the merge path is not only a code-quality question; if you publish or contractually claim a provenance level, autonomous merges can invalidate the claim without any visible failure. Re-derive the claim rather than assuming it carries over.

**2. The enforcement point must sit where the agent cannot reach it.** Branch protection rules and required-reviewer policies must be enforced at the repository layer, not at the agent's configuration, "since agents that can influence their own configuration can also weaken the controls meant to bound them."

Generalised: **a control an agent can reach is not a control on that agent.** Put enforcement in the forge's server-side policy, not in a file inside the repo the agent is editing, a CLI flag it can pass, or an agent settings file it can rewrite.

The misreading to avoid: this does *not* say agents must not commit, and it is not an argument for human review of every diff. It says the review gate and the mechanism enforcing it must live outside the agent's blast radius, and that provenance claims must be re-derived when the gate changes.
