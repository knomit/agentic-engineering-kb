# Classification that stops at the raw data layer protects nothing: six surfaces carry the same sensitivity, and the only proof is deleting a test record and finding no trace in any of them

OWASP's GenAI data-security guide enumerates six surfaces a single sensitive record lands on, and states that classification which stops at the first one provides no protection:

1. Source data — raw corpora structured and unstructured, user uploads, tickets, knowledge bases.
2. Derived data — embeddings, indexes, retrieved passages, summaries, synthetic datasets, feature stores.
3. Model artifacts — checkpoints, adapters and LoRA, training logs, evaluation sets, model registries.
4. Runtime data — prompts, context windows, tool calls, agent-to-agent messages, KV caches, session memory.
5. Operational exhaust — logs, traces, debug captures, monitoring pipelines.
6. Agent state — short- and long-term memory, tool payloads, delegation chains, cached credentials.

The guide's framing of why the runtime surface is the hardest: a context window merges trust domains into a single flat namespace with no internal access control, so a record admitted anywhere in it is readable by everything else in it.

THE VERIFICATION IS THE ACTIONABLE PART, because an erasure policy is unfalsifiable without it. The guide prescribes a simulated deletion test — delete a test record and verify no trace across the database, the logs, the embeddings, the backups and the model outputs — and, separately, membership inference audits on the model itself to test whether sensitive records are learnable. Its other lifecycle controls: TTLs on agent memory and cached retrievals, data-to-model lineage, blocking training and indexing of restricted records without explicit approval, ingress scanning, and quarterly lineage and classification audits.

Operational consequence: when a deletion request, a retention limit or a sensitivity label is implemented, the acceptance test is the sweep across all six surfaces, not the row disappearing from the source store. An embedding or a KV cache derived from a deleted record is still that record.

WHAT THIS DOES NOT MEAN: this is a stated control framework, not an audited outcome — the guide presents its tiers as maturity levels rather than a pre-production checklist, and names no tolerance for a failed check.
