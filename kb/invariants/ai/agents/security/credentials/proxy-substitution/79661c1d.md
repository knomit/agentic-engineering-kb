# A proxy-substituted secret works only for an outbound HTTPS header on port 443 or 8443 from an OpenAI-hosted sandbox, and two separate allowlists have to agree — one lets the sandbox reach the host, the other lets the proxy supply the secret

OpenAI's Agents API Vaults keep a credential out of the agent's instructions and configuration and inject it at the network edge instead. A vault is attached per session with `vault_ids`. For the sandbox case the credential type is `environment_variable`, and the documented mechanism is that the sandbox receives a placeholder in the named environment variable while the real secret stays outside the sandbox: "Printing the variable inside the sandbox shows the placeholder, not the token." A network proxy substitutes the real value on approved outbound requests. Retrieving a vault or credential through the API does not return its secret values.

FOUR CONDITIONS ALL HAVE TO HOLD, and each one is a separate way to get a silent failure or a design dead end.

First, the shape of use: the placeholder is passed unchanged in an HTTPS request header. The documentation states the limit directly — "It cannot supply the real secret for local computation, such as signing a request" — and directs that case to a function tool instead. So any scheme that needs the plaintext in the sandbox (HMAC signing, a JWT assembled locally, a non-HTTP protocol) cannot use this mechanism at all.

Second, the transport: "The proxy supplies secrets only to HTTPS destinations on port 443 or 8443." Plain HTTP and any other port get the placeholder and nothing else.

Third, the two host lists, which do different jobs and are easy to conflate: `allowed_domains` lets the sandbox connect to a host, while the credential's own `allowed_hosts` lets the proxy supply the secret to that host. Both must name the host, and `allowed_hosts` takes exact host names "without a scheme, path, port, or wildcard". With restricted network access, every credential host must also appear in `allowed_domains`, and `network.access` must not be set to `disabled` for a session that has environment credentials.

Fourth, the environment: this workflow requires an `openai_hosted` environment. It does not supply credentials to self-hosted environments or to function tools the application runs. Each attached environment credential also needs a unique `secret_name`, and that name must not also be defined in `environment.env`. `secret_name` and `networking` are immutable — changing either means creating a new credential.

WHAT THIS DOES NOT MEAN. "The real secret stays outside the sandbox" is a statement about the sandbox, not about the whole system: the documentation does not say whether the model's own context ever holds the value, so do not read it as a guarantee that the credential is invisible to the model. It is also not a revocation boundary — deleting the stored credential does not revoke the upstream token.
