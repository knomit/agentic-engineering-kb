# The lethal trifecta: private data + untrusted content + exfiltration channel — a screening heuristic, not a safety threshold

An agent becomes exploitable by prompt injection when it simultaneously has all three of: (1) access to private data, (2) exposure to attacker-controllable content, and (3) a way to communicate externally. All three together mean an attacker who can write text your agent reads can cause it to read secrets and send them out. The root cause is that models cannot reliably distinguish instruction provenance — operator instructions and injected text are both just tokens.

**Meta's "Agents Rule of Two" (October 2025) turns this into a design constraint:** within any session that does not require human approval, an agent should satisfy **no more than two** of the three properties; a three-property configuration requires human-in-the-loop approval before the agent acts.

**Do not read "two is safe".** An earlier revision of this fact said "any two are survivable" — that was wrong, and OWASP's 2026 state-of-agentic-security report names the counter-evidence: the Rule of Two "is valuable for explaining the structural problem, but it is not a complete defence," and *Invitation Is All You Need* (2025) documents attacks delivered through calendar invitations **that remain viable with only two of the three properties present**. Treat the trifecta as a screening heuristic that tells you when you are certainly exploitable, not as a threshold that certifies you are not. OWASP's own finding is consistent with the heuristic's value at the top end: the enterprise prompt-injection incidents it documents "consistently involve agents that satisfied all three properties without approval gates."

What this does NOT mean: it is not a call for better filtering. Willison explicitly rejects detection guardrails as the control here — vendors advertising ~95% catch rates are quoting what is, in application security, a failing grade, because an attacker simply retries until one payload lands. Telling the model in your own system prompt to ignore injected instructions is likewise not a control.

Actionable consequence: treat the trifecta as an architectural invariant to design around. Remove one leg per agent — no external egress once untrusted content has entered the context, or no private-data tools in the same session that browses untrusted pages. Splitting capability across sessions is a real mitigation; a classifier in front of one is not. Then, because two legs are not a safe harbour, still gate consequential actions on approval and still assume the remaining two-property configuration is attackable.

Why the residual risk exists at all: what counts as an "exfiltration channel" is broader than an outbound HTTP tool — a calendar response, a rendered link, or the agent's own visible output can carry data out. Enumerating the third leg is harder than it looks, which is the most likely reason two-property attacks keep working.
