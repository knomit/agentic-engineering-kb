# The lethal trifecta: private data + untrusted content + exfiltration channel

An agent becomes exploitable by prompt injection when it simultaneously has all three of: (1) access to private data, (2) exposure to attacker-controllable content, and (3) a way to communicate externally. Any two are survivable; all three together mean an attacker who can write text your agent reads can cause it to read secrets and send them out. The root cause is that models cannot reliably distinguish instruction provenance — operator instructions and injected text are both just tokens.

What this does NOT mean: it is not a call for better filtering. Willison explicitly rejects detection guardrails as the control here — vendors advertising ~95% catch rates are quoting what is, in application security, a failing grade, because an attacker simply retries until one payload lands. Telling the model in your own system prompt to ignore injected instructions is likewise not a control.

Actionable consequence: treat the trifecta as an architectural invariant to design around. Remove one leg per agent — no external egress once untrusted content has entered the context, or no private-data tools in the same session that browses untrusted pages. Splitting capability across sessions is a real mitigation; a classifier in front of one is not.
