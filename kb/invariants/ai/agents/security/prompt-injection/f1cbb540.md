# A permission classifier must be reasoning-blind, and a denial must be a tool result that says do not route around it

Three rules from Claude Code's auto mode that generalise to any agent guarded by a model-based permission check.

1. THE CLASSIFIER MUST NOT READ THE AGENT'S REASONING. Anthropic's is "reasoning-blind by design": assistant messages and tool results are stripped before it sees anything, leaving only user messages and the executable payload. The reason is direct — if the classifier reads the agent's justification, then an injected instruction that convinces the agent also convinces its guard, and the two layers collapse into one. A guard that can be argued with by the thing it guards is not a second layer. Judge the ACTION and its provenance, never the stated intent behind it.

2. A DENIAL IS A PROMPT. When an action is blocked, it comes back as a tool result carrying an instruction to find a safer path and explicitly NOT to try to route around the block. Returning a bare error invites the agent to treat the guard as an obstacle to be engineered around — which is exactly the behaviour that turns a blocked `rm -rf` into a creative shell equivalent. Say what to do differently, not just that it was refused.

3. CAP ESCALATION, DON'T JUST COUNT IT. Sessions halt after 3 CONSECUTIVE denials or 20 total. Two thresholds, because they catch different pathologies: consecutive denials mean the agent is stuck retrying variations of a forbidden action right now, while a high total across a long session means the run has drifted somewhere it should not be even if it keeps recovering. A single counter catches only one of these.

Separately, injection defence is two-layered on the way in as well as the way out: a server-side probe scans tool outputs for injection attempts and prepends warnings before the results reach the agent. Note the ordering — the annotation happens outside the agent, because a scan the agent performs on its own context is subject to the same injection it is looking for.
