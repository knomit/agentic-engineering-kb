# Data residency guarantees cover data at rest, not inference location — and latency-based routing is incompatible with sovereignty by construction

Microsoft draws a distinction that is easy to read past and expensive to get wrong. For Azure Global and Data Zone deployments, "data stored at rest remains in the designated Azure geography," but that data "might be transmitted and processed for inferencing in any hosting location" — any region at all for Global deployments, or any location inside the specified data zone for Data Zone deployments.

So the residency guarantee you were sold is about storage. The prompt itself, which for an agent contains retrieved documents, tool outputs and conversation history, crosses borders at inference time. If your obligation is about processing rather than storage, a Global deployment does not satisfy it regardless of what the resource's region says.

The routing consequence is categorical, not a matter of tuning. Performance-based or latency-based routing selects an endpoint by whichever is fastest right now, which means it will cross a geopolitical boundary whenever that is fastest — so it cannot be reconciled with a sovereignty requirement, and Microsoft says it "needs to be highly scrutinized" and that a unified gateway spanning geopolitical regions "would violate the data residency requirements." Every active-active and active-passive failover pattern inherits the same limitation: each is only usable when all regions involved stay inside one geopolitical boundary.

The prescribed shape is therefore a fully independent, highly available gateway per geopolitical region, treating each boundary as an isolated stamp, with active-active or active-passive handling applied only within a stamp. Two enforcement details that are easy to omit: clients must be BLOCKED from reaching gateway endpoints outside their own region, not merely configured to prefer their own — and the gateway must not make a cross-boundary call on the client's behalf even when the client asked correctly. A failover rule written without a boundary check is the most likely place this breaks, because it fires only during an incident, when nobody is reviewing routing decisions.
