# Every gate between external data and a promoted model must fail closed, and the promotion gate has to score memorization alongside capability or a leakier model ships for looking better

OWASP's GenAI data-security guide states the path from external data to a promoted model as a series of gates, and every one of them is specified to fail closed rather than to warn:

- Ingestion: never ingest external data directly into production training pipelines; quarantine external data first. Schema validation failures must block ingestion, not merely log a warning. Refuse symlinks unconditionally. Run services non-root with read-only mounts.
- Artifacts: unsigned artifacts must not be loaded, executed, or promoted. The guide names a CycloneDX ML-BOM (ECMA-424, v1.7) as the base format for what an artifact declares, plus reproducible builds and supplier vetting.
- Detection: canary triggers validate every training run, and behavioural divergence on the canaries is the early indicator of poisoning. A checksum comparison against the last known good state is prescribed, with no numeric tolerance defined for divergence.

THE PROMOTION GATE IS THE NON-OBVIOUS ONE. The guide puts memorization metrics in the promotion criteria and states that a model with better benchmarks but more memorization should be flagged, not promoted. A privacy regression therefore has to be scored in the same decision as the capability gain, because a capability-only gate will always promote the leakier model: more memorization tends to read as better performance on exactly the benchmarks the gate measures.

Why the thresholds are this strict: the guide cites a research result of 250 poisoned samples, 0.00016% of training tokens, and presents it as a LOWER BOUND for effective poisoning. At that fraction, sampling-based review cannot be the control — only a gate that refuses unverified input can be.

WHAT THIS DOES NOT MEAN: signing an artifact does not establish that its contents are sound, only that it is the artifact the pipeline approved. A pipeline that verifies signatures and then reuses an unverified cached input still fails — see [[f1e54f16]], where exactly that let an intervention be zeroed out while the run reported success and produced a normal-looking checkpoint. Source caveat: the document's risk list runs DSGAI01 to DSGAI21 but cites DSGAI25 and DSGAI26, which do not appear in its own list, so a cross-reference by identifier may not resolve.
