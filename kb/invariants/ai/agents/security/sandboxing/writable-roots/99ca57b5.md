# An agent's writable root must subtract the directories that configure the agent and hold the repository's history — Codex denies writes to .git, .codex and .agents inside the very workspace it can otherwise write

Granting a coding agent write access to its working directory is not one decision but two, and Codex's Windows sandbox separates them explicitly. Write, execute and delete access is granted — via a sandbox-only synthetic SID on the ACLs — to the current working directory and any configured writable_roots. Then "The sandbox setup explicitly denied that same SID write access to 'read-only within writable' locations such as" `<cwd>/.git`, `<cwd>/.codex` and `<cwd>/.agents`.

The rule to carry over: the writable set is the task's product surface MINUS the paths that determine the agent's own behaviour and the paths that record what it did. Agent configuration and instruction files are the first class, because a write there reconfigures the agent for its next turn rather than changing the product — so none of the agent's own permission checks fire on the escalation. Version-control metadata is the second, because an agent that can write .git can rewrite or discard the history that is the audit trail of its changes, which is the record a reviewer relies on.

WHAT THIS DOES NOT MEAN: this is not a claim that the agent's instruction files should be immutable across the board — a human or a separate privileged step may legitimately update them. The rule is that the agent running the task does not hold that write while running it. Nor does the deny list end at these three names: they are the instances in one harness, and the test to apply to any candidate path is whether writing it changes the agent's future behaviour or the record of its past behaviour rather than the artifact under construction.

One mechanism caveat from the same source: read access in this design is granted by extra ACLs applied best-effort and asynchronously, and applying workspace ACLs can be expensive depending on directory structure — so a deny that depends on ACL application has a window and a cost, and is weaker than a profile the kernel evaluates per call.
