# Proxy environment variables and stubbed PATH binaries are an advisory network restriction, not a sandbox boundary — and when the OS cannot match a filter rule to the restricted token, the enforceable identity has to be a separate user account

Codex's first, unelevated attempt at restricting an agent's network on Windows worked by environment overrides: pointing proxy variables at a dead port and stubbing SSH binaries on PATH. OpenAI's own verdict on it is that "it was still only advisory" and that it "wasn't designed to hold up to adversarial code." A program that ignores proxy variables or opens its own socket simply is not restricted by it.

The design constraint that decided the replacement is the transferable part. The natural move is to attach the network rule to the restricted token the child process already runs under, and that is not available: "Windows doesn't allow matching a firewall rule to the non-principal identity of a restricted token." Per-binary rules were judged too coarse, and port or address rules did not fit the problem. So the enforceable identity had to be manufactured: Codex creates two dedicated local users, "CodexSandboxOffline (the one targeted by firewall rules)" and "CodexSandboxOnline (the one not targeted by firewall rules)," and the network policy is a Windows Firewall rule aimed at the first. The sandbox users' credentials are encrypted with DPAPI and stored where those users cannot read them.

The operational consequence when building an agent sandbox: find out what identity your platform's network filter can actually match, and make the agent's processes run as that identity. Windows offers no built-in equivalent of macOS Seatbelt or Linux seccomp, so this is construction work, not configuration.

WHAT THIS DOES NOT MEAN: it does not mean environment-variable restriction is useless — it stops well-behaved tooling and is cheap. It means it must not be counted as containment in a threat model that includes prompt injection or a model acting against its instructions, because the thing it relies on is the restricted program's cooperation. The two-account design also costs something the advisory one did not: the current design requires administrator rights at setup time.
