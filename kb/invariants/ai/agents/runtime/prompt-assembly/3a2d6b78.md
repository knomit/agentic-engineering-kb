# Who assembles a Responses-API agent prompt: the server orders it, the client supplies instructions, tools and input, and AGENTS.md content is capped at 32 KiB by default

In the Codex loop over OpenAI's Responses API, the prompt is not assembled client-side. The server orders it; the client supplies three fields — `instructions`, `tools` and `input` — and the roles are ranked system, developer, user, assistant.

The `instructions` field comes from `model_instructions_file` when that is set, and otherwise from the model's own `base_instructions`. Project instructions gathered from AGENTS.md files enter as user instructions and are "Subject to a limit (32 KiB, by default)".

Two operational consequences. First, a client cannot control where in the prompt its material lands beyond choosing the field and the role, so the question "will the model see this before that" is answered by the field, not by concatenation order. Second, 32 KiB is roughly eight thousand tokens of project instruction; a repository whose AGENTS.md tree exceeds it loses the overflow at the harness boundary, before the model or any context-management policy is involved.

Transport detail for anyone instrumenting the loop: requests go to the Responses API as HTTP with a Server-Sent Events response, and the endpoint is configurable — ChatGPT login uses `https://chatgpt.com/backend-api/codex/responses`, API-key auth uses `https://api.openai.com/v1/responses`, and `--oss` defaults to `http://localhost:11434/v1/responses`.
