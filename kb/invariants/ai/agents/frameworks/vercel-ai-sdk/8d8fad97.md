# AI SDK agent loops silently stop at 20 steps by default, and isLoopFinished() removes the ceiling entirely

In the Vercel AI SDK, an agent loop with no `stopWhen` set defaults to a step-count stop the docs name `isStepCount(20)`. Two consequences that bite in opposite directions.

First, a long-horizon agent that needs more than 20 steps does not error — it stops and returns whatever it has, which reads like a normal completion. If you only look at the output text you cannot tell a finished run from a truncated one; you have to inspect why the loop ended. This is the same class of bug as a silently truncated paginated API response, and it gets worse as you add tools, because more tool round-trips fit inside the same logical task.

Second, the obvious fix — swapping in `isLoopFinished()` so the agent decides when it is done — removes the ceiling. The docs warn that `isLoopFinished()` never triggers on its own; without a step limit alongside it the loop can run indefinitely and accrue unbounded cost. `stopWhen` accepts an array and stops when ANY condition is met, so the correct shape is a generous step count AND the natural-completion condition, never the completion condition alone. `hasToolCall(...names)` is the third built-in: stop when the agent calls a designated terminal tool.

`prepareStep` runs before each iteration and receives `stepNumber`, the prior `steps`, and the message state. It can override `model`, `activeTools`, `toolChoice` and `messages` for that step alone. That is the seam for narrowing the tool surface as a run progresses or dropping to a cheaper model for mechanical steps — you do not need separate agent definitions to do it.
