# AI SDK agent loops silently stop at 20 steps by default, and isLoopFinished() removes the ceiling entirely

In the Vercel AI SDK the default belongs to a named class, and the docs state it in one sentence: "By default, `ToolLoopAgent` stops after 20 steps using `isStepCount(20)`." An agent loop with no `stopWhen` set therefore truncates at 20 steps. Two consequences that bite in opposite directions.

First, a long-horizon agent that needs more than 20 steps does not error — it stops and returns whatever it has, which reads like a normal completion. If you only look at the output text you cannot tell a finished run from a truncated one; you have to inspect why the loop ended. This is the same class of bug as a silently truncated paginated API response, and it gets worse as you add tools, because more tool round-trips fit inside the same logical task.

Second, the obvious fix — swapping in `isLoopFinished()` so the agent decides when it is done — removes the ceiling. The docs warn that `isLoopFinished()` never triggers on its own; without a step limit alongside it the loop can run indefinitely and accrue unbounded cost. `stopWhen` accepts an array and stops when ANY condition is met, so the correct shape is a generous step count AND the natural-completion condition, never the completion condition alone. `hasToolCall(...names)` is the third built-in: stop when the agent calls a designated terminal tool.

`prepareStep` runs before each iteration. Its arguments, as the docs' own annotations name them, are `model` ("Current model configuration"), `stepNumber` ("Current step number (0-indexed)"), `steps` ("All previous steps with their results") and `messages` ("Messages to be sent to the model"), plus `initialMessages` and `responseMessages`. Its override surface is wider than the loop-shaping fields alone: it returns `model`, `activeTools`, `toolChoice` and `messages`, and the docs also state that "`prepareStep` can override `maxOutputTokens`, `temperature`, `topP`, `topK`, `presencePenalty`, `frequencyPenalty`," continuing with `stopSequences`, `seed` and `reasoning`. So per-step sampling control is available here too, not only per-step tool and model selection. That is the seam for narrowing the tool surface as a run progresses or dropping to a cheaper model for mechanical steps — you do not need separate agent definitions to do it.
