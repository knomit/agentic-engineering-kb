# Goose subagents: 25 turns and 5 minutes by default, no recursion, and a failed subagent returns nothing at all

Concrete limits from Goose's subagent implementation, useful both as defaults to know and as a reference point for what any subagent contract should specify.

- Max turns: 25, overridable via the `GOOSE_SUBAGENT_MAX_TURNS` environment variable or in natural language in the prompt.
- Timeout: 5 minutes by default; a longer one is requested in the prompt rather than configured.
- Context: subagents INHERIT the parent session's context and extensions by default ("Extensions | Inherited from parent"). Restricting tool access is opt-in, and is recommended for security, focus, or performance — so the safe-by-default assumption does not hold; a subagent sees what its parent sees unless you narrow it.
- Recursion is blocked: "Subagent spawning: Cannot create additional subagents to prevent infinite recursion." A subagent also cannot enable or disable extensions, or manage scheduled tasks.

The failure semantics are the part that bites, and the source is explicit: "If a subagent fails or times out (5-minute default), you will receive no output from that subagent. For parallel execution, if any subagent fails, you get results only from the successful ones." Not partial work, not a summary of how far it got. So a parallel fan-out silently returns an incomplete result set rather than an error, and the parent has to notice the gap itself. Design the parent's prompt to verify it received a result per dispatched task, and prefer subagent tasks small enough to finish inside the 5-minute and 25-turn envelope over ones that will half-finish and vanish.

Tool calls made by a subagent surface as expandable sections in the parent conversation, and the return mode is configurable between full detail and summary-only.
