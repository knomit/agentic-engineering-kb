# OpenAI subagents inherit MCP tools with their credentials but cannot use function tools, and they share the coordinator's single environment

Delegation is off unless `agent.multi_agent.enabled` is set to `true` at session creation. When it is on, the harness supplies the coordination tools itself — create, message, wait for, and interrupt a subagent — rather than you declaring them. `max_concurrent_subagents` caps simultaneous subagents and must be a positive integer when delegation is enabled; the default concurrency is 6, **excluding the coordinator**, so the ceiling on live agents is seven, not six. To disable delegation, omit `multi_agent`, or set `enabled` to `false` and omit the limit.

THE ASYMMETRY, and it runs in the surprising direction on both sides: subagents do not support function tools, but they do inherit the configured MCP tools together with their credentials and allowed tools, and the web search settings. The capability you reasoned about as the coordinator's — an MCP server holding a live credential — reaches every subagent, while the function tools your orchestration logic was written against are simply absent there.

They also share one filesystem. Creating a subagent does not create another environment: the coordinator and its subagents operate in the same environment's filesystem and can use its files and command-line tools. The guide states that agents editing the same files must coordinate their changes, and describes no mechanism for doing so, so that coordination is yours to build. Compare [[6fba697c]] for the same shape in Anthropic's dynamic workflows, where the shared filesystem is likewise the coordination substrate.

Settings apply at session creation, and changes to a stored agent affect only new sessions — so a concurrency or delegation change does not reach sessions already running.

What this does NOT mean: the absence of function tools in subagents is not a reason to move that work onto MCP without re-examining the credential question. The same inheritance that makes an MCP tool work inside a subagent is what hands that subagent the credential. Decide the credential scope first, then the transport.
