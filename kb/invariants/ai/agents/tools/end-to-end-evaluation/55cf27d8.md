# A tool whose output is correct in isolation can still fail to raise the agent's score — measured across 13 tool configurations, with three named mechanisms for the gap

AuditBench evaluates alignment-auditing tools by giving them to an investigator agent rather than running them standalone, and the reason is a measured gap: "tools that surface accurate evidence in isolation often fail to improve agent performance". A static arm applies each tool directly to the target and has an LLM judge check whether the output reveals the behaviour; the agentic arm gives the same tool to an agent. The two arms disagree, and the static arm is the optimistic one.

Three mechanisms are named for the gap, and each is a separate failure:

- UNDERUSE. The agent abandons the tool before it has paid off. On one tool the page reports "agents often invoke it only 5-10 times before switching back to standard conversation." (That count is stated for that one tool, not as a total across the agent's run.)
- FALSE POSITIVES. "Agents that encounter these false positives may investigate false leads rather than productive directions." A tool with a tolerable false-positive rate for a human reviewer can be worse than nothing for an agent, because the agent spends its remaining turns on the false lead.
- EVIDENCE-TO-HYPOTHESIS. Correct evidence does not become the correct conclusion: the work "requires combining tool outputs in ways that agents sometimes fail to accomplish".

Operational consequence: a tool's acceptance test is the agent's end-to-end task score with the tool available, never the tool's own output quality. Precision matters more than a human-facing tool's would, because a false lead costs turns the agent cannot get back, and a tool that needs several outputs combined needs the combining done for it or demonstrated to it.

What this does NOT mean: it is not the tool-count claim that adding tools degrades selection, and it is not a claim that the tools were inaccurate. The static arm shows the evidence was there.

Scale and scope of the measurement: 13 tool configurations on a 56-model benchmark — "We evaluate 13 tool configurations on AuditBench’s 56 models" — with "We run each agent configuration 16 times per target model per tool configuration". The agent is built on the Claude Agent SDK and the task is finding an implanted hidden behaviour, so the gap is established for investigative search, not for every tool class.
