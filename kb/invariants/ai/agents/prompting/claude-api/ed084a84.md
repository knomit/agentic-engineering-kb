# Assistant prefill and budget_tokens are now 400 errors, not degraded behaviour — and thinking defaults differ per model

Two long-standing prompt-engineering techniques became hard failures rather than quietly-worse behaviour, which matters because a 400 takes down a production path on the day you switch models.

1. Prefilled assistant responses — supplying a partial assistant message on the LAST turn for the model to continue from — are unsupported starting with Claude 4.6 models and Claude Mythos Preview; such requests return 400. Assistant messages elsewhere in the conversation are unaffected, so it is specifically the trailing prefill that breaks. Replacements, by original use case: structured outputs (or a tool with an enum field) for forcing JSON/classification shape; a plain system instruction for preamble suppression, with post-processing to strip the occasional leak; and for continuations, move the interrupted text into a USER message ("your previous response was interrupted and ended with […] — continue from where you left off").

2. `thinking: {type: "enabled", budget_tokens: N}` is deprecated on Opus 4.6 and Sonnet 4.6 and returns 400 on Claude 4.7 and later. The replacement is `thinking: {type: "adaptive"}` with `output_config.effort`, using `max_tokens` as the hard ceiling. There is no direct token-budget equivalent — you steer depth with effort, not with a number.

The thinking DEFAULT also varies by model, which is the part that silently changes behaviour and cost when you swap a model string: omitting `thinking` leaves it off on Opus 4.6–4.8 and Sonnet 4.6, but on Opus 5 and Sonnet 5 thinking is on by default. On Opus 5 it can only be disabled at effort high or lower, and on Fable 5 / Mythos 5 it is always on regardless of the parameter. Never assume omitting the parameter means the same thing across a model migration.
