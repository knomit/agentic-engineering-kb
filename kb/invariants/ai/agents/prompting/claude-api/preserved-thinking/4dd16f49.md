# Preserved thinking blocks editing Claude's prior context on Fable 5.1 and Opus 5.5 — but only for API accounts created on or after 2026-08-31, so the same code works on one account and not another

Anthropic introduced "preserved thinking" with Claude Fable 5.1 as an anti-distillation safeguard and shipped it again with Claude Opus 5.5 (launched 2026-09-22). Its stated function: it "stops API users from editing Claude's prior context in an attempt to extract Claude's reasoning."

THE CONDITION IS COMPOUND AND BOTH HALVES BIND, in one sentence: "It applies to Fable 5.1 and Opus 5.5 for API accounts created on or after August 31, 2026." Note the boundary is ON OR AFTER that date, so an account created exactly on 2026-08-31 is subject to it. Neither half alone predicts the behaviour: an older account calling Opus 5.5 is not subject to it, and a new account calling an older model is not either. The practical consequence of the account-age half is the one that costs debugging time — identical client code behaves differently on two accounts at the same organisation, and a reproduction on the older account will not show the failure.

WHY IT REACHES ORDINARY AGENT CODE AND NOT ONLY ATTACKERS: editing prior assistant turns is a mainstream context-engineering technique, not an exotic one. Compaction that rewrites earlier turns into a summary, a scaffold that trims or reorders thinking blocks to fit a window, a replay harness that reconstructs a conversation from stored state — all of these edit prior context, and all of them are what this safeguard is built to reject. The motivation is extraction (distillation attacks using many fake accounts to pull a model's reasoning at industrial scale), but the mechanism does not read intent.

OPERATIONAL: if you compact, replay or rewrite assistant history against these models, test on an account created after the cutoff before assuming your pipeline works, and treat the newer account as the one that tells the truth about production. The API-level detail of what exactly is rejected is not in the launch post, which says only that the safeguard "stops API users from editing Claude's prior context in an attempt to extract Claude's reasoning." The post sends readers to two documents for it: the preserved-thinking docs at https://platform.claude.com/docs/en/build-with-claude/preserved-thinking, which it says "show how to test and update your integrations", and a Help Center article at https://support.claude.com/en/articles/16761192. Go there for the interface; this fact carries the policy and the account-age trap only.

NOT ESTABLISHED HERE: the error mode (whether an edited prior context is rejected with an error, silently ignored, or degraded), whether the cutoff will move, and whether the restriction extends to later models. The launch post states the policy, not the interface.
