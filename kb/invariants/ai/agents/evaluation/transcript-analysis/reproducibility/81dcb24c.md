# An LLM-judged transcript analysis is not reproducible from its inputs — pinning the transcript, categories, settings, code and software versions still yields different labels, so the stored judgements are the artifact

UK AISI, releasing its Transect transcript-analysis package (2026-10-07), states the reproducibility condition for a model-judged analysis and then states that meeting it is not enough. Both halves matter and the second is the one that gets dropped.

**The inputs you must retain**, verbatim: "Rerunning the same analysis also requires retaining the transcript, category definitions, settings, custom analysis code and software versions." That is the ordinary reproducibility checklist — five things, all of them under your control.

**And it still does not reproduce the result**, verbatim: "Fresh model judgements may differ even when these are unchanged." The variance is in the judge, not in the configuration, so no amount of pinning removes it.

**What the tool does about it**, verbatim: "Transect saves activity labels and individual model judgements, so reviewers can reopen an analysis without making new model calls." Note the granularity — not just the aggregate labels but the *individual judgements* behind them.

**The operational consequence.** In an LLM-judged pipeline the system of record is the judgement output, not the recipe that produced it. Persist every individual judgement at write time and serve later reads from that store. A re-run is a NEW measurement that happens to use the same inputs; it is not a reproduction, and if you treat a second run's differing labels as a regression in your code you will debug the wrong thing. This also means an analysis whose judgements were not persisted is unauditable after the fact: you cannot recover what the reviewer saw, only what a fresh judge would say now.

**What this does NOT mean.** It does not mean pinning is pointless — AISI lists the five retained inputs as a requirement, so unpinned code and versions make the result *neither* reproducible *nor* interpretable. Pinning is necessary and insufficient. Nor does it mean the labels are worthless: the same post's remedy is to link every label back to its transcript passage, so a label's trustworthiness comes from being checkable against the source, not from being replayable.

**Scope.** This is a stated design rationale for one tool, not a measurement: AISI reports no variance figure, no rerun-agreement rate, and no quantitative evaluation of Transect's accuracy. The claim's strength is that the team shipping the tool chose caching over replay and said why.
