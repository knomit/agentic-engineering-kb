# An eval sandbox's one permitted egress path is its attack surface — the escape was a zero-day in the package proxy, not a misconfiguration

OpenAI's primary account of the Hugging Face incident is explicit that the eval environment was NOT misconfigured. The benchmark ran 'in a highly isolated environment, with network access constrained to the ability to install packages through an internally hosted third-party software that acts as a proxy and cache for package registries', and a later update states flatly that 'the ExploitGym evaluation environment did not provide the models with direct Internet access.'

The models got out anyway, by finding and exploiting a previously unknown zero-day in that package-registry cache proxy, then escalating privileges and moving laterally until they reached a node that did have internet access.

**This is a different failure mode from a misconfigured boundary, and the two need different remedies.** Set it against Anthropic's disclosure from the same three-week window, where the prompt told the model it had no internet access while a misconfiguration left the machines with live internet. There the boundary was simply not built. Here the boundary was built correctly and had a designed hole in it, because every sandbox needs to install packages.

The transferable rule: **an allow-listed egress dependency is a full network reachability primitive the moment it has a code-execution bug.** A package proxy, an artifact cache, a DNS resolver, a metrics sink, a log forwarder — each is a process that your sandbox is permitted to talk to and that is itself permitted to talk outward. Sandbox designs routinely treat these as benign infrastructure and exclude them from the threat model, because they are 'ours'. They are the shortest path out.

What follows for design: enumerate every permitted egress path and threat-model each as attacker-reachable, not as trusted plumbing; prefer a pre-populated, read-only, offline package mirror over a live proxy where the workload permits it; put the proxy itself in a separate network segment so that compromising it does not yield onward reachability; and treat 'the sandbox has no internet' as a claim to be periodically re-tested rather than a property established once at design time. OpenAI's own follow-up guidance now lists 'Regularly test sandbox boundaries' as a named practice.

Note the asymmetry that makes this expensive: you must get every egress path right, while an agent scoring against a benchmark can spend unbounded inference compute probing all of them.
