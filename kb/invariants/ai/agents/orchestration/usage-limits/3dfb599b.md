# A workflow run pauses on a usage limit instead of failing only when four conditions all hold, and the third hit fails the agent regardless

When an agent in a Claude Code dynamic workflow hits a claude.ai usage limit, the run can pause instead of failing that agent: the agents that hit the limit wait for the reset, no new agents start, and shortly after the reset the waiting agents run again and the run continues on its own. While it waits, the task-panel progress line and the `/workflows` header show when the limit resets.

The pause is not a property of the runtime. It holds only when ALL FOUR of these are true, and when one is not, the affected agent fails instead:

1. The session is interactive and signed in with a claude.ai subscription. It does not pause in non-interactive mode with `claude -p` or the Agent SDK, in a background session, or in a Remote Control or agent-team teammate session.
2. `autoContinueAtUsageLimit` is on — the same setting that lets the session itself wait for a reset. Turning it off during a wait ends the wait and the waiting agents fail.
3. The limit resets within 24 hours. A weekly limit can reset further out, and then does not qualify.
4. The run has not already waited twice. On the third hit, the agent fails.

It also requires Claude Code v2.1.271 or later; on earlier versions the affected agents fail.

WHAT THIS DOES NOT MEAN: it is not a general "workflows survive usage limits" guarantee, and dropping any one component turns the claim false. The headless, background and teammate paths — the unattended ones, where nobody is present to notice — are precisely the paths that fail rather than wait, and a long run that has waited twice has spent its whole allowance of waits. A usage-limit wait is also not a stall: time an agent spends waiting for a reset does not count toward the stall window, and an agent that does fail here fails the way [[565222b5]] describes.

Operational consequence: a workflow intended to run unattended needs its own resume path, because the pause mechanism is unavailable there by construction. The replay semantics that make a resume cheap or expensive are in [[d43b3db6]] — a failure mid-fan-out reruns every agent that started after it, completed ones included.
