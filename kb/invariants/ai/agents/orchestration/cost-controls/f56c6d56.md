# Every size control on Claude Code's workflow runtime except the runtime caps is advice to the model: the size guideline bounds nothing and the large-run warning does not pause the run

Claude Code's dynamic-workflow runtime exposes three things that look like limits on run size. Two are advisory and one is enforced, and treating the advisory pair as bounds is how a run costs more than planned.

ADVISORY (1) — the size guideline. `unrestricted` means no guideline; `small` is fewer than 5 agents, `medium` fewer than 10, `large` fewer than 50. The default is `medium`, or `small` when signed in on a Pro plan with v2.1.271 or later; the feature itself requires v2.1.219 or later, and earlier versions default to `unrestricted`. The documentation states the guideline is sent to Claude as advice, not a cap, so a prompt that calls for a different scale still overrides it. A `workflowSizeGuideline` key in a settings file takes precedence over `/config`, and changes take effect on the next prompt.

ADVISORY (2) — the `Large workflow` warning. It appears on the run's progress line when a workflow schedules more than 25 agents, or its projected token total passes 1.5 million. It is advisory: it does not pause or limit the run. Choosing a size guideline yourself replaces the 25-agent threshold with that guideline's own agent count, while the built-in default leaves the threshold at 25.

ENFORCED — the runtime caps, and only these. At most 4,096 items in a single `parallel()` or `pipeline()` call, and the runtime rejects a longer list with an error rather than silently truncating it. At most 1,000 agents total per run. Concurrency is up to 16 agents by default, fewer when Claude Code has fewer CPUs available, including inside a CPU-limited container, and settable from 1 to 256 with `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` on v2.1.269 or later.

WHAT THIS DOES NOT MEAN: choosing `small` does not cap a run at five agents, and the absence of a `Large workflow` warning is not evidence that a run is small — `large` moves the warning's threshold up to 50, so the louder the guideline the quieter the warning. The runtime caps still apply whatever the guideline says, and they bound a runaway script rather than a merely large one.

Operational consequence: to bound spend, run the workflow on a narrow slice first and stop it from `/workflows`, and set a developer-side budget rather than instructing the model — see [[09b6b554]].
