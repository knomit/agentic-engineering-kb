# The model does not know its budget while running, so agent spend is bounded by a developer-set session budget and never by instructing the model

Reported of Anthropic's dynamic workflows, in two clauses that belong together: "the model does not know its budget while running", and the control a developer has instead is that "developers can set a session budget".

THE OPERATIONAL CONSEQUENCE: cost is a harness-enforced ceiling, in exactly the way a permission boundary is. An instruction in the prompt to stay under some spend has no referent the model can measure itself against, so it cannot function as a limit. Set the session budget.

THE FORESEEABLE MISREADING, and it is the dangerous one: this does NOT mean the model will moderate itself, slow down, or stop as it approaches a limit. It has no signal with which to do so. A flow launched without a session budget therefore has no upper bound on spend, and a fan-out shape makes that unbounded quantity large — which is why the same source names runaway spend and over-spawning as separate failure modes rather than one.

The presenters' stated reason for not telling the model its budget is that doing so might make the model "anxious". Treat that as a rationale offered in a talk, not as a measured finding: the source reports no experiment comparing budget-aware with budget-blind runs.

PACK ANALYSIS: this is the cost-domain instance of the pattern that kb/gotchas/ai/agents/alignment/stated-compliance/de4e90a4.md records for forbidden actions — an in-context statement of a limit does not bind later behaviour, so the limit has to live in the runtime. The mechanism here is weaker and simpler than in that case: not that the model disregards a known limit, but that it is never given one to know.

SOURCE MODALITY: a third-party write-up of a talk by two Anthropic Members of Technical Staff at AI Engineer New York 2026, with no measurements of any kind.
