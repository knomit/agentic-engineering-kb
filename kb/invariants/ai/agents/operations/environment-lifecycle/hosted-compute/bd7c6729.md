# On OpenAI-hosted agent compute, "files persist across turns" holds only WHILE THE SANDBOX EXISTS, and the sandbox is deletable after an hour idle on a timeout that isn't configurable — the only durable copy is what reached /workspace/outputs before a turn completed

The durability rule for OpenAI's hosted sandboxes has three clauses, and only all three together say what survives. Each session gets its own workspace, and the documentation's own wording is that "Files persist across turns while its sandbox exists"; connected sandboxes also receive keep-alives between turns. But if activity and keep-alives stop for an hour the sandbox can be deleted, and of that timeout the page says plainly: "This timeout isn't configurable." What survives the deletion is only what was written under `/workspace/outputs` before a turn completed — those files are published as immutable artifacts at turn completion and stay downloadable after the sandbox is gone. Everything else in the workspace is not published and is not covered once the sandbox is gone.

SO THE OPERATIONAL RULE IS: `/workspace/outputs` is the only storage, and the moment of durability is turn completion, not file write. Anything an agent produces that a later turn, a later session or a human will need must be in that directory before the turn ends. The guidance when a sandbox has already expired is not recovery — it is to create a new session and supply the inputs again.

Three further lifecycle behaviours from the same page:

- **Closing the event stream does not cancel the task.** Disconnecting a reader is not a stop signal, so a client that drops the stream leaves work running and billing.
- **Deleting a session requests sandbox cleanup, and can return `409` while setup or execution is still finishing.** The documented handling is to wait and retry with a cap on attempts, so teardown is an eventually-consistent operation rather than a synchronous one.
- **Environment templates "save configuration, not a running workspace."** Reusing a template brings back the setup and carries over no files and no running state.

WHAT THIS DOES NOT MEAN. "Files persist across turns" must never be stored or repeated as "files persist": dropping the sandbox-existence clause is exactly how a true sentence becomes a false guarantee, and the hour is short enough that a human-in-the-loop pause reaches it. Nor is this the rule for self-hosted environments, which have their own and different lifecycle — there, reusing the environment ID does not restore files on replacement compute and deleting the session does not stop the compute (see [[6c3343c7]]). And the page does not state what happens to a sandbox when the calling application restarts; its stated mitigation is to save `session.id` from `agent.session.created` and to save the outputs you need before deleting the session.
