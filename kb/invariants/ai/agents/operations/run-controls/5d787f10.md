# A run's safety controls must fail closed in both directions — the run cannot start without monitoring, and the monitor cannot be switched off from inside the run

OpenAI's guidelines for frontier reinforcement-learning training runs state this control as a pair of negatives, and both halves are load-bearing: "it should not be possible to start runs without appropriate monitoring enabled, or to disable the monitor from within RL training, evaluation, or an internal deployment." A system satisfying only the first half still lets a monitored run silence its own monitor mid-flight; one satisfying only the second still lets an unmonitored run be started. The stated framing is that safety features "should fail closed", and that "it should be challenging for humans and agents to start noncompliant runs" — agents are named alongside humans as the party the control is against.

The same document pairs this with an escalation path designed to degrade safely when nobody answers. Priority alerts must "result in action within a defined SLA, either by paging an on-call person or by automatically pausing the affected run", and the worked example pages security on-call and the run owner for incidents during the day while auto-pausing runs for unacknowledged alerts at night. The unattended path is therefore a pause, not a queued alert — which is the design decision to copy, because an alerting path whose failure mode is silence gives an unattended run unbounded time to continue.

Scope: these are recommendations OpenAI describes as "in the process of being implemented", not an audited end state, and they are scoped to frontier reinforcement-learning training — the document states that "internal and external deployment require considering a much broader set of alignment properties." The transferable content is the shape of the control, not evidence that it is in place anywhere.

What this does NOT mean: it is not an argument for more monitoring coverage. Coverage and bypassability are independent properties — a fleet can monitor 100% of actions and still permit the monitored process to disable the monitor, and adding coverage does not close that gap.
