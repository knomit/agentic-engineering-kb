# An analytics agent must query as the user, not as itself — OpenAI's internal data agent passes the caller's permissions through to the warehouse

In OpenAI's internal data agent, warehouse access is pass-through: "users can only query tables they already have permission to access." The agent flags missing access rather than working around it. The same principle extends to the retrieved context — institutional documents from Slack, Google Docs and Notion are embedded and stored with metadata and permissions, and a retrieval service handles access control and caching.

The rule this encodes: an agent that holds its own credential becomes a confused deputy the moment it is reachable by more than one person, because its reach is the union of everything it can read and every requester who can ask it a question. Pass-through keeps the authorization boundary where it already was and already works.

The operational consequence that is easy to miss: the permission check has to cover the retrieval layer too, not just the query. An agent that enforces table permissions at execution time but embeds every internal document into one shared index has moved the leak from the warehouse to the index, where it is harder to see — a document's content can be surfaced in an answer without any table ever being queried.
