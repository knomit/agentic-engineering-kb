# Context is an attention budget: compaction, external notes, and just-in-time retrieval

Anthropic frames context as a finite resource that depletes with every token, not a container to fill. The mechanism given is architectural: transformers model n² pairwise token relationships, so attention is stretched thinner as length grows, and models have seen fewer long sequences in training. The result is a performance gradient, not a cliff — which is why it is easy to miss.

Three techniques, with the condition each fits:
- Compaction — summarise history near the limit and reinitialise. Use for long conversational back-and-forth. Preserve architectural decisions, unresolved bugs, and implementation details; drop redundant tool outputs. Claude Code carries forward the five most recently accessed files. The stated risk is real: over-aggressive compaction silently loses subtle context, and you find out later.
- Structured note-taking — the agent writes to an external file (NOTES.md, a memory tool) and re-reads it. Use for iterative work with clear milestones spanning sessions. Claude playing Pokémon maintained precise tallies across thousands of steps this way.
- Sub-agents — each works in a clean window and returns roughly 1,000-2,000 tokens of summary despite consuming tens of thousands internally. That compression ratio, not parallelism, is the point.

On retrieval: prefer just-in-time. Keep lightweight identifiers — file paths, queries, links — and let the agent load what it needs, as Claude Code does by piping through head and tail rather than reading whole files. The honest trade-off is that runtime exploration is slower than pre-computed retrieval, so hybrid (preload a little for speed, explore for the rest) is often right.

On tools: the test for whether your tool set is too ambiguous is whether a human engineer could definitively say which tool applies in a given situation. If they cannot, the agent certainly cannot.

On system prompts: aim for the right altitude — neither hardcoded brittle if-then logic nor vague aspiration. Start minimal on the best available model, then add instructions targeted at observed failure modes.
