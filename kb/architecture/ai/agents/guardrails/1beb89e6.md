# Layer guardrails and make approvals resumable, not restart-the-run

OpenAI's agent guidance places guardrails at three distinct points rather than one: input validation before the model sees the request, output filtering on what it produces, and tool-specific approvals at the point of action. They stack — each catches a class the others cannot, and an input classifier alone leaves the action surface unguarded.

The implementation detail worth copying is resumable approval flows. When a run pauses for human approval, the human reviews and the run CONTINUES from that point rather than restarting. If approval means re-running, two things follow: you pay the whole run's tokens again, and teams quietly stop asking for approval on the steps where it matters most because the cost is intolerable. Resumability is what makes human-in-the-loop economically survivable, which makes it a safety property and not just an ergonomic one — and it is the same requirement as pause/resume in externalised agent state.

Stated triggers for pausing: tool calls exceeding a risk threshold, actions modifying critical systems, and outputs violating policy. Note the first is a threshold you must define numerically, not a category — decide it before shipping rather than discovering it in an incident.

OpenAI also splits tools into data tools (web search, file search, retrieval), action tools (shell, code execution, computer use), and orchestration tools (agents-as-tools, MCP connectors). That taxonomy is directly useful for permissioning: the action tier is where approval gates belong, and it maps onto the exfiltration leg of the lethal trifecta.
