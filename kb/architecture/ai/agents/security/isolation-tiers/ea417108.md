# Three containment tiers for agents, and the two costs nobody plans for: EDR goes blind and the agent loop belongs outside the VM

Anthropic's published containment architecture spans three deployment shapes, and the useful content is the reasoning about where each stops working.

TIER 1 — EPHEMERAL CONTAINER (claude.ai). A gVisor container on isolated infrastructure, per-session filesystem, nothing persistent. Threat model is the traditional one: protect the infrastructure and other tenants from this session. Minimal blast radius, and correspondingly limited agent capability. This is the right tier when the agent does not need to touch anything of the user's.

TIER 2 — HUMAN-IN-LOOP SANDBOX (Claude Code). Runs on the user's own machine with real filesystem, shell and network. Started as approval-gated for writes, bash and network — and the measured outcome is the argument for changing it: "Our telemetry showed users approved roughly 93% of permission prompts", which is approval fatigue, which means the prompt that mattered got approved too. Adding an OS-level sandbox (Seatbelt on macOS, bubblewrap on Linux) with reads allowed, writes confined to the workspace and network denied by default produced "an 84% reduction in permission prompts" — a figure Anthropic frames as coming from its own internal usage. The security case for sandboxing here is not that it blocks more, it is that it asks less so the remaining asks get read. See [[2b9a10f8]] for the both-isolations-or-neither rule these numbers sit on.

TIER 3 — SEALED VM (Claude Cowork). Full VM isolation via Apple Virtualization or Windows HCS. Only the user-selected workspace folder is mounted; credentials stay in the host keychain. "The six main isolation mechanisms of Claude Cowork's VM. Two are enforced outside the guest kernel and would thus survive the agent achieving root-level access within the VM." So two survive a root compromise of the guest and four do not — which is the number to carry into a threat model, because it means most of the isolation is inside the thing being isolated. Mount modes: "Claude Cowork offers read-only, read-write, and read-write-no-delete."

TWO COSTS THAT ARRIVE WITH TIER 3, both of which teams discover late:

1. THE AGENT LOOP GOES OUTSIDE THE VM, code execution stays inside. Anthropic moved it for reliability — a VM that can be suspended, lose its network, or be rebooted is a bad host for the orchestration loop that has to survive those events. Plan the split before you build, because it decides where conversation state lives.

2. YOUR ENDPOINT DETECTION GOES BLIND. "The same isolation keeping Claude contained also kept host-based endpoint detection and response out...Our current mitigation is to use pull-based OTLP exports that let administrators retrieve event logs after the fact". Note 'after the fact': you trade live detection for forensics. Budget for replacing that visibility rather than assuming the VM subsumes it.

One more stated rule worth copying, on unvetted remote MCP servers: "Run it against fake data first, in an environment where the blast radius of a malicious tool is contained."
