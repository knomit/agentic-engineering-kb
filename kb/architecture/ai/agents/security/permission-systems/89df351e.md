# Tier permissions so the classifier only sees ambiguous actions, and stage the classifier itself to trade false positives against latency

Claude Code's auto mode is a worked example of how to grant an agent autonomy without asking a model to approve every action. Two structural ideas are transferable.

FIRST, tier by reversibility so most actions never reach a classifier at all. Tier 1 is a fixed allowlist of state-free tools (file reads, text and file-pattern search, code navigation). Tier 2 is file writes and edits INSIDE the project directory, which bypass the classifier on the explicit reasoning that in-project edits are already reviewable through version control and shouldn't pay classifier latency. Tier 3 — shell commands, web fetches, external tools, subagent spawns, filesystem writes outside the project — is everything else, and only that reaches the classifier. The general rule: if an action is cheaply reversible by an existing mechanism, the existing mechanism IS the control, and re-checking it is pure latency.

Note what entering auto mode REMOVES rather than adds: blanket shell access, wildcarded script interpreters (python, node, ruby and similar), and package-manager run commands are stripped from any pre-existing allowlist. Those are the wildcards through which a user-configured permission becomes arbitrary code execution, so more autonomy means a narrower standing allowlist, not a wider one.

SECOND, stage the classifier. Stage 1 is a single-token filter with no reasoning, deliberately tuned to over-block, at an 8.5% false-positive rate. Stage 2 runs chain-of-thought only on what Stage 1 flagged, cutting false positives to 0.4% but at 17% false negatives on genuinely overeager actions. Cheap-and-paranoid in front, expensive-and-accurate behind, so reasoning cost is paid only on the ambiguous minority.

Those numbers are the honest part: a shipped permission classifier still misses roughly one in six overeager actions. Anthropic characterises the dominant miss as the classifier correctly identifying the danger but misjudging CONSENT — "A similar action was approved earlier, but one approval isn't a pattern." Design accordingly: prior approval of a similar action is the failure mode, so do not build consent inference on top of single approvals.

The classifier's trust boundary is explicit and narrow — by default the only thing it trusts is the git repo currently being worked in, widened deliberately to named GitHub orgs, buckets, or internal APIs. Its 20+ default block rules group as: irreversible destruction (force-pushes, mass deletes), security degradation (disabling logs, installing persistence), cross-trust-boundary actions (running external code, credential harvesting), and bypassing shared-infrastructure safeguards. Allow-exceptions are narrow: installing packages already declared in the repo manifest, standard credential flows, pushing to the session's working branch.

*** SCOPE, ADDED 2026-08-27 FROM A SECOND SOURCE, AND IT CHANGES WHAT THIS ARCHITECTURE IS FOR. ***
Everything above describes a permission architecture, not a containment boundary, and Anthropic has now said so in its own words. Responding to a published multi-step exploit chain against Auto Mode ([[367b7933]]), Anthropic closed the report as "Informative" rather than as a vulnerability, on the stated ground that "Auto Mode is a convenience feature backed by a best-effort classifier, not a security guarantee" — positioning OS isolation and network controls as the actual security boundary.

That is consistent with, not a retraction of, the design above: a staged classifier tuned to a 0.4% false-positive rate at 17% false negatives is self-evidently not something you would put load on as a last line of defence, and this fact already recorded that number. What the operator's statement adds is the DECISION RULE the numbers only implied — the classifier's job is to keep an agent from doing careless things, and an adversary who can chain individually-innocuous steps is out of its scope by design. If your threat model includes an attacker, the classifier is not the control; the sandbox is. Do not read the tiering and staging above as a substitute for isolation, and do not treat a Tier-2 bypass (in-project writes) as safe when the project directory itself can be attacker-populated.
