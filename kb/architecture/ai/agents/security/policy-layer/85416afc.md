# Contextual integrity reframes agent permissions as the appropriateness of a flow, so the policy is generated per request rather than granted in advance

A Google Research workshop report frames agent privacy and security through Contextual Integrity, which specifies an information flow by three components — the actors, the information types, and the transmission principles — and calls a flow private when it is appropriate to its context. The report extends the same structure to actions, naming "contextual security, that is the appropriateness of agent actions".

WHY THE REFRAMING HAS TEETH, and it is the part a competent default would miss: if appropriateness is a property of the flow's context rather than of the capability, then a static grant cannot express it. The same tool call on the same data is appropriate or not depending on who the actors are and what was promised about the transmission. The report's architectural answer follows from that: a contextual policy engine in a supervisor layer that evaluates proposed actions and data flows "before any information leaves the user's workspace", fed by "a dynamic policy generation loop that can operate in real time" rather than by policies experts author ahead of time — because the tools and contexts an agent discovers at runtime cannot be pre-enumerated.

It also takes a position against the obvious cheap control: per-action user confirmation is treated as insufficient for long tasks and sub-agent delegation, which weaken oversight while risking "confirmation fatigue". So the layer is proposed as a replacement for asking the user more often, not as a complement to it.

The other failure modes it names for agents are input ambiguity (natural-language and image inputs make expected behaviour hard to define and leave room for prompt injection), probabilistic control flow (generatively planned execution paths that conventional testing does not cover), and multi-agent collusion. Its evaluation proposal is standardised dynamic multi-agent benchmarks, including open-source "Agent Gym" sandboxes for simulating cascading interactions over extended periods.

EPISTEMIC STATUS, stated plainly because it decides how this should be used: this is a research agenda, not a validated design. The report comes from a workshop of "more than 50 academic and industry leaders from numerous institutions" and contains no measurements, no thresholds and no reported implementation. Nothing here has been shown to work, including the claim that runtime-generated policies can be made sound enough to gate actions. Treat it as a position to evaluate against the permission designs this pack already documents — tiering by action risk in kb/architecture/ai/agents/security/permission-systems/89df351e.md, and downstream re-authorization in kb/invariants/ai/agents/security/authorization/48c4e555.md — rather than as guidance to implement.
