# Non-human identity answers "may this credential connect"; agent identity has to answer "should this reasoner be doing this, right now"

OWASP argues that the industry conflates two distinct layers to its own cost, and that the conflation is why most identity programmes are not agent-ready.

- **Non-Human Identity (NHI)** is the *authentication primitive*: the digital representation and authentication of non-human entities, traditionally static service accounts, API keys, OAuth credentials and certificates. It answers one question, once, at authentication time — "is this entity allowed in?" — and the answer holds until someone rotates the credential.
- **Agent Identity** is the *governance framework* on top: a dynamic cryptographic framework attesting the provenance, intent and authority of entities that reason, plan and execute across trust boundaries.

"NHI tells you a credential is valid. It cannot tell you whether the reasoning entity holding it should be taking the action it is taking right now." The shift is from **verifying the holder at session start to governing the behaviour at the moment of each action** — because an agent reasons, delegates to other agents, and discovers new tools at runtime, so the question becomes "who delegated this agent, what is it trying to do right now, and is it still allowed to do it."

The seven dimensions OWASP contrasts — traditional NHI → agentic identity: nature (static credential → dynamic cryptographic identity); scope (predefined, coarse-grained → intent-based, dynamically discovered, fine-grained); lifespan (long-lived → ephemeral / just-in-time); delegation (basic OAuth scopes → delegation chains with context preservation); auditability (token-based → structured, intent-bound claims); trust model (infrastructure trust → cryptographic attestation plus provenance); risk (over-privileged accounts → trust transitivity and dynamic misuse).

A framework must dynamically enforce three cryptographic assertions: **Provenance** (the agent's integrity), **Attestation** (its identity), and **Intent**.

**The concrete implementation trap:** OAuth 2.0 machine-to-machine patterns such as the client-credentials flow use static scopes in reusable tokens, which blocks the real-time revocation agents need. Opaque access tokens fail here for three stated reasons — they are size-limited, static once issued, and lack per-decision authorization visibility — which degrades both fine-grained policy evaluation and post-incident forensics. If your plan is "give the agent a service account and scope it tightly", you have built the NHI layer and none of the agent-identity layer.

**Scale of the existing gap** (Entro Security, 2025 State of NHI): non-human identities outnumber human users roughly 100:1 in most enterprises and up to 500:1 in some; 97% of NHIs carry excessive privileges; 0.01% of machine identities control 80% of cloud resources; 71% are not rotated within recommended timeframes. Vendor-published figures, so treat the exact percentages as indicative — the order of magnitude is the actionable part.
