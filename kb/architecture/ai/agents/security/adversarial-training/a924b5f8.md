# Give the automated attacker a simulator of its victim and it iterates before it commits — OpenAI's injection attacker reads a counterfactual rollout of the defender's reasoning and action trace

OpenAI's prompt-injection red team against its browser agent is an LLM attacker trained end to end with reinforcement learning, and the component that makes it efficient is not the training — it is a separate simulator in the loop.

The mechanism: the attacker sends a candidate injection to an external simulator, which runs a counterfactual rollout of the victim agent and returns that agent's REASONING and action trace. The attacker iterates against that feedback before committing to an attack — the post's phrasing is that it tries before it ships. The attacker is also given privileged access to the defender's reasoning traces, which are not disclosed to external users.

Two design consequences for anyone building this. First, the expensive part of automated red teaming is usually the live attempt against a real deployment; a simulator that returns the victim's internal trace converts that into a cheap inner loop, and the attacker's search signal becomes the defender's reasoning rather than only the binary outcome. Second, the privilege asymmetry is deliberate and it is what makes this attacker stronger than an external one — which means a robustness number produced this way is not a number an external attacker would reproduce, in either direction.

The stated reason for reinforcement learning rather than prompted attack generation: long-horizon objectives with sparse, delayed rewards, scaling with frontier model capability, and scaling test-time compute. The reported capability is that the attacker can steer agents through workflows spanning "tens (or even hundreds) of steps", with the worked example an injected email that causes the agent to send a resignation letter to the user's CEO. Discovered attacks feed a rapid-response loop into adversarial training, prioritising cases where current agents fail, and also into monitoring, the safety instructions placed in the model's context, and system-level safeguards — not only into weights.

What is NOT established, and matters before citing this. The post reports NO attack success rates, no before/after figures and no benchmark numbers, so there is no measured evidence here that the simulator loop or the adversarially trained checkpoint reduced successful injections. It also names no defence approach that failed. The source's own position is that "prompt injection remains an open challenge for agent security" and is "unlikely to ever be fully 'solved'", and that narrowly scoping an agent's instructions "does not eliminate risk".
