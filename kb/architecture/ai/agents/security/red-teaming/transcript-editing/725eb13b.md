# Editing a recorded transcript instead of re-running the environment makes attack generation cheap and leaves "would it have worked" unverified

Screwtape generates monitor-evading attacks by EDITING transcripts that real agents already produced, rather than by driving an agent in a live environment. The shape, and what each part is for:

- Inputs are a real transcript, the monitor, and a threat contract naming the threat vector and the severity required for acceptance.
- The attacker agent returns an edited transcript plus a written description of the attack it inserted.
- Some edits are refused mechanically rather than judged: "the attacker can’t change user messages or edit subagent calls", which keeps the attack attributable to the agent under test instead of to its principal or its subagents.
- The verifier is given the edited transcript, the attack description, and "the diff between the source and edited transcripts" — the diff is what lets it judge the insertion rather than the scenario.
- The monitor in the loop may be the target monitor or a proxy standing in for it.

The cost of working offline is that success is never executed, only judged: "the pipeline lacks access to the original environment", and "The verifier sometimes accepts invalid attacks." A second scope limit comes from the same choice — "Currently, Screwtape can only generate attack transcripts without reasoning traces", so this construction cannot test a monitor that reads chain-of-thought.

Operational consequence: use transcript editing to enumerate candidate attacks against an action-only monitor at low cost, and treat every surviving candidate as unconfirmed until it is replayed in a real environment or reviewed by a human. Do not use it to score a reasoning-reading monitor at all.
