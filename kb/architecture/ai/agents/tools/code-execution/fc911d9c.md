# Programmatic tool calling keeps intermediate tool results out of context by running model-authored code in a sandbox

OpenAI's programmatic tool calling inverts where the agent loop runs. Instead of the model emitting one tool call, seeing the result, and deciding again, the model writes JavaScript that orchestrates many tool calls — with real loops, conditionals and intermediate processing — and that program executes in a hosted V8 runtime. Only the program's final output enters the conversation; intermediate tool results never reach the model's context at all.

That is the whole point, and it names the condition where it wins: a task that needs a SEQUENCE of related tool calls, or that must reduce a large tool output before anything useful can be said about it. Fetching 500 rows to compute one aggregate is the canonical case — direct calling pays for all 500 rows in context and again on every subsequent turn; the program pays for the aggregate.

Where it loses is equally explicit, and the docs say direct calling remains the recommended baseline: single lookups, and adaptive search where the model genuinely needs to re-evaluate after each result. If the control flow cannot be written down in advance, writing it as code just produces a program that guesses.

The constraints are sharp and worth knowing before you design around it. The runtime is fresh and isolated per program — no Node.js, no package installation, no network, no filesystem, no console, and no persistence between programs. Client-owned functions still execute in YOUR application, so their results must be fed back to the running program explicitly rather than simply returned. MCP tools carrying a `require_approval` policy pause the program mid-execution pending authorization, so an approval gate you added for safety becomes a latency cliff inside a loop. Tools must opt in via `allowed_callers: ["programmatic"]`, and deferred tools are invisible to a program — the model has to load them first. With `store: false` you must replay every output item, including program and reasoning items.

The honest caveat the docs include: the token saving depends on the task, and is not guaranteed.
