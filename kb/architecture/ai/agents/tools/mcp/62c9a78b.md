# Code execution over MCP: load tool definitions on demand instead of all upfront

Connecting an agent to many MCP servers front-loads every tool definition into the context before the request is even read — at thousands of tools that is hundreds of thousands of tokens — and then re-pays for every intermediate result as data passes through the model between tool calls.

The alternative Anthropic describes: present MCP servers to the model as code on a filesystem (e.g. ./servers/google-drive/getDocument.ts) and let it write code that imports what it needs. Models navigate filesystems well, so tool discovery becomes progressive disclosure — read the definitions relevant to this task, ignore the rest. They report one case going from 150,000 tokens to 2,000, a 98.7% reduction.

The second, less obvious win is that filtering and transformation happen in the execution environment, so intermediate results never enter the model's context by default. That is a privacy control as much as a cost control: PII can be tokenized so real email addresses and phone numbers flow from one system to another without ever passing through the model.

The trade is that you now need a sandbox with real isolation, and the model is writing code rather than emitting structured tool calls — more expressive, and correspondingly harder to constrain. This is worth it at many-tool scale and probably not at five tools.
