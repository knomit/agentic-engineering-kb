# MCP 2025-11-25 adds experimental tasks: poll for deferred results instead of holding a request open

Revision 2025-11-25 adds experimental support for **tasks** (SEP-1686): a way to track durable requests with polling and deferred result retrieval, rather than keeping a single request-response open for the lifetime of a long operation.

This matters for a specific and common agent problem. A tool that takes minutes — a build, a deep crawl, a long query — forces a choice between blocking the connection (fragile: any disconnect loses the work, and timeouts are set by whatever proxy is in the middle) or inventing your own job-handle convention (every server does it differently, so the model has to learn each one). Tasks make the deferred-result pattern part of the protocol.

Two caveats to hold together before building on it: it is marked **experimental**, so the shape may change in a later revision; and it is only present from 2025-11-25 onward, so a client negotiating an earlier revision will not have it. Detect via capability negotiation rather than assuming.

Related transport change in the same revision: SEP-1699 allows servers to disconnect SSE streams at will and have clients poll, with resumption always via GET regardless of stream origin and event IDs encoding stream identity. The design intent across both is the same — stop treating a held-open connection as the unit of durability, because it is not one.
