# In a ten-day advisory workflow the traffic reverses — "agents prompt people more than people prompt agents" — so the load-bearing component is the memory that survives handoffs, not the prompt

Arca runs agents on financial-advisory work where, per its CTO, "agent tasks at Arca can take up to ten days." The work's shape is the reason: "It's very stop-start, there's many actors in between, many decision points, many handoffs," he said. In that setting the usual request–response picture inverts — "agents prompt people more than people prompt agents" — because the agent is mostly waiting on, and soliciting, decisions from humans.

WHAT THAT CHANGES ARCHITECTURALLY. If the agent is the thing that keeps asking, then nothing can live in a conversation: the state has to outlive every gap, every actor and every handoff. Arca's answer is a per-client memory system that the agents themselves write to, tracking what has happened, what is next, and who owns each action.

THE AUTHORITY BOUNDARY IS SEPARATE FROM THE WORKFLOW. Agents are scoped to analysis and proposing solutions; "Trading and any other money movement is handled by a human advisor," and "there are guardrails in place to ensure that human advisors are making the final decisions." The enforcement is not model-mediated: "All of our safety restrictions are fully deterministic," he said.

WHAT IS NOT ESTABLISHED. The source names no mechanism for HOW an agent requests input — no trigger, interface or approval protocol — and gives no figures for completion rates, latency or error rates. It is a practitioner's account of a deployed system's shape, not a measured result, so treat the ten-day figure as the operator's stated task horizon rather than a benchmark.
