# The quarantine pattern makes the privilege boundary an agent boundary: unprivileged reader agents consume the untrusted content, a separate actor agent holds the tools that change things

Claude Code's dynamic-workflow guidance names a "quarantine" pattern for triaging untrusted material at scale: reader agents are spawned with no privileges and are the only agents that see the untrusted content; they emit summaries; a separate actor agent, which never reads the raw untrusted content, holds the high-privilege tools and acts only on those summaries. The pattern is recommended for triage work and paired with a recurring driver (`/loop`) when the queue is continuous.

What makes it structural rather than cosmetic is that BOTH halves of the split are load-bearing, and dropping either one dissolves the protection. The reader must actually lack the acting tools, not merely be told not to use them, because an in-context instruction to refrain does not bind later behaviour in the same session (see [[de4e90a4]]). And the actor must actually never be handed the raw content, because the whole value of the arrangement is that the injected text and the privileges are never resident in the same context window — which is the lethal trifecta's combination condition (see [[48c9de1b]]) decomposed across two agents instead of mitigated inside one.

Operational consequence: when you build this, the summary channel is the entire interface between the halves, so it is the thing to constrain — a schema'd return value rather than free prose gives the actor something it can validate.

WHAT THIS DOES NOT MEAN. It does not make the summary trustworthy. Pack analysis, grounded in this corpus rather than in the source: a reader's summary is itself model output derived from attacker-controlled text, and self-generated prompt injections surviving into a summary that a later agent then treats as instructions is a documented failure, not a hypothetical (see [[fa05de12]]). The pattern narrows the attack surface from "any text the attacker writes" to "what the attacker can get a summariser to emit"; it does not close it. Treat the actor as processing untrusted-derived input, with its own authorization checks at the point of action.
