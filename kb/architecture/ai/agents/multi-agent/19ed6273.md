# Anthropic's multi-agent research system: +90.2% on research eval at ~15x the tokens

Anthropic's orchestrator-worker research system (Claude Opus 4 lead agent spawning Claude Sonnet 4 subagents) beat single-agent Opus 4 by 90.2% on their internal research eval. The price is token volume: agents use roughly 4x the tokens of a chat interaction, and multi-agent systems roughly 15x. On BrowseComp, token usage alone explained about 80% of performance variance, with tool-call count and model choice accounting for another ~15% — which is the real reason the architecture wins. It buys a way to spend more tokens in parallel across separate context windows, not smarter reasoning.

Corollary the numbers force: upgrading the model beat doubling the token budget on the older model. Reach for multi-agent only after model choice is already maxed.

Stated boundary: worth it when task value justifies ~15x cost, subtasks parallelize, and the information exceeds one context window. Explicitly unsuitable when subtasks need shared context or have heavy interdependencies — they name most coding tasks as falling on the wrong side of that line.

STALENESS (checked 2026-07-26): the measurement is anchored to Claude Opus 4 and Claude Sonnet 4, both several generations superseded (Opus 5 and Sonnet 5 are current). Treat the +90.2% as a point-in-time result against a two-generation-old single-agent baseline, not as the current gap — the single-agent baseline has moved the most, so the honest expectation is that the margin has narrowed. What does NOT depend on the model generation is the causal finding that token volume explains most of the variance, and the boundary conditions.

One thing has changed materially since publication and cuts against naive application: current Claude models orchestrate subagents natively and over-delegate without being asked, spawning them for work a single tool call would answer. So the deliberate architectural choice this post describes is no longer the only way subagents enter your system, and the first tuning problem is now damping delegation rather than enabling it.
