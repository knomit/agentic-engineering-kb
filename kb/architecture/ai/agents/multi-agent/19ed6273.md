# Anthropic's multi-agent research system: +90.2% on research eval at ~15x the tokens

Anthropic's orchestrator-worker research system (Claude Opus 4 lead agent spawning Claude Sonnet 4 subagents) beat single-agent Opus 4 by 90.2% on their internal research eval. The price is token volume: agents use roughly 4x the tokens of a chat interaction, and multi-agent systems roughly 15x — note both multiples are stated against CHAT, not against each other. On BrowseComp, "token usage by itself explains 80% of the variance, with the number of tool calls and the model choice as the two other explanatory factors" — which is the real reason the architecture wins. It buys a way to spend more tokens in parallel across separate context windows, not smarter reasoning.

Corollary the numbers force: "upgrading to Claude Sonnet 4 is a larger performance gain than doubling the token budget on Claude Sonnet 3.7". Reach for multi-agent only after model choice is already maxed. (That comparison is anchored to those two specific models; the ordering is what transfers, not the margin.)

Stated boundary: worth it for "valuable tasks that involve heavy parallelization, information that exceeds single context windows, and interfacing with numerous complex tools". Explicitly unsuitable for domains requiring "all agents to share the same context or involve many dependencies between agents". They name coding as falling on the wrong side, for TWO reasons that are worth separating because only one is about the task: "most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time". The first is a property of coding work; the second was a property of 2025 models and is the half most likely to have moved.

STALENESS (checked 2026-07-26, re-verified 2026-08-17): source is live, published 2025-06-13, carries no update notice. The measurement is anchored to Claude Opus 4 and Claude Sonnet 4, both several generations superseded (Opus 5 and Sonnet 5 are current). Treat the +90.2% as a point-in-time result against a two-generation-old single-agent baseline, not as the current gap — the single-agent baseline has moved the most, so the honest expectation is that the margin has narrowed. What does NOT depend on the model generation is the causal finding that token volume explains most of the variance, and the boundary conditions.

One thing has changed materially since publication and cuts against naive application: current Claude models orchestrate subagents natively and over-delegate without being asked, spawning them for work a single tool call would answer. So the deliberate architectural choice this post describes is no longer the only way subagents enter your system, and the first tuning problem is now damping delegation rather than enabling it. (This paragraph and the split of the coding rationale above are this pack's analysis, not the source's.)
