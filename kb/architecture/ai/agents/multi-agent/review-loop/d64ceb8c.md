# The reviewer agent must have clean context, not a shared briefing with the coder

A generator agent paired with a separate evaluator agent is the most consistently reported working multi-agent pattern, and two independent vendors report it working — but they report DIFFERENT things about it, and the design constraint below comes from only one of them. Cognition reports that "Devin Review catches an average of 2 bugs per PR, of which roughly 58% are severe". Anthropic reports the reason the second agent is needed at all: "agents reliably skew positive when grading their own work", and, scoped to one axis rather than to output in general, that "on design and originality, Claude often produced outputs that were bland at best".

The non-obvious design constraint is that the evaluator must start from COMPLETELY CLEAN context — no shared briefing, no handoff of the generator's trace. **ATTRIBUTE THIS TO COGNITION, NOT TO BOTH VENDORS:** it is Cognition that states it and gives the reason — "Perhaps more importantly though, having a clean context makes the agent smarter because of the math of attention", the mechanism being "models making less intelligent decisions at longer and longer context lengths" — and Cognition that prescribes the consequence, that the reviewer should "only look at the diff, and re-discover any context it needs as it reads the code from scratch". The Anthropic post does not state a clean-context rule for its evaluator at all, so this constraint rests on one source. It is the opposite of the instinct to "give the reviewer everything so it understands the intent," and also the opposite of Cognition's own general advice to share full traces between agents, which is what makes it worth writing down.

This is the specific case where context isolation beats context sharing, and it works because review is read-only — the evaluator contributes intelligence, never writes.

Give the evaluator real tools rather than only the artifact. Anthropic's evaluator "used the Playwright MCP to click through the running application the way a user would", going on to test UI features, API endpoints and database states before grading, and caught defects a diff read would not surface. An evaluator restricted to reading the diff can only find what is visible in the diff. Note that this sits in tension with the clean-context rule above and the tension is real: Cognition's reviewer is deliberately diff-only, Anthropic's drives the live application. The reconcilable reading is that what must stay clean is the generator's CONVERSATION, not the evaluator's tool access — fresh context plus its own tools, rather than inherited context.

The cost is on the return path: the generator must filter evaluator feedback against the original user intent before acting on it. Cognition frames this as the open question its own product has to answer — whether "Devin properly use[s] its broader context of user instructions, decisions, etc. to filter the bugs" the reviewer returns. Without that filter the loop degrades into looping, scope creep, and the generator following the evaluator into work the user never asked for. An unfiltered evaluator-to-generator channel is where this pattern fails, not the review itself.

Two things that bound when to use it. Price: Anthropic's table gives a solo run at 20 minutes and $9 against 6 hours and $200 for the full harness, and the prose states "The harness was over 20x more expensive, but the difference in output quality was immediately apparent." The figures are in a table rather than a sentence, so cite them as a table reading.

AND THE VALUE DECAYS AS MODELS IMPROVE, WHICH MAKES THE WHOLE PATTERN'S ROI A MOVING TARGET. The measurement is pinned to one model: "for tasks within that boundary, the evaluator became unnecessary overhead", stated of Opus 4.6, with the harness cost-justified only at the edge of that model's native capability. That measurement has not been repeated on any of the models released since, so what carries forward is the SHAPE, not the verdict: as a model's native capability grows, the band of tasks where an evaluator pays shrinks and moves outward. Re-benchmark whether the evaluator still earns its place on each model upgrade rather than treating the harness as permanent, and do not read the Opus 4.6 result as a claim about any later model — in either direction.
