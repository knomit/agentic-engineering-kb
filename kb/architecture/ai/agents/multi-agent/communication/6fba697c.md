# Dynamic-workflow sub-agents coordinate through a shared filesystem and the lead agent — the API exposes no sub-agent-to-sub-agent message path

Two reported clauses fix the communication topology of Anthropic's dynamic workflows: "the agents share a filesystem and can use it to exchange information", and "developers cannot directly instruct one workflow subagent to message another through the API". Coordination therefore has exactly two routes — through the lead agent, which passes a payload to each sub-agent at a phase transition, and through the shared filesystem.

THE OPERATIONAL CONSEQUENCE: in this shape the filesystem is not incidental scratch space, it IS the inter-agent channel. That makes it a trust boundary and an observability surface, and both follow from the same fact. Anything one sub-agent writes there is readable by its peers, and a file a peer wrote enters another sub-agent's context as content that sub-agent did not author and whose provenance the filesystem does not record. Design it as a channel: name who may write what, and keep the writer's identity attached to the content rather than leaving it implicit in a path.

WHAT THIS DOES NOT MEAN: the absence of a peer-to-peer message API is not an absence of peer-to-peer influence. The filesystem supplies it, which is the point of the paragraph above.

The observability affordance for the lead-agent route is specific and does not extend to the other one: the Console lets a developer inspect the payload the lead agent passed to each sub-agent at every transition. No equivalent per-write view of the shared filesystem is reported.

PACK ANALYSIS: a writable shared filesystem between collaborating agents is the same substrate as the one in kb/architecture/ai/agents/multi-agent/collaboration-substrate/44ab25b6.md, where it was the first rung of a published five-rung escalation that ended in egress to a public host. There, the shared store was an unintended channel; here it is the designed one. The mechanism is identical either way, so the controls that case argues for are the ones this design needs by default rather than after an incident.

SOURCE MODALITY: a third-party write-up of a talk by two Anthropic Members of Technical Staff at AI Engineer New York 2026. No measurements, and no security analysis of the filesystem channel is offered by the source — the trust-boundary reading above is this pack's, not the source's.
