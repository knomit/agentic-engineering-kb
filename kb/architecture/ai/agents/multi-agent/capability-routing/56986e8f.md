# Model-pairing works as capability routing, not difficulty escalation — and the gap between the two models must be small

The 'smart friend' pattern gives a primary model the ability to consult a second, more expensive model as a specialist — Cognition's framing: 'Let the primary/smaller model decide when a situation was tricky enough to be worth consulting the smarter/expensive model.'

They report a specific negative result that constrains when it works. Using their own SWE-1.5 as primary with Sonnet 4.5 as consultant FAILED: 'SWE 1.5 was not good enough at being the primary model for this setup to really work. The gap between it and Sonnet 4.5 was too wide.' The mechanism, in their words, is the load-bearing part: 'The cost and speed wins were real, but the quality ceiling was set by the primary, and the primary wasn't strong enough.'

That is the insight to carry. In an asymmetric pairing the PRIMARY sets the quality ceiling, not the consultant — because the primary is the one that must recognise its own limits, decide to escalate, formulate a useful question, and then act on the answer. All of those are frontier-model capabilities. So a large capability gap DEFEATS the pattern rather than justifying it, which inverts the naive cost argument that you should put the cheapest adequate model in front. Buying a smarter consultant does not raise a ceiling the primary sets.

What did work was cross-frontier pairing where neither model is clearly weaker: 'We've run Claude and GPT together in this setup in production for a meaningful stretch, and it produced real gains.' That reframes the pattern from difficulty escalation to CAPABILITY ROUTING — some models debug better, some handle visual reasoning better, some write tests better. Route on which model is better at this KIND of work, not on how hard the work is.

Two implementation details Cognition names: share a fork of the primary's full context with the consultant rather than a summary (they call this 'a reasonable 80/20 solution'), and encourage the primary to ask BROAD questions — 'what should I do?' — letting the consultant decide what is interesting and guide the primary back to the answer, rather than returning a finished result. The primary has to stay the one that acts.

Open and unsolved as of April 2026: reliably training a weaker model to know when to escalate. Do not design an asymmetric pairing that depends on this.
