# Model-pairing works as capability routing, not difficulty escalation — and the gap between the two models must be small

The "smart friend" pattern gives a primary model the ability to consult a second, more expensive model as a specialist. Cognition reports a specific negative result that constrains when it works: using their own SWE-1.5 as the primary with Sonnet 4.5 as the consultant FAILED, because "the gap between it and Sonnet 4.5 was too wide in exactly the places that mattered for this setup: knowing when to escalate, knowing what to ask."

That is the load-bearing insight. Delegation requires the delegating model to recognise its own limits and formulate a useful question — both of which are frontier-model capabilities. So a large capability gap defeats the pattern rather than justifying it, which inverts the naive cost argument that you should put the cheapest adequate model in front.

What did work was cross-frontier pairing (Claude with GPT) where neither model is clearly weaker. That reframes the pattern from difficulty escalation to CAPABILITY ROUTING: "Some models debug better, some handle visual reasoning better, some write tests better." Route on which model is better at this kind of work, not on how hard the work is.

Two implementation details Cognition names: share a fork of the primary's full context with the consultant rather than a summary, and have the consultant ask broad questions that guide the primary back to the answer rather than returning a finished result — the primary has to stay the one that acts.

Open and unsolved as of April 2026: reliably training a weaker model to know when to escalate. Do not design an asymmetric pairing that depends on this.
