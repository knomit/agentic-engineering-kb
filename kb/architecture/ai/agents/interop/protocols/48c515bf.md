# AHP is a coordination layer over ACP's communication layer — one host, N clients, many backends — and an AHP host can bridge to any ACP agent, but VS Code's own host does not ship that bridge

Two protocols with similar names sit at different layers.

Agent Client Protocol (ACP, originated by Zed) defines how ONE client talks to ONE coding agent: initialization, authentication, prompts, streaming updates, tool calls and permission requests, as JSON-RPC over stdio. Agents that speak it include Gemini CLI (`--experimental-acp` / `--acp`), `codex-acp`, `copilot --acp`, OpenCode, Qwen Code, Kiro, OpenClaw and Hermes; the VS Code ACP Client extension lists them. Antigravity CLI (which replaced Gemini CLI on 2026-06-18) had NO ACP mode as of 2026-09-25; an open feature request asks for one.

Agent Host Protocol (AHP, Microsoft) defines how N clients share one live session: the host manages authoritative state, sequences every mutation, and synchronizes the result to every connected client. The AHP guide's own words: 'AHP is a coordination layer. ACP is a communication layer. They compose naturally.' The composition is a bridge: the host speaks AHP upstream to clients and ACP downstream to the agent, mapping ACP events onto AHP actions.

Where that bridge exists (2026-09-25): in the third-party host `ahpd` (Node 22 / Bun / Deno, MIT, tracking AHP 0.9.0), whose `@ahpd/agent-acp` backend wraps any ACP server, alongside `@ahpd/agent-claude` (Claude Agent SDK) and an OpenAI-compatible backend, with `@ahpd/sdk` for custom backends (an `Agent` needs `provider`, `displayName`, `schema`, `defaults`, `create`). It does NOT exist in VS Code's Agent Host, which ships only first-party adapters and documents no way to register a custom harness.

Consequence: the portable, vendor-neutral part of this stack is the PROTOCOL, not Microsoft's host. Non-Microsoft harnesses (Gemini, OpenCode, Hermes, OpenClaw) reach an AHP control plane only through an ACP-capable host such as ahpd; VS Code's Agents window can attach to such a host via `chat.remoteAgentHosts`.

WHAT THIS DOES NOT MEAN: that AHP replaces MCP. MCP is the tool/resource layer between an agent and its servers; AHP has an MCP channel only to let a client proxy traffic to servers the host already runs (see the MCP-injection gotcha). The MCP-vs-A2A layering fact is the sibling distinction on the agent-to-agent side.
