# Agent discovery registries are trust infrastructure, and the first documented A2A attack was simply lying in a directory entry

Discovery protocols let agents locate tools and peers dynamically from *advertised* capabilities. That makes the registry a trust concentration point, and the selection decision is being made by a model reading self-asserted metadata.

**The documented failure (April 2025, Trustwave):** a malicious agent published a fake agent card in an open A2A directory, falsely claiming high trust. The LLM judge agent selected it, letting the rogue agent intercept sensitive data and leak it to unauthorized parties. OWASP maps it to five of the ten agentic risk categories (ASI03, ASI06, ASI07, ASI08, ASI10). No exploit was needed — the attack was an assertion in a metadata field that the selection logic had no way to verify.

Observed risks at this layer: capability misrepresentation, registry poisoning, Sybil agent creation, traffic redirection. OWASP's requirement is that discovery systems "require controls comparable to domain name systems and public key infrastructure, including cryptographic identity anchoring, integrity monitoring, and reliable revocation mechanisms." Agent Name Service (ANS) is the DNS-inspired, PKI-backed answer and integrates across MCP, A2A and ACP — but it is rated *low adoption*, so today the control usually does not exist and you supply it yourself.

**Adoption ratings worth knowing before betting an architecture on one** (OWASP, mid-2026): MCP — high adoption; A2A and ACP — low; NANDA and ANS — low. The report's own assessment is that protocol governance "has not kept pace with adoption" and that open-foundation governance "has not yet translated into consistently secure implementations."

**Cross-cutting structural weaknesses recurring across all protocol categories:** identity dilution through composite and transitive trust; excessive capability exposure; fragmented audit trails across vendors; weak containment and revocation mechanisms; limited visibility into autonomous delegation. These are architectural and governance problems rather than implementation bugs, and are compounded by fragmented shared-responsibility models between vendors and deploying organisations — meaning nobody owns the gap by default.

The practical rule: treat any capability advertised by a peer or registry as a claim, not a credential. Bind selection to cryptographic identity you can verify and revoke, or keep the candidate set closed rather than discovered.
