# Put the agent where people already work, but give it its own thread to work in — a shared channel is where adoption spreads and also where the agent's output pollutes the human conversation

A team running internal agents names the deployment surface as the first of five components: the agent "lives where people already work (for us that's Slack)", reachable by direct message or by being tagged in a channel.

THE CHANNEL IS WHERE ADOPTION COMES FROM, and that is the stated reason to accept the cost of being there: working in channels lets others "see how people use it." An agent only reachable in private has no demonstration path — nobody learns what to ask it by watching someone else ask.

THE CHANNEL IS ALSO WHERE THE AGENT IS A NUISANCE, because an agent's working output is long and iterative while a channel's content is shared and scarce. Running in the main thread "would pollute the human conversation and distract." Their answer is a "breakout" feature: the agent opens a thread of its own and does its work there, so the invocation stays visible in the channel while the transcript does not. That split — visible entry point, relocated body of work — is the transferable part, and it generalises to any shared surface where an agent's verbosity competes with human discussion.

AND THE BOUNDARY CONDITION IS STATED, which is what makes this more than a platform preference: some experiences are "best NOT done in Slack", with tracking a large email backlog given as the example, and the team built a custom UI for those. A chat surface is good at a request and an answer; it is bad at a persistent list whose state the user needs to see, scan and revisit. When the interaction's natural shape is a view over standing state rather than a conversation, the chat surface stops paying and a purpose-built interface starts.

The operational consequence when choosing where an agent lives: ask whether the value is in being discovered by colleagues (go to the shared channel, and build the breakout), whether the authority involved is personal (direct messages only — the same source restricts its email tools to DMs), or whether the user needs a durable view of accumulating state (build the interface).
