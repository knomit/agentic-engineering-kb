# Coding agents degrade past roughly 400K LOC, and it is a retrieval-infrastructure problem rather than a model-capability one

Sourcegraph scored 1,281 agent runs across 40+ large open-source repositories in 9 languages (their CodeScaleBench benchmark) and reports a size threshold: agents with only local tools (grep, file read, glob) begin to struggle systematically once a codebase exceeds roughly 400,000 lines. Below that, local file reading and grep are adequate; above it, the agent navigates file references without converging.

THE MOST ACTIONABLE NUMBER IS THE NEGATIVE ONE. The reward delta from adding code-intelligence tools is:
  under 400K LOC:   −0.080  — adding them makes the agent WORSE
  400K–2M LOC:      +0.259  — strongest positive effect
So this is a genuine threshold with a cost on the wrong side of it, not a monotonic 'more retrieval is better' curve. Giving a small-repo agent an indexed search stack spends context and tool-selection budget on a problem it does not have. Do not adopt this infrastructure by default; adopt it at scale.

The headline measurement is a Kubernetes task where the baseline agent spent 6,000 seconds (over an hour and a half) and produced ZERO output, while the indexed run finished in 89 seconds scoring 0.90 — 'Same model. Same task. Different context infrastructure.' Cross-file refactoring on a finance library went from touching 2 of 7 affected files (0.32) to all 7 (0.80). The multi-repository retrieval delta was +0.209 F1 versus +0.085 for single-repo, so the benefit scales with how scattered the relevant code is.

The actionable claim: if your agent is failing on a LARGE codebase, the first thing to change is the retrieval layer (indexed search, go-to-definition, find-references, type hierarchies), not the model or the prompt. Structural navigation beats lexical search because the compiler already knows which hit is the definition and which are call sites or tests — their example is grep for 'allocate' in Kubernetes returning 47 unranked matches versus 1 definition plus 12 ranked call sites.

Weigh the source's incentive: Sourcegraph sells code search, and the benchmark is their own. The relative ordering and the order-of-magnitude latency gap are hard to explain away; treat the exact reward deltas as vendor-reported. The 400K figure is a reported inflection point from one benchmark, not a validated constant — use it as the scale at which to start investing in retrieval, not as a cliff.

STALENESS PASS 2026-07-28: source live, and every figure above was re-verified verbatim against it (400K threshold, 6,000s/89s, −0.080 and +0.259, 0.32→0.80, +0.209 vs +0.085, 47 matches vs 1 definition + 12 call sites).
