# Agent fleets inverted source control's client assumption: 2,500 merges a day became over 30,000 in four months, and git's distributed-offline-client model became the thing working against them

Anthropic replaced git for its monorepo with an in-house system, Scion, and the stated reason is a change in WHO the clients are rather than how big the repository is. Git's design assumes distributed clients that are offline and each hold a full copy; at Anthropic "nearly all of our clients were agents and jobs that are online by definition", so the full-clone primitive was paying for an assumption that no longer held.

The load, in the post's own figures: "In May 2026, Anthropic averaged around 2,500 code changes merged per day" and "as of September, we merged over 30,000 per day." Separately, "We perform on the order of 25 million code checkouts per day for CI".

The design that replaced it follows from the client population: the server holds authoritative state and clients fetch on demand, the server does history, blame, commits, merges and rebases while the client keeps a bounded cache, every source-control query is exposed as an API so a job needs no local repository at all, and the working copy is optional and sparse or virtualised.

Operational consequence: when agents and CI jobs dominate your client mix, re-derive the primitives rather than tuning the human-era ones. Mirrors, shallow and sparse clones and periodic snapshots were tried first and were explicitly reported as insufficient — snapshots drifted from the tip of main and mirrors got harder to operate as the merge rate rose.

What this does NOT mean: it is not an argument that git is obsolete, and the authors say so directly — systems like this "really only make sense for truly enormous monorepos". They are not offering Scion publicly and their suggestion to the rest of the world is that git platforms adopt the server-side ideas (richer server RPCs, a revised negotiation protocol) while keeping the git model. Read the figures as the threshold where the inversion bit for one organisation, not as a threshold for yours.
