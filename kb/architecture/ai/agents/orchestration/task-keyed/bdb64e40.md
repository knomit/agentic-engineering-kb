# Symphony keys orchestration on tracker issues rather than on sessions or PRs, because the binding constraint was human attention: three to five concurrent Codex sessions before context switching became painful

The constraint Symphony is built around is not model capability or cost. It is that an interactive coding agent consumes a person's attention: "In practice, most people could comfortably manage three to five sessions at a time before context switching became painful." Adding agents past that point does not add throughput, because the human is the serialising resource.

The design response is to change what orchestration is keyed on. Instead of coding sessions or pull requests — both of which exist only once a human has started something — the unit is a deliverable in the issue tracker, and the invariant is "For every open task, guarantee that an agent is running in its own workspace." The post's one-line summary of the operating model: "Every open task gets an agent, agents run continuously, and humans review the results." A human's interaction moves from driving sessions to writing and triaging tickets at one end and reviewing results at the other.

Shape, for anyone evaluating it: Symphony is a spec — "technically just a SPEC.md file" — with a reference implementation in Elixir, running agents through the Codex App Server's headless JSON-RPC-over-stdio mode ([[b4f5a2f4]]). Its named components are a Workflow Loader, Config Layer, Issue Tracker Client, Orchestrator, Workspace Manager, Agent Runner, an optional Status Surface and Logging; a workflow is a `WORKFLOW.md` with YAML front matter and a Markdown prompt body. This spec version supports exactly one tracker, Linear (`tracker.kind: linear`).

The reported outcome, and its scoping is the important half: "Among some teams at OpenAI, we saw the number of landed PRs increase by 500% in the first three weeks." That is self-reported, from an unspecified subset of teams, over three weeks, with landed PRs as the measure — a count that this very architecture is designed to raise and that says nothing about the value or durability of what landed. Also reported: "garnering over 15K GitHub stars(opens in a new window) as of April 23", the reference implementation written by Codex in Elixir in one shot, and the spec tested by having Codex implement it in TypeScript, Go, Rust, Java and Python.
