# Write-once transcripts make an incident investigable; model-to-artifact lineage is what makes it reversible, and a log of what the model did is not that lineage

OpenAI's guidance for frontier reinforcement-learning runs asks for two distinct records, and teams reliably build the first while missing the second.

The first is append-only capture: "Save agent transcripts immutably for a reasonable period of time (for example, in write-once storage accounts) for all RL training, evaluation, and internal deployment." Two purposes are stated — to "enable reliable incident investigation" and to "prevent inadvertent edits" — so write-once storage is being asked for as a durability and integrity control, not only as an anti-tamper one, and the named scope includes evaluation and internal deployment rather than training alone.

The second is lineage: "It should be easy to identify all downstream uses of a misaligned model in the training process (for example: data generation or grading) to enable undoing the effect of misaligned outputs if necessary." A model used as a grader or a data generator writes its outputs into artifacts that outlive the model, so discovering after the fact that it was misaligned is only actionable if you can enumerate what it touched. Transcripts answer "what did this model do"; they do not answer "which of our current datasets, graders and checkpoints contain something this model produced". Those are different indexes over the same history, and only the second supports a rollback.

Operational consequence: record, per artifact, which model produced or graded it, at the time the artifact is created. This cannot be reconstructed later from transcripts alone, because the link between a generation event and the dataset the generation ended up in is exactly what is not written down.

Scope: stated recommendations, described as in the process of being implemented; no implementation detail beyond the write-once storage example is given.
