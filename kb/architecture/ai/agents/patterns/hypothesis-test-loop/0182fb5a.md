# The reported zero-day research loop closes on a lab copy of the target — a self-curated knowledge base supplies the hypotheses and the lab build is the oracle that lets the loop iterate to success

Anthropic's threat intelligence report titled "Detecting and countering misuse of AI: September 2026" — the page prints no publication date of its own and gives its activity window as "between December 2025 and August 2026" — sets out, step by step, the "exploit foundry" loop it observed GTG-10007 running against network and security appliance firmware. Read as an architecture rather than as an attack, it is the clearest published description this pack holds of an agent loop that terminates on a real oracle.

THE LOOP, in the report's order. "The workflow started with loading firmware and binaries into a decompiler through a tool server"; the report names neither the decompiler nor the tool-server protocol. An assistant agent surveys the image and "walked decompilation and cross-reference chains (over thousands of decompile calls, with back-to-back decompile sequences dominating the call stream)". It then "formed vulnerability hypotheses against a knowledge base it curated over time and prior proof-of-concept lookups". Exploit code is written against those hypotheses and tested "against lab copies of the target product". The workflow "iterated over edits of the exploit code until success, at which point the chain landed in the operator's private exploit portfolio". The input side is stated as a chain: "Vendor firmware images were obtained and decrypted with a purpose-built skill, unpacked into root filesystems, and loaded into disassembler and audit sessions", and "Vulnerability patterns were hunted component-by-component with parallel agents instructed to require evidence and use project memory".

TWO COMPONENTS CARRY THE RESULT, AND NEITHER IS THE MODEL. First, the hypothesis source is a store the agent built and kept: a curated knowledge base plus prior proof-of-concept lookups, so each pass starts from what previous passes established rather than from the binary alone. Second, the loop has a genuine oracle — a lab copy of the real product, against which "it works" is decided by execution rather than by the agent's own judgement. A separate convention in this corpus states the single-agent version of the same principle — give a coding agent a check it can run, or you become the verification loop — and this is what that looks like when the check is a full instrumented replica of the target and the loop is allowed to run unattended against it. Contrast the recorded cases in which agents game a verifier the designer wrote: an oracle that IS the artifact under test cannot be gamed the same way, which is why this loop converges on working exploits rather than on plausible-looking ones. Compare also the continuous-analysis pattern in which a threat model is built once and every commit is evaluated against it — the same build-once-evaluate-many economics, with the durable artifact on the analysis side instead of the target side.

THE ONE FIGURE, WITH ITS FRAME AND ITS HEDGE: "One workflow iterating continuously on network appliances yielded more than a dozen possible zero day findings in a single month." The word is POSSIBLE, and it should not be upgraded — the report separately describes "sustained research against a major security product (of a class of software deployed specifically to detect intrusions)" "which produced multiple previously-unknown vulnerabilities that were validated by the actor in their own lab environment" — the quantifier there is "multiple", not a dozen, and the validation is the actor's own as reported by Anthropic, not an independent confirmation. The figure is one workflow over one month against one class of target, with no stated rate of false positives.

WHAT THIS DOES NOT ESTABLISH. The report gives no cost, no token or compute budget, no success rate per hypothesis, and no comparison against human researchers or against a non-agentic pipeline. It establishes that the shape was operated continuously and produced candidates, not how efficient it is.
