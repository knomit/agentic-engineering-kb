# The reported zero-day research loop closes on a lab copy of the target — a self-curated knowledge base supplies the hypotheses and the lab build is the oracle that lets the loop iterate to success

Anthropic's 2026-09-10 threat intelligence report sets out, step by step, the "exploit foundry" loop it observed GTG-10007 running against network and security appliance firmware. Read as an architecture rather than as an attack, it is the clearest published description this pack holds of an agent loop that terminates on a real oracle.

THE LOOP, in the report's order. Firmware and binaries are loaded into a decompiler through a tool server. An assistant agent surveys the image and "walked decompilation and cross-reference chains (over thousands of decompile calls, with back-to-back decompile sequences dominating the call stream)". It then "formed vulnerability hypotheses against a knowledge base it curated over time and prior proof-of-concept lookups". Exploit code is written against those hypotheses and tested "against lab copies of the target product". The workflow "iterated over edits of the exploit code until success, at which point the chain landed in the operator's private exploit portfolio". Firmware was "obtained and decrypted with a purpose-built skill", and "vulnerability patterns were hunted component-by-component with parallel agents instructed to require evidence and use project memory".

TWO COMPONENTS CARRY THE RESULT, AND NEITHER IS THE MODEL. First, the hypothesis source is a store the agent built and kept: a curated knowledge base plus prior proof-of-concept lookups, so each pass starts from what previous passes established rather than from the binary alone. Second, the loop has a genuine oracle — a lab copy of the real product, against which "it works" is decided by execution rather than by the agent's own judgement. [[519ec939]] states the single-agent version of this (give a coding agent a check it can run, or you become the verification loop); this is what it looks like when the check is a full instrumented replica of the target and the loop is allowed to run unattended against it. Contrast [[a5ade87d]], where agents game a verifier the designer wrote: an oracle that IS the artifact under test cannot be gamed the same way, which is why this loop converges on working exploits rather than on plausible-looking ones. Compare also [[30543305]], where a threat model is built once and every commit evaluated against it — the same build-once-evaluate-many economics, with the durable artifact on the analysis side instead of the target side.

THE ONE FIGURE, WITH ITS FRAME AND ITS HEDGE: "One workflow iterating continuously on network appliances yielded more than a dozen possible zero day findings in a single month." The word is POSSIBLE, and it should not be upgraded — the report separately says the findings against a major security product were "validated by the actor in their own lab environment", which is the actor's validation as reported by Anthropic, not an independent confirmation of a dozen zero-days. The figure is one workflow over one month against one class of target, with no stated rate of false positives.

WHAT THIS DOES NOT ESTABLISH. The report gives no cost, no token or compute budget, no success rate per hypothesis, and no comparison against human researchers or against a non-agentic pipeline. It establishes that the shape was operated continuously and produced candidates, not how efficient it is.
