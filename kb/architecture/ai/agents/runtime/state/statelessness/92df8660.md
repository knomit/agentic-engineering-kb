# Codex resends the whole conversation every turn instead of using previous_response_id, to stay stateless and support Zero Data Retention — and the quadratic wire cost is only tolerable because the prompt cache absorbs it

Codex does not pass `previous_response_id`. The stated reason is to "keep requests fully stateless and to support Zero Data Retention (ZDR) configurations": reasoning items are carried forward in the request as `encrypted_content`, and under ZDR "OpenAI persists a ZDR customer's decryption key, but not their data." Each new user message resends the full conversation history, so the prompt grows every turn and the loop is quadratic in transmitted JSON.

The post accepts that quadratic transfer on an explicit argument, not an oversight: sampling cost dominates network cost, so the lever is cache hit rate rather than payload size, and with cache hits "sampling the model is linear rather than quadratic".

The operational consequence for anyone copying this shape: statelessness is not free, it is paid for in cache dependence. A stateless resend loop whose prefix is being invalidated is paying the quadratic cost twice over, so prefix stability stops being an optimisation and becomes the thing that makes the architecture viable.
