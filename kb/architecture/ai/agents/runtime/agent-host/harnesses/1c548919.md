# Harness matrix for VS Code's Agent Host (2026-09-25): Copilot, Claude via the Claude Agent SDK, Codex experimental; the 'Local' harness stays in the extension host; no custom-harness registration

What VS Code's Agent Host can run, as documented on 2026-09-25 (VS Code 1.138 on the observing machine). Dated reference; re-check before relying on any row.

- Copilot: powered by the GitHub Copilot SDK, which manages its runtime as a child process of the host. Same GitHub auth as chat in VS Code. Documented limitation: Copilot sessions do not have access to every VS Code built-in or extension-provided tool.
- Claude: loads Anthropic's Claude Agent SDK IN-PROCESS. Its adapter maps sessions, tools, permissions and subagents into AHP 'while retaining features such as slash commands and hooks'. Enabled by default. Two auth paths: a GitHub Copilot subscription with Copilot-routed models, or Anthropic credentials (an API key or a Claude Code OAuth token) billed by Anthropic.
- Codex: experimental; requires the OpenAI Codex extension or an experimental Agent Host setting. Auth via Copilot subscription or ChatGPT subscription.
- 'Local': the pre-host harness. Runs in the editor window's extension host, NOT in the Agent Host, and is the one with full access to VS Code built-in tools, extension tools, MCP servers and VS Code-configured models.
- Cloud sessions (Claude/Codex cloud): use the tools, MCP servers and models configured by the cloud service; they cannot access VS Code built-in tools or local runtime context.

Not present: Gemini, Antigravity, Hermes, OpenClaw, or any mechanism to register a third-party harness with VS Code's host (no extension API is documented). Those only reach AHP through an ACP-bridging host such as ahpd.

Customization files (VS Code issue #332083, migration-readiness tracker): AGENTS.md, CLAUDE.md, GEMINI.md, .github/copilot-instructions.md and .github/agents/*.agent.md are the baseline across harnesses; `.mcp.json` / `.github/mcp.json` and `.github/skills` work natively in the Copilot CLI/SDK; `.vscode/mcp.json` needs conversion to `.mcp.json`; several `chat.*Locations` settings are not consumed by the Copilot CLI. The tracker's table is NOT split per harness, so whether the Claude adapter honours a workspace `.mcp.json` is unverified from documentation alone — test it before depending on it.

Consequence: choose the harness by tool reach, not by model. If a session needs VS Code's own tools, the Local harness is still the only one that has all of them.
