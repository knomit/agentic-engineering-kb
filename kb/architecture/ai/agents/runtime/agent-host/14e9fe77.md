# VS Code's Agent Host moves the agent session out of the editor window into its own process, and the Agent Host Protocol (AHP) is a state-first, one-host-many-clients protocol — not a harness

The VS Code Agent Host (shipped in VS Code 1.129, July 2026; formalized with the open protocol in the 2026-08-26 blog post) is a self-contained process that OWNS agent sessions. It runs either as a VS Code utility process or as a standalone server started with `code agent host`. Because the session lives in the host and not in a window: a session keeps running when the folder or window that started it closes; several clients (editor windows, the Agents window, a browser at insiders.vscode.dev/agents, a CLI) attach to the SAME live session and stay in sync; and a session continues when NO client is connected at all. The host can sit on another machine, reached over SSH or a dev tunnel. For the editor-spawned host, VS Code itself must stay running since it manages that host; the standalone host has no such dependency.

Stack: the host itself is TypeScript on Node, in the VS Code repo at `src/vs/platform/agentHost/node/`. The `code` CLI that supervises it is the Rust tunnel binary (its help banner reads `code-tunnel agent host`). So it is a Rust launcher plus a Node server, the same shape as `code tunnel`; it is not a native daemon. Platforms: Windows, macOS, Linux, wherever the VS Code CLI runs.

The Agent Host Protocol is MIT-licensed, JSON-RPC, and deliberately STATE-FIRST rather than event-first: a client subscribes to URI-addressed channels (root, session, chat, terminal, changesets, automation, resource watch, telemetry, MCP) and receives a snapshot followed by an ordered stream of Redux-like reducer actions stamped with `origin` and `serverSeq`; clients apply their own actions optimistically and reconcile against the server's echo. Harness-specific events are translated by adapters into 'durable, display-ready state'; code changes are modelled as generic changesets rather than harness internals. Transport is a message port / unix socket / named pipe with WebSocket framing locally, and WebSocket over TCP remotely. Client SDKs exist for TypeScript (`@microsoft/agent-host-protocol`), Rust (`ahp`, `ahp-types`, `ahp-ws`), Go (`github.com/microsoft/agent-host-protocol/clients/go`), Kotlin, Swift and .NET; third-party CLIs are `ahpx` and `ahpc`.

Version caution (pinned as of 2026-09-25): the protocol is 0.9.0 and explicitly pre-1.0 and 'under active development'. The local endpoint registry on one macOS machine held editor entries advertising 0.8.0 (2026-08-19) and 0.9.0 (2026-09-18), so the wire version moved a minor within a month. Consequence: any integration must pin the client SDK version and treat channel shapes as dated.

WHAT THIS DOES NOT MEAN: 'Agent Host' is not itself a coding agent or harness. It hosts harness ADAPTERS (Copilot, Claude, Codex in VS Code's implementation) and exposes them uniformly; which harnesses it can run is a separate question (see the harness matrix fact).
