# VS Code's Agent Host moves the agent session out of the editor window into its own process, and the Agent Host Protocol (AHP) is a state-first, one-host-many-clients protocol — not a harness

The VS Code Agent Host (shipped in VS Code 1.129, July 2026; formalized with the open protocol in the 2026-08-26 blog post) is a self-contained process that OWNS agent sessions. It runs either as a VS Code utility process or as a standalone server started with `code agent host`. Because the session lives in the host and not in a window: a session keeps running when the folder or window that started it closes; several clients (editor windows, the Agents window, a browser at insiders.vscode.dev/agents, a CLI) attach to the SAME live session and stay in sync; and a session continues when NO client is connected at all. The host can sit on another machine, reached over SSH or a dev tunnel. For the editor-spawned host, VS Code itself must stay running since it manages that host; the standalone host has no such dependency.

Stack: the host itself is TypeScript on Node, in the VS Code repo at `src/vs/platform/agentHost/node/`. The `code` CLI that supervises it is the Rust tunnel binary (its help banner reads `code-tunnel agent host`). So it is a Rust launcher plus a Node server, the same shape as `code tunnel`; it is not a native daemon. Platforms: Windows, macOS, Linux, wherever the VS Code CLI runs.

The Agent Host Protocol is MIT-licensed, JSON-RPC, and deliberately STATE-FIRST rather than event-first: a client subscribes to URI-addressed channels (root, session, chat, terminal, changesets, automation, resource watch, telemetry, MCP) and receives a snapshot followed by an ordered stream of Redux-like reducer actions stamped with `origin` and `serverSeq`; clients apply their own actions optimistically and reconcile against the server's echo. Harness-specific events are translated by adapters into 'durable, display-ready state'; code changes are modelled as generic changesets rather than harness internals. Transport is a message port / unix socket / named pipe with WebSocket framing locally, and WebSocket over TCP remotely. Client SDKs exist for TypeScript (`@microsoft/agent-host-protocol`), Rust (`ahp`, `ahp-types`, `ahp-ws`), Go (`github.com/microsoft/agent-host-protocol/clients/go`), Kotlin, Swift and .NET; third-party CLIs are AHPX and `ahpc`. Two of the project's own pages disagree on the SDK count and it is worth knowing which to trust for a dependency decision: the implementations guide lists five and calls them "The five clients shipped from this repository", omitting .NET, while the site's home page and the repository README's client table list all six. Treat the five-client sentence as the statement about what ships from that repository.

VERSIONING, and it is the part of this that moves fastest. The specification has reached 1.0.0 — the documentation site's hero button reads "Specification v1.0.0" — and its version selector offers "1.1.0 (draft)" alongside "1.0.0". The site carries no pre-1.0, stability or "under active development" caution. Versions are also not global: "Each language client and the spec itself release independently on their own SemVer tracks."

So there are three separately moving numbers, and conflating them is the error: the SPEC version, each CLIENT SDK's version, and the `protocolVersion` an individual running host advertises in its local endpoint entry. One macOS machine's registry held editor entries advertising 0.8.0 (2026-08-19) and 0.9.0 (2026-09-18) within a month of each other, and the spec reached 1.0.0 within weeks after that. Consequence: pin the client SDK version, read the host's advertised version from its registry entry rather than inferring it from the published spec, and date any channel shape you depend on by the spec release it was read from. The per-language package versions are published only as badge images in the repository README, so they cannot be read from the page text.

WHAT THIS DOES NOT MEAN: 'Agent Host' is not itself a coding agent or harness. It hosts harness ADAPTERS (Copilot, Claude, Codex in VS Code's implementation) and exposes them uniformly; which harnesses it can run is a separate question (see the harness matrix fact).
