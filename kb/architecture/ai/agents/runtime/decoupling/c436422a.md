# Decouple brain, hands, and session: an append-only event log is what lets a crashed harness resume instead of dying

Anthropic's Managed Agents architecture separates three things that agent harnesses normally fuse: the BRAIN (model plus harness), the HANDS (sandboxes, tools, execution environments), and the SESSION (an append-only event log). Their description of the prior coupled design is that agent infrastructure was treated as pets — hand-tended, and losing a container meant losing the entire session.

What each separation buys:

- Resilience. Because the session is a durable event log rather than in-process state, a failed harness reboots from the log via `wake(sessionId)` and a failed container is simply replaced through normal provisioning. In the coupled design engineers could not even tell a harness bug from a network fault from a container crash.
- Latency. Stateless brains no longer block on container provisioning when a sandbox is not immediately needed. Reported time-to-first-token improvement: p50 down roughly 60%, p95 down over 90%.
- Security. The coupled design kept credentials in the same container that executed untrusted model-generated code. Decoupled, credentials are bundled with resources or held in vaults outside the sandbox, so tokens are not reachable from the execution environment at all.
- Scale. A single container becomes a bottleneck as soon as one brain needs multiple hands. Each hand is instead exposed through a uniform `execute(name, input) -> string` interface.
- Placement. A decoupled brain works regardless of where the hands live — customer VPCs, custom infrastructure — because it no longer assumes resources are adjacent to the container.

The stated interface surface is `execute(name, input)`, `provision({resources})`, `wake(sessionId)`, `getSession(id)`, `emitEvent(id, event)`, and `getEvents()`, the last allowing the harness to interrogate context across positional slices of the log.

The design deliberately assumes nothing about the number of brains or hands, their physical location, or the harness implementation. What it does assume is that the agent will need durable state, computation, and room to scale to multiple brains and hands — so if your agent is short-lived and single-sandbox, this buys you very little for real added complexity.
