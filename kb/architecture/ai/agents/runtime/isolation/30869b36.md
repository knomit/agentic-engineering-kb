# Long-running agents need snapshot-and-resume, and container-level isolation cannot provide it

Cognition's stated reason for building on microVMs rather than containers is not primarily security — it is that real engineering work has ASYNC GAPS. An agent waiting on a CI run, a code review, or a human decision must survive "minutes, hours, sometimes days" between steps. Without snapshotting, an agent can only survive an async break by burning compute to stay alive, and "if the container is rescheduled, times out, or crashes, the session is lost."

Their solution is hypervisor-level state snapshots capturing memory, process trees, and filesystem, so a session can shut down entirely while idle and resume exactly where it left off. They report this as the single most time-intensive piece of infrastructure they built, on top of a year of hypervisor engineering for the microVM layer itself.

The design consequence worth carrying: if your agent workload has any waiting-on-external-systems step, the runtime question is not "how do I isolate this" but "how do I suspend and resume this," and those two requirements pick different substrates. A container platform answers the first and not the second.

The security argument is separate and also stated: containers sharing a kernel mean "one compromised session can access every other container's filesystems, credentials, and network connections" — which matters specifically because agents execute untrusted model-authored code.

They also name orchestration, governance, and integrations as three interdependent systems that all have to exist at scale, with orchestration alone consuming over three quarters of engineering time to run thousands of concurrent VMs — and report one company abandoning the effort when "the combined surface area became untenable." Read that as the build-versus-buy signal it is. Their headline customer result (Itaú, 17,000 engineers, 11 months): migrations 5–6x faster, 70% of static-analysis security vulnerabilities auto-remediated, test coverage 2x — vendor-reported, uncontrolled.
