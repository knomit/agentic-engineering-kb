# Four vendors document, in their own product docs, that their agent can be hijacked into exfiltration or code execution — and ship it; the warning is evidence of the drift, not a control against it

Johann Rehberger borrows Diane Vaughan's term for the Challenger analysis — "the process in which deviance from correct or proper behavior or rule becomes culturally normalized" — and applies it to agent deployment: "I use the term Normalization of Deviance in AI to describe the gradual and systemic over-reliance on LLM outputs, especially in agentic systems."

THE OBSERVATION THAT MAKES THIS MORE THAN A SLOGAN IS THE SIMULTANEITY, and it is the author's own framing: "Three years after ChatGPT shipped, vendors push agentic AI to users, but at the same time vendors are highlighting that your system might get compromised by that same AI - that drift, that normalization, is what I call 'The Normalization of Deviance in AI'." The evidence is four vendors' own published documentation, each quoted and linked in the post (Dec 4 2025):

* Microsoft's documentation warns that prompt injection "can override agent instructions, leading to unintended actions like data exfiltration or malware installation".
* OpenAI on ChatGPT Atlas: "We recommend caution using Atlas in contexts that require heightened compliance and security controls — such as regulated, confidential, or production data."
* Anthropic on a Claude feature: "we recommend you monitor Claude while using the feature and stop it if you see it using or accessing data unexpectedly."
* Google Antigravity: remote code execution via indirect prompt injection "is a known issue when the product first shipped, as is data exfiltration", per Google's own known-issues page.
* Windsurf Cascade: "No human in the loop feature for MCP tool calls."

THE OPERATIONAL POINT, AND IT IS THE ONE WORTH ACTING ON: a documented known hazard is not a mitigated hazard. Three of these five are mitigations that delegate the control to the user's attention — exercise caution, monitor it, stop it if you see something — which is the control that degrades fastest under repetition and volume. A programme that accepts "it is in the known issues" as closure has converted a disclosure into a permission. When auditing an agent deployment, read the vendor's own warnings as an inventory of hazards you must control yourself, and check whether anything in your stack actually enforces each one; a residual-risk register whose entries never close is the measurable form of this drift.

SCOPE AND MODALITY. This is one practitioner's framing, not a measurement: the post publishes no rate, no incident count and no CVE, and it names no threshold at which the drift becomes acceptable or unacceptable. What is verifiable is the roster — each quotation is attributed to a live vendor documentation page. The author's prescription is correspondingly general ("proper threat modeling, mitigations and oversight", "sandbox, hermetic environments, least privilege, temporary credentials", and keeping AI "human-led, particularly in high-stake contexts"), and that part is below the altitude at which it changes a design; the contribution is the diagnosis, not the remedy. The post closes "Trust No AI."
