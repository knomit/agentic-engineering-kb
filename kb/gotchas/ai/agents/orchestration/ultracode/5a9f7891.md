# One opt-in toggle removes three independent checks at once: ultracode drops the large-run warning, the concurrent-subagent limit and the auto-mode launch approval

Turning on ultracode in Claude Code (`/effort ultracode`, or the `ultracode` setting) makes Claude plan a workflow for every substantive task instead of waiting to be asked. The documentation treats that as opting in to large runs, and states that three checks stop applying while it is on:

- the `Large workflow` warning does not appear on a workflow run;
- the session's concurrent subagent limit is not enforced for the subagents Claude spawns with the Agent tool;
- in auto permission mode, you are not asked to approve the first workflow launch.

The cost side is stated plainly too: a single request can turn into several workflows in a row, each request uses more tokens and takes longer than the same request without a workflow, and on a subscription plan a session with ultracode on reaches a session or weekly limit sooner than the same work with it off.

The shape worth carrying away is that the three guards removed are the three that would otherwise have told you a run had grown unusually large. A session in this mode gives no in-band signal of scale, so scale has to be read out of `/workflows` and the model chosen in `/model` instead of waiting for a warning that will not come.

WHAT THIS DOES NOT MEAN: ultracode does not relax permission checks on the agents' own tool calls. The documentation states the keyword only chooses how Claude structures the work, and the agents' tool calls receive the same permission checks and sandboxing as any other tool call in the session. An organisation effort cap lowers the effort level a session with ultracode on runs at without turning ultracode off, and no managed setting rules out ultracode alone — disabling workflows entirely is what removes it.
