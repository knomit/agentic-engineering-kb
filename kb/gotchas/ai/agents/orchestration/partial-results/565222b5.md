# A stopped, failed or repeatedly stalled agent resolves to null inside parallel() or pipeline() and the run carries on — so a fan-out over N items can complete successfully with fewer than N results and no error anywhere

In Claude Code's dynamic workflows, "an agent() call resolves to null if you stop it mid-run or it hits an unrecoverable API error", and `pipeline()` KEEPS each null in its results array — which is why the documented example script ends with `.filter(Boolean)`. An agent that stalls ends the same way once its retries are spent: an agent whose output stops arriving for long enough restarts from the same prompt, at most five times counting any restart you ask for, and if the sixth attempt stalls too the `agent()` call fails. WHERE THAT FAILURE LANDS DEPENDS ENTIRELY ON HOW THE SCRIPT CALLED IT: "Inside parallel() or pipeline(): the run carries on with null in place of the agent's result"; "Awaited directly: the run ends with the error."

THE FAILURE SHAPE: a fan-out over N items can finish successfully carrying fewer than N results. A script that counts, ranks, aggregates or summarises its results array without separating null from a real result converts a partial run into a confident-looking complete answer, computed over the survivors, and nothing in the run's status says so. The null is the only signal, and it is the thing a convenience filter removes.

THE THREE ERROR ENDINGS ARE NOT INTERCHANGEABLE, and only one of them is a timeout worth tuning. `agent stalled on all 6 attempts` means every attempt went the whole window without output, and lengthening the window helps — `stallMs` on the one call, or `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS` for every agent, which also applies to subagents outside workflows. `agent lost its reply on all 6 attempts` means the response stream went silent and a streaming idle watchdog ended the response first, so lengthening the stall window does NOT help and `CLAUDE_STREAM_IDLE_TIMEOUT_MS` is the relevant knob. `agent abandoned after 6 attempts` means the attempts ended in different ways, which the error lists in order.

SIDE EFFECTS SURVIVE A RESTART WHILE THE TRANSCRIPT DOES NOT: "The new attempt starts without the stalled attempt's transcript. Files the stalled attempt already changed stay changed, and the tokens it spent stay in the run's total." An agent whose task is not idempotent can therefore apply its effect more than once while the orchestration observes a single result.

WHAT THIS DOES NOT MEAN: a null is not evidence that the model failed. Stopping an agent yourself produces the same value, and time an agent spends waiting on its own tool calls or on a usage-limit reset does not count toward the stall window, so a slow-but-working agent does not produce one.
