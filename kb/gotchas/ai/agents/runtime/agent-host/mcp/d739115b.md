# AHP gives a client no way to inject an MCP server into a session — the MCP channel only proxies traffic to servers the host already runs — so tool injection rides harness config discovery or client-contributed tools

Symptom: a client that creates AHP sessions expects to attach its own MCP server to each session through the protocol, and finds no command for it.

Cause: the AHP MCP channel is a side-channel that lets a client originate 'a constrained subset of MCP traffic against an MCP server the agent host is already running'. The host has initialized the upstream server before the client joins; the client 'is joining an in-flight session'. Only methods enabled by the host's advertised capabilities (`AhpMcpUiHostCapabilities`: server tools, resources, logging, sampling) are served. Nothing in the channel registers, configures or relays a client-supplied server. The spec's guide lists 'MCP relay' and 'Customizations' as PLANNED, not shipped (2026-09-25, AHP 0.9.0).

Two working routes:
1. Harness config discovery. The MCP config has to be where the harness reads it BEFORE `createSession`: for the Claude adapter that is a `.mcp.json` in the session's working directory or the user-level Claude config; for Copilot CLI/SDK `.mcp.json` / `.github/mcp.json`. Whether the Claude adapter honours a workspace `.mcp.json` is documented only in aggregate (VS Code issue #332083 does not split by harness), so verify on the target VS Code version.
2. Client-contributed tools. The host marks a tool call with `contributor.kind: 'client'` and a `clientId`; the owning client executes it locally once the call reaches `running`, streams partial content via `chat/toolCallContentChanged`, and finishes with `chat/toolCallComplete`. The server rejects completion actions from any client whose `clientId` does not match the contributor. Such a tool exists only while that client is connected.

Related undocumented corner: with no VS Code attached, how a STANDALONE `code agent host` obtains Anthropic credentials for the Claude adapter is not documented (with an editor attached, the client pushes bearer tokens through the `authenticate` command, RFC 6750 style, discovered via RFC 9728 protected-resource metadata). The third-party host ahpd states that Claude 'inherits daemon credentials unless a token is pushed'; VS Code's host has no equivalent statement.

WHAT THIS DOES NOT MEAN: that the MCP channel is useless. It is how a UI client renders MCP resources or drives MCP UI for a server the host runs. It is not a configuration surface.
