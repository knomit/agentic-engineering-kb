# Forced tool_choice and the old computer-use type became 400s across one model generation, and the computer-use one is still accepted on Amazon Bedrock — so the same request body is valid or fatal depending on the host

The thinking-parameter 400s across this model boundary are covered in [[ed084a84]]. The TOOL surface moved too, and one of its changes is host-dependent rather than model-dependent, which no per-model migration table will catch.

FORCED TOOL CHOICE IS GONE. A `tool_choice` of type `any` or `tool` returns a 400 on Claude Sonnet 5.5, including on the token counting endpoint — so a pre-flight token count written against the old shape fails before the real call does. The documented replacement is `{"type": "auto"}`, with the forcing moved into the tool definitions and the prompt: mark tools `strict: True`, set `additionalProperties: False` on every object in the schema, and state in the prompt when to use each tool. A scaffold that relied on forced choice to guarantee a call now relies on selection accuracy instead, which is a behavioural change and not only a syntactic one.

STREAMING FLAG. `fine-grained-tool-streaming-2025-05-14` returns a 400 when sent alongside a toolset entry; the replacement is per-tool `eager_input_streaming: true`.

THE HOST-DEPENDENT ONE. `computer_20251124` returns a 400 on the Claude API and on Google Cloud, where the replacement is `{"type": "computer_toolset_20260801"}` and the `computer-use-2025-11-24` beta header is removed. Amazon Bedrock still accepts `computer_20251124`. One request body is therefore valid on one host and fatal on another for the same model, so a deployment spanning hosts cannot keep a single computer-use request shape, and the migration check is per host rather than per model. Expect the convergence to come later and verify rather than assume it has.

A REFUSAL IS NOT AN ERROR AND WILL NOT APPEAR IN YOUR ERROR PATH. A declined request returns HTTP 200 with `stop_reason: "refusal"`, so handling keyed on status codes sees a success. Server-side fallback retries only the `cyber` and `frontier_llm` categories; it does not retry `reasoning_extraction`, `bio` or `general_harms`. Asking the model to write its reasoning into the response is what invites a `reasoning_extraction` decline, which means a prompt requesting visible reasoning buys a failure mode with no automatic retry behind it. Ask for a short stated justification of the approach instead.

ONE PARSER TRAP IN THE SAME MIGRATION. Read content blocks by iterating and testing `block.type`. `content[0].text` breaks whenever the first block is a `thinking` block, and between-tool notes longer than a sentence or two now arrive as `thinking` blocks that are empty at the default display — so a UI that used to show those notes silently shows nothing rather than erroring.

WHAT THIS DOES NOT MEAN. This is not a claim that forced tool choice or the old computer-use type are gone everywhere or permanently; it is one model generation on named hosts. The transferable part is that a model upgrade is an API-surface migration whose surface is indexed by host as well as by model, and that a refusal is a successful response.

SCOPE. Stated by the vendor at this model's launch. The Bedrock divergence in particular is the kind of thing that resolves without an announcement, so re-read it per host before designing around it.
