# Anti-laziness prompting inverts on model upgrade: emphatic tool instructions now cause overtriggering

Prompt patterns written to stop an older model under-using tools push current models the other way, and Anthropic's guidance says so directly. Where you wrote "CRITICAL: You MUST use this tool when…", current Claude models want plain "Use this tool when…" — the emphatic form overtriggers. The same inversion appears in three other spots: "If in doubt, use [tool]" now overtriggers; "Default to using [tool]" should become the conditional "Use [tool] when it would enhance your understanding of the problem"; and appended self-verification instructions ("Before you finish, verify your answer against…"), which used to reliably catch errors, cause over-verification on Claude Opus 5 because it already verifies its own work. For that last one the instruction is to REMOVE the line on migration, not to reword it more gently.

What makes this expensive is the failure signature. An under-triggering model gives you a visibly wrong or lazy answer, so you notice. An over-triggering one gives you the right answer after four unnecessary tool calls and a long thinking block — it degrades as cost and p95 latency, not as an error, so nobody files a bug and the prompt is never revisited. Treat every emphatic phrase in a system prompt as a dated workaround carrying the name of the model it was written against, and re-audit them on each upgrade.

This is not an argument against verification generally: an executable check the agent runs itself (a test suite, a linter) remains the right mechanism. What has stopped paying is the PROMPTED request for the model to re-read and second-guess its own output.
