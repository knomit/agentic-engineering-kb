# Anti-laziness prompting inverts on model upgrade — but the direction is PER-MODEL: emphatic tool phrasing overtriggers on Claude Opus 4.5 and 4.6, appended self-verification overtriggers on Opus 5 and should be deleted there, and Fable 5.1 leans the other way

Prompt patterns written to stop an older model under-using tools push a newer model the other way, and Anthropic's guidance says so directly — but EACH inversion is attributed to a named model generation, and the generations do not all lean the same way. Reading this as "current models overtrigger" is the available error.

**Attributed to Claude Opus 4.5 and Claude Opus 4.6 (the page's wording is "Claude 4.6 models"):** emphatic tool phrasing. "Claude Opus 4.5 and Claude Opus 4.6 are also more responsive to the system prompt than previous models. If your prompts were designed to reduce undertriggering on tools or skills, these models might now overtrigger. The fix is to soften any aggressive language. Where you might have said "CRITICAL: You MUST use this tool when...," you can use more normal prompting such as "Use this tool when..." instead." Alongside it: "Instructions such as "If in doubt, use [tool]" cause overtriggering", and "Default to using [tool]" should become the conditional "Use [tool] when it would enhance your understanding of the problem". The migration item is to "Tune anti-laziness prompting" because "Claude 4.6 models are more proactive and might overtrigger on instructions that were needed for previous models".

**Attributed to Claude Opus 5:** appended self-verification. The general advice is still to "Append something like "Before you finish, verify your answer against [test criteria]."", with Opus 5 named as the exception: "Claude Opus 5 is the exception: it verifies its own work well without explicit instruction, and verification instructions carried over from prompts tuned for earlier models can cause over-verification, adding tokens and latency." Here the instruction is removal, not softening: "On Claude Opus 5, remove these instructions rather than rewriting them."

**Subagent spawning, a third axis:** Claude Opus 4.6 "has a strong tendency to use subagents and might spawn them in situations where a simpler, direct approach would suffice", and "Claude Opus 5 also delegates to subagents more readily than prior models", for which the documentation points at a damping prompt.

**And the direction reverses on another model:** Claude Fable 5.1 "writes fewer user-facing updates between tool calls" — the under-doing side of the same axis. So the rule is not that newer models do more; it is that the bias is per-model and has to be looked up.

What makes this expensive is the failure signature. An under-triggering model gives you a visibly wrong or lazy answer, so you notice. An over-triggering one gives you the right answer after four unnecessary tool calls and a long thinking block — it degrades as cost and p95 latency, not as an error, so nobody files a bug and the prompt is never revisited. Treat every emphatic phrase in a system prompt as a dated workaround carrying the name of the model it was written against, and re-audit them on each upgrade.

This is not an argument against verification generally: an executable check the agent runs itself (a test suite, a linter) remains the right mechanism. What has stopped paying, on Opus 5 specifically, is the PROMPTED request for the model to re-read and second-guess its own output.

A trap for anyone reading the source to settle a question: the same page's own sample prompts still use the emphatic phrasing it warns about, with no model caveat attached — "you MUST read the file before answering" in one example block and "it is critical that you think outside the box!" in another. Take the guidance from the guidance sections and do not infer a recommendation from the examples.
