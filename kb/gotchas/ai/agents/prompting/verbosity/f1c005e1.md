# Instructing an agent to be terse costs measurable capability — a 25/100-word cap dropped ablation scores 3% on two models

In Anthropic's April 2026 Claude Code postmortem, one of three named causes of a reported quality regression was a system-prompt instruction added on April 16. Its full text: "Length limits: keep text between tool calls to ≤25 words. Keep final responses to ≤100 words unless the task requires more detail." It was reverted on April 20, and the postmortem states the change "impacted Sonnet 4.6, Opus 4.6, and Opus 4.7."

THREE QUALIFICATIONS THE 3% DOES NOT CARRY ON ITS OWN, all of which change how far it can be pushed. (1) The regression was invisible to the eval suite that gated the change: it shipped after "multiple weeks of internal testing and no regressions in the set of evaluations we ran", and the drop appeared only when a broader set was run during the incident investigation. (2) The source's wording is "One of these evaluations showed a 3% drop for both Opus 4.6 and 4.7" — one evaluation out of a broader set, not a suite-wide figure, and measured on the two Opus versions rather than on all three models the change affected. (3) The postmortem attributes the harm to this line "In combination with other prompt changes", so the 3% is not established as this instruction's isolated effect.

The instruction was already hedged — it ended "unless the task requires more detail" — and still cost measurable capability. A softened brevity instruction is not a safe version of this change.

The mechanism to reason from: for a tool-calling agent, the text emitted between tool calls is not decoration — it is where the model states what it just learned and what it intends next, and it conditions the following call. Capping it removes reasoning the model would otherwise have conditioned on. This makes brevity instructions a capability/UX tradeoff with a price tag, not a free style preference.

Boundary conditions worth stating, because the fact is easy to over-apply. The figure comes from a single evaluation on one harness and two model versions, so 3% is an order-of-magnitude signal rather than a constant. It says nothing against constraining the FINAL response alone, which was only half the instruction; the between-tool-call cap is the part that sits in the reasoning path. And the actionable form is procedural: Anthropic's own remedy was to run ablations on a broader eval suite for every system-prompt change, which implies that any prompt edit motivated by tone, cost or latency should be treated as an intelligence-affecting change until measured.
