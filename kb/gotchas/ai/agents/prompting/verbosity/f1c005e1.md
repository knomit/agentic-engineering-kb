# Instructing an agent to be terse costs measurable capability — a 25/100-word cap dropped ablation scores 3% on two models

In Anthropic's April 2026 Claude Code postmortem, one of three named causes of a reported quality regression was a system-prompt instruction added on April 16 telling the model to "keep text between tool calls to ≤25 words" and "keep final responses to ≤100 words." Ablation testing measured a 3% drop for both Opus 4.6 and Opus 4.7; it was reverted on April 20.

The mechanism to reason from: for a tool-calling agent, the text emitted between tool calls is not decoration — it is where the model states what it just learned and what it intends next, and it conditions the following call. Capping it removes reasoning the model would otherwise have conditioned on. This makes brevity instructions a capability/UX tradeoff with a price tag, not a free style preference.

Boundary conditions worth stating, because the fact is easy to over-apply. The figure is an ablation on one harness and two model versions, so 3% is an order-of-magnitude signal rather than a constant. It says nothing against constraining the FINAL response alone, which was only half the instruction; the between-tool-call cap is the part that sits in the reasoning path. And the actionable form is procedural: Anthropic's own remedy was to run ablations on a broader eval suite for every system-prompt change, which implies that any prompt edit motivated by tone, cost or latency should be treated as an intelligence-affecting change until measured.
