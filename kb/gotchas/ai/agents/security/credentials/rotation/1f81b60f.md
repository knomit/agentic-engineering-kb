# Rotating or deleting a stored agent credential changes nothing that is already running: the sandbox keeps the old value until a new session is created, and the upstream token stays valid at the provider

Three separate non-propagations are documented for OpenAI Agents API vault credentials, and each one breaks an assumption an operator would reasonably bring to a secrets store.

Rotation does not reach a running session: "Updating the vault does not change the credential already configured in an existing sandbox", and the remedy given is "Create a new session to use the replacement." So a rotation is not complete when the write succeeds; it is complete when every session started before it has ended.

Deletion is not revocation: "Deleting stored credentials does not revoke the original tokens with their providers or stop a running session." Pulling a credential out of the vault therefore removes your copy and leaves the attacker's. Revocation has to be done at the issuing provider, as a separate action.

Expiry is not deletion: "Token expiry does not delete the credential or its vault." An expired OAuth credential stays attached and stays listed; if the token cannot be refreshed, a valid replacement must be supplied. Supplying a new access token without an expiry clears the stored expiry, and an explicit `null` also clears it — so an omitted `expires_at` on a rotation silently drops the expiry you had.

THE CONSEQUENCE FOR INCIDENT RESPONSE. A credential compromise involving an agent needs three actions in order, not one: revoke at the provider, delete or replace in the vault, and end or restart the sessions that still hold the old value. Doing only the vault write looks like containment in the control plane and changes nothing in the data plane.
