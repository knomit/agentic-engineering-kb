# The agentic supply chain's payload is in the metadata, not the code — your reviewers read source, your agent reads descriptions

The organising insight, from the AI Agent Traps framework (Franklin et al., 2026): **the attacker's target is not the agent but the information environment the agent consumes** — tool descriptions, retrieval corpora, persistent memory stores, skill registries, web content. The agent's own capabilities are the attack mechanism.

Named techniques, all now observed rather than theorised:

- **Tool Poisoning Attacks** — malicious instructions hidden in tool *description* fields, invisible to human reviewers but processed by the model as trusted context. "The payload is not in the code but in the metadata, exploiting the gap between what humans audit and what agents consume."
- **MCP Rug Pulls** — tool descriptions change *after* approval. Approval is a point-in-time decision taken against mutable metadata.
- **Cross-origin escalation** — a malicious server shadows the tools of a trusted one.
- **postmark-mcp**, the first documented malicious MCP server in the wild: it spent *fifteen versions* building legitimacy before silently adding a single line of exfiltration code. Package age and release history are not evidence of intent.
- **CVE-2025-6514** (CVSS 9.6), a critical RCE in core MCP infrastructure used by hundreds of thousands of developers — the transport layer carried exploitable trust assumptions too, so this is not only a metadata problem.

The consequence for practice: **code review does not cover your agent's attack surface.** A review process that diffs source but not tool metadata is structurally blind to this entire class. Pin and diff tool descriptions across versions the way you pin dependencies, and re-verify on change rather than only at first approval — the rug-pull technique exists precisely because most integrations verify once.

This is the same lesson as the MCP spec rule already in the pack that tool *annotations* are untrusted and must not gate auto-approval. Descriptions are equally attacker-controlled and, unlike annotations, are fed directly to the model as guidance.
