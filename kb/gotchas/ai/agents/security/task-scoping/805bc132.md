# Task breadth is a security parameter — a broad instruction widens what injected content can steer toward without ever tripping the confirmation gate

OpenAI reports that giving an agent a very broad instruction — their example is "review my emails and take whatever action is needed" — makes it easier for hidden malicious content to mislead the model, and states this holds **even though the agent is designed to check with the user before taking sensitive actions**.

That qualifier is the part worth keeping. The intuitive model is that an approval gate makes task scope a quality concern rather than a security one: however wide the brief, anything dangerous still stops for a human. It does not work that way. A confirmation gate fires on an enumerated set of consequential actions; a broad brief expands the set of *plausible* actions the agent will take without ever reaching that set, and it also makes an attacker-suggested action look in-scope when the user is asked to approve it. "Take whatever action is needed" is exactly the instruction that makes an injected task indistinguishable from the assigned one — the user authorised an open-ended goal, so no specific step contradicts it.

The consequence for design: treat the breadth of the task specification as a control you tune, alongside tool permissions and approval gates, rather than as a UX preference. Narrow the brief where you can — name the accounts, the folders, the action verbs — and prefer several narrow invocations to one open-ended one. OpenAI is explicit that this does not guarantee attacks fail; it raises the attacker's cost.

**CONFIDENCE.** This is an asserted design observation in a consumer-facing explainer, not a measurement — no success-rate comparison between broad and narrow briefs is published. Treat the direction as sound and the magnitude as unknown.
