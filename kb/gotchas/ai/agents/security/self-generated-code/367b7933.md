# An agent that refuses to run an attacker's binary will still execute the attacker's code if it writes the loader itself — self-authored code inherits trust the inputs never had

A published attack chain against Claude Code Opus 5 in Auto Mode turns the agent's own safety-conscious decision into the exploit step. The reported success rate is the author's: "I got attack success rates up to 80% using a small sample size" — treat that as a demonstration of feasibility, not a measured rate.

THE CHAIN, and the shape matters more than the specific product. (1) A server answers a WebFetch with "415 Unsupported Media Type", which pushes the agent off its own fetch tool and onto `curl` — a TOOL DOWNGRADE driven entirely by a response code the attacker chooses. (2) The retrieved archive carries encoded data, a platform binary, and a file named `struct.py`. (3) The agent DECLINES to run the unfamiliar binary — the safety behaviour works. (4) So it writes its own Python decoder instead, and runs it from the directory the archive unpacked into. (5) That decoder imports `base64`; "The standard-library `base64` module imports `struct`", which resolves to the attacker's `struct.py` sitting alongside. Execution follows.

THE TRANSFERABLE FINDING — TRUST FOLLOWS AUTHORSHIP, NOT PROVENANCE. The agent applied real scrutiny to an artifact it received and none to an artifact it produced, even though the code it produced ran in an environment the attacker had populated. Any control that gates on "did this come from outside" is blind to this, because at the moment of execution the answer is no. The unit that needed checking was not the code but the CWD it ran in.

WHY THE CLASSIFIER DID NOT FIRE: every step is individually unremarkable — fetch a file, decline a binary, write a decoder, run it. This is [[bdf3336e]]'s per-hop/compose-across-hops shape with an unusually clean worked example, and it is [[92dc0441]]'s finding one layer in: there the agent influenced its execution environment through an allowlist, here through its working directory.

THE VENDOR RESPONSE IS THE MOST DECISION-RELEVANT PART, AND IT IS A SCOPE STATEMENT RATHER THAN A DISPUTE. Anthropic "closed the report as **Informative**" — not as a vulnerability — on the stated ground that "Auto Mode is a convenience feature backed by a best-effort classifier, not a security guarantee", positioning OS isolation and network controls as the actual security boundary. So the disagreement is not about whether the chain works; it is about what the classifier was ever claiming. Read this against [[89df351e]] and [[f1cbb540]], which describe that classifier's design from Anthropic's own engineering post: the architecture is real, and this fixes its scope. A tiered permission classifier is a false-positive reducer for ambiguous single actions. It is not a containment boundary, and the operator says so.

DO NOT MISREAD `python3 -I` AS A RECOMMENDATION FROM THIS POST. Isolated mode, which ignores the script directory on `sys.path`, appears here as something the ATTACKER's child process uses — "The child uses `python3 -I -c ...` to avoid recursively falling for the same shadowing attack". It happens to also be the correct defence for a harness that must run agent-authored Python in an untrusted directory, but that inference is this pack's, not the source's.

SCOPE AND WHAT IS NOT ESTABLISHED. Asked directly, the post does NOT state that the attack requires a pre-existing attacker-controlled directory — the directory becomes attacker-influenced through the download itself — and it does NOT report testing against any agent other than Claude Code. The "0.00%" figure the post contrasts itself against is the author's reading of a chart attributed to Anthropic ("the shared chart shows **0.00% attack success for Opus 5 in Auto Mode**"); this pack has not seen that chart and does not know its benchmark or threat model, so no gap between 0.00% and 80% should be computed from it — two numbers from two different evaluations do not license a comparison. Auto Mode is reported as "the default starting mode for Claude Code" since mid-August 2026, which is what makes the scope statement worth acting on rather than noting.
