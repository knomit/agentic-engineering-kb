# An in-process hook that inspects a command's text is bypassed by command substitution, aliases and any script that calls the dangerous binary — the vendor documents this of its own worked example and sends you to permission rules for a hard block

Claude Code mods are JavaScript or TypeScript modules that register hooks on events such as `tool.call`, and a hook can answer a call itself by returning `{ deny: "..." }` without passing the event on. The published tutorial builds a worked guard on that mechanism — one that intercepts destructive shell commands, lists the files they would delete, and holds them for confirmation — and then states its own limit: the guard reads the command text, so `$(...)` command substitution, shell aliases, and scripts that call `rm` themselves get past it. The tutorial's own remedy is to use permission rules for a hard block.

The mechanism is that the hook sees the string the agent proposed, while the damage is done by what the shell resolves that string into. Every layer of indirection the shell offers — substitution, alias expansion, a wrapper script, a Makefile target — separates the two, and the inspecting layer sits on the wrong side of the gap.

OPERATIONAL CONSEQUENCE. Place a text-inspecting hook where friction is the goal: showing the blast radius, prompting a human, logging intent for review. Do not count it as the control that makes a destructive capability unreachable. That control has to act on the effect rather than the spelling — a permission rule evaluated by the harness, a credential that cannot perform the write, or a filesystem the process cannot reach. If a threat model's only entry against a destructive action is a hook that pattern-matches the command, that entry is unfilled.

WHAT THIS DOES NOT MEAN. It does not mean the hook is worthless or that it should be removed; it caught the direct form of the command in the vendor's own demo, and surfacing what a command would do is a real contribution to a human's decision. It means the hook's value is in the decision it informs, not in a guarantee it cannot give, and it must not be the last line.

SCOPE. Stated by the vendor about its own extension API and its own example guard, as a documented limitation rather than a measured bypass rate; no incident or exploit is attached to it here.
