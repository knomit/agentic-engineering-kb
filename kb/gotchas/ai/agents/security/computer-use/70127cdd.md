# TOCTOU: a computer-use agent's click lands on a screen that changed during inference

Screenshot-driven agents have a time-of-check/time-of-use gap built into their loop: capture screen → reason (seconds) → click coordinates. The screen can change during the reasoning window, so the click lands on whatever occupies those coordinates now, not what the model saw.

The demonstrated exploit: a malicious page renders a "Continue" button exactly where Outlook's "Send" button will appear. The agent screenshots, decides to click Continue, and while it reasons (2-4 seconds) the attacker loads an Outlook draft via a crafted URL. The click lands on Send. The email goes out and nothing in the agent's trace records an intent to send anything. The researcher extended the window deliberately by injecting a request to compute "1+1 using bash", buying time for Outlook to finish loading — so inference latency is attacker-tunable, not fixed.

Why this defeats the usual controls: the agent's reasoning was correct, its logged intent was benign, and an approval prompt showing the intended action would have shown "click Continue". Auditing intent does not catch it.

The defense named is re-checking: snapshot when reasoning starts, and before acting verify nothing significant changed — Anthropic reportedly added pixel-change detection subsequently. If you build a computer-use loop, that check is not optional hardening, it closes the only gap the attack uses. Note the residual: "significant change" is a threshold, and a sufficiently small overlay may sit under it.
