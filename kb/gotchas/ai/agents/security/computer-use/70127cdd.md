# TOCTOU: a computer-use agent's click lands on a screen that changed during inference

Screenshot-driven agents have a time-of-check/time-of-use gap built into their loop: capture screen → reason → click coordinates. The screen can change during the reasoning window, so the click lands on whatever occupies those coordinates now, not what the model saw.

The demonstrated exploit (Johann Rehberger, published 2026-06-25): a malicious page renders a "Continue" button exactly where Outlook's "Send" button will appear. The agent screenshots, decides to click Continue, and while it reasons the attacker loads an Outlook draft via a crafted URL. The click lands on Send. The email goes out and nothing in the agent's trace records an intent to send anything.

THE ATTACKER CONTROLS THE WINDOW, WHICH IS THE PART THAT MAKES IT RELIABLE RATHER THAN LUCKY. The researcher widened the gap deliberately: "the prompt injection asked Claude to calculate `1+1` using bash. This means there is an additional bash command run, which takes enough time to successfully load the Outlook page." Any injected work that costs a tool round-trip buys the attacker more time — so the race is not a fixed-width window the defender can reason about, it is one the attacker can widen on demand. (That generalisation is this pack's; the source demonstrates the specific technique.)

WHY THIS DEFEATS THE USUAL CONTROLS: the agent's reasoning was correct, its logged intent was benign, and an approval prompt showing the intended action would have shown "click Continue". Auditing intent does not catch it — which also means a trajectory monitor reading the reasoning trace sees nothing wrong.

THE DEFENCE, in the source's words: "Ensure that the UI hasn't changed before taking an action, e.g take a snapshot when reasoning starts and when reasoning concludes check again that nothing significant changed." This shipped: the post reports the issue was addressed by Anthropic and quotes Felix Rieseberg in the Cowork announcement — "We also ensure that pixels haven't changed before action." If you build a computer-use loop, that check is not optional hardening; it closes the only gap the attack uses. Note the residual: "significant change" is a threshold, and a sufficiently small overlay may sit under it.
