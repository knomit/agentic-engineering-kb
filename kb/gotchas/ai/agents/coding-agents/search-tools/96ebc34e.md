# Agents overwhelmingly reach for keyword search, and adding more tools can make performance worse

Across **1,281 scored agent runs over 40+ large open-source repos**, Sourcegraph counted **7,993 keyword-search calls against 2,449 semantic-search calls**. Agents reach for grep by roughly 3:1 even when better retrieval is available to them. Do not assume that exposing a superior search tool means the agent will use it — tool availability and tool selection are separate problems, and the default lexical habit is strong.

The compounding failure they name is **tool thrashing**: one baseline run made "96 tool calls over 84 minutes (including 6 complete reversals of approach) and scored 0.32"; the same task with a structured search interface took "5 targeted search calls in 4.4 minutes and scored 0.68". MCP-augmented agents were "30% cheaper ($0.51 per task vs. $0.73 baseline) and 38% faster on average". The reversals are the tell — an agent that keeps abandoning and restarting its search strategy is signalling that its retrieval tools are not answering the question it has, and more turns will not fix it.

**THE MORE-TOOLS WARNING — QUOTATION AND CAUSATION CORRECTED 2026-07-30.** An earlier revision of this fact quoted the source as saying more tools "made performance worse due to poor strategic usage." That wording was this pack's, not Sourcegraph's, and it inverted the blame. What they actually say is that **"providing agents with more tools sometimes made this worse"** — where *this* is specifically **context overflow**, not general performance — because **"agents weren't given sufficient strategic information on when and how to use them."**

The corrected reading points at a different fix. The deficiency is in what the *builder supplied* — missing guidance on when and how each tool applies — not in the agent's judgement. "Poor strategic usage" invites you to conclude the model is bad at choosing tools and that a stronger model would help. The source's actual claim is that the tools were under-documented, which is repairable by you, today, without changing models. So: if you add structural search, make the keyword tool's description say when NOT to use it, and give each tool an explicit when-and-how-to-use statement rather than only a capability description.

Sourcegraph's own framing of the whole result: **"these are context problems, not intelligence problems"** — infrastructure (code search, indexing, retrieval pipelines) matters more than model capability for scaling agents to large codebases.
