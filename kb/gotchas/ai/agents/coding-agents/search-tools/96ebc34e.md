# Agents overwhelmingly reach for keyword search, and adding more tools can make performance worse

Across 1,281 scored agent runs, Sourcegraph counted 7,993 keyword-search calls against 2,449 semantic-search calls. Agents reach for grep by a factor of roughly 3:1 even when better retrieval is available to them. Do not assume that exposing a superior search tool means the agent will use it — tool availability and tool selection are separate problems, and the default lexical habit is strong.

The compounding failure they name is tool thrashing: one baseline run made 96 tool calls over 84 minutes with 6 distinct approach reversals (score 0.32); the same task with a structured search interface took 5 targeted calls in 4.4 minutes (score 0.68), 30% cheaper ($0.51 vs $0.73) and 38% faster on average. The reversals are the tell — an agent that keeps abandoning and restarting its search strategy is signalling that its retrieval tools are not answering the question it has, and more turns will not fix it.

The warning that matters most for tool design: they report that "more tools sometimes made performance worse due to poor strategic usage." Adding a retrieval tool without removing or clearly differentiating the ones it supersedes gives the agent more ways to thrash. If you add structural search, make the keyword tool's description say when NOT to use it.

Source caveat: Sourcegraph sells the structured-search product being measured here.
