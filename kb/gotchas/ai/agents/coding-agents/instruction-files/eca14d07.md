# A bloated agent instruction file causes rules to be ignored — concision is functional, not stylistic

Persistent instruction files (CLAUDE.md and equivalents) load into every session, so length is a direct tax on the attention available for the actual task. The failure this produces is specific and counterintuitive: adding a rule to fix a behaviour can make the agent follow FEWER of your rules, because important instructions get lost in the noise.

The diagnostic Anthropic gives: if the agent keeps doing something you have a rule against, the file is probably too long and that rule is being lost — the fix is deletion, not a stronger restatement. If it asks questions the file already answers, the phrasing is ambiguous.

Per-line test: would removing this cause mistakes? If not, cut it.

Include: bash commands the agent cannot guess, style rules that DIFFER from defaults, test runners, repo etiquette, project-specific architectural decisions, environment quirks, non-obvious gotchas.
Exclude: anything derivable from reading the code, standard language conventions the model already knows, detailed API docs (link instead), frequently-changing information, file-by-file descriptions, self-evident advice like "write clean code".

That exclude list is the same altitude test this whole discipline runs on — do not spend context telling a model what it already knows.

Two structural alternatives to growing the file: on-demand skills for knowledge relevant only sometimes, and hooks for anything that must happen every time — instructions are advisory, a hook is deterministic. If the agent already does something correctly without the instruction, delete the instruction or convert it to a hook.
