# Current models over-delegate to subagents, and this failure shows up as cost rather than as wrong answers

Anthropic documents that "Claude Opus 4.6 has a strong predilection for subagents and may spawn them in situations where a simpler, direct approach would suffice. For example, the model may spawn subagents for code exploration when a direct grep call is faster and sufficient. Claude Opus 5 also delegates to subagents more readily than prior models." Models now orchestrate subagents natively and "do so proactively without requiring explicit instruction", so merely HAVING subagent tools defined and described is enough to get this behaviour; you do not have to prompt for it.

This is a distinct failure from the standard case against multi-agent systems. That argument (Cognition's) is about correctness: dispersed context produces work products that do not fit together. Over-delegation is not a correctness failure — the answer is usually right. It costs you a fresh context window, a full summarization round-trip, and serialized latency for a question one tool call would have answered. So it lands in the bill and in p95 latency, where nobody is looking, rather than in an eval.

The damping guidance names conditions rather than banning delegation, and Anthropic publishes it as a drop-in prompt fragment: "Use subagents when tasks can run in parallel, require isolated context, or involve independent workstreams that don't need to share state. For simple tasks, sequential operations, single-file edits, or tasks where you need to maintain context across steps, work directly rather than delegating." Note that the first list is about the SHAPE of the work, not its size — a big task that is inherently sequential is still a direct-work task.
