# Current models over-delegate to subagents, and this failure shows up as cost rather than as wrong answers

Anthropic documents that Claude Opus 4.6 has a strong predilection for subagents and will spawn them where a simpler direct approach suffices — the named example is spawning subagents for code exploration when a single grep call is faster and sufficient. Opus 5 also delegates more readily than prior models. Models now orchestrate subagents natively without being asked, so merely HAVING subagent tools defined is enough to get this behaviour; you do not have to prompt for it.

This is a distinct failure from the standard case against multi-agent systems. That argument (Cognition's) is about correctness: dispersed context produces work products that do not fit together. Over-delegation is not a correctness failure — the answer is usually right. It costs you a fresh context window, a full summarization round-trip, and serialized latency for a question one tool call would have answered. So it lands in the bill and in p95 latency, where nobody is looking, rather than in an eval.

The damping guidance names conditions rather than banning delegation: use subagents when work can run in parallel, requires isolated context, or is an independent workstream that need not share state; work directly for simple tasks, sequential operations, single-file edits, and anything where context must carry across steps. Note that the first list is about the SHAPE of the work, not its size — a big task that is inherently sequential is still a direct-work task.
