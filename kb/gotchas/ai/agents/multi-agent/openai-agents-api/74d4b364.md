# A completed subagent create or wait action does not mean the subagent finished its task, and the coordination stream is not a transcript

In OpenAI's Agents API multi-agent model the harness executes the coordination actions, so the stream items `create_subagent_call`, `send_subagent_input_call`, `wait_for_subagents_call` and `interrupt_subagent_call` complete when the harness has performed the action — not when the delegated work is done. The guide says directly that a completed create or wait action does not mean the subagent finished its task.

Two related limits on observability. Coordination items can omit message content, and the stream does not provide a full conversation transcript of what a subagent did; subagent histories are available through saved items and turns instead. And attribution requires the turn field `subagent_id`, which is `null` for the main agent — without reading it, commands a subagent ran are indistinguishable from the coordinator's own.

Operational consequence: do not gate downstream work, a test, or a user-visible "done" on a completed wait item. Treat the coordination stream as a record of orchestration actions, and read the subagents' saved items and turns for their results. For anything you need to audit — which agent ran which command — persist `subagent_id` at the moment you record the turn, because the stream will not reconstruct it afterwards.

Also stated: the stream event `agent.session.subagent.created` reports the new subagent's ID, and with `environment.type: "none"` the initial input must be included in the create request, where setting `stream: true` streams the first turn.
