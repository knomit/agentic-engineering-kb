# Claude's text watermark rides on word choice, so it is weakest exactly where an agent's output is most constrained — code, exact answers, and edits of someone else's text

Anthropic published how Claude's text watermark works on 2026-08-14. It is a version of Google DeepMind's SynthID-Text (Nature, 2024) and it works by changing the SOURCE OF THE RANDOMNESS used to choose among candidate next words — the key plus a few preceding words settle the pick when several options are equally good. "Nothing is added to the text and there are no hidden characters", it needs no extra tokens and costs no more, and it carries no information about the user, their organisation or their conversations.

THE CONSEQUENCE FOR AN AGENT PIPELINE, and it is an inversion of what you would assume: the signal lives in lexical freedom, so it is thinnest precisely where the output is most determined. Anthropic states that "Where an _exact_ output is required...the watermark isn't applied", and that code "has generally less watermarking than some other forms of text". So the artifacts you would most want provenance on — generated code, structured or tool-shaped output, extracted facts — are the ones that carry the least detectable mark. Likewise, when Claude proofreads or edits human text, "there's very little (if anything) for the watermark to attach to" because most words are unchanged: a review or refactor step leaves close to no trace, while a full translation does carry the watermark because every word is Claude's.

LENGTH IS A HARD CONSTRAINT TOO: "Detecting a watermark also doesn't work well on small samples, where there are fewer word choices and thus less information to go on", and confidence rises with passage length. Anthropic publishes no token threshold. Short agent outputs — a tool argument, a JSON field, a one-line commit message — should be assumed undetectable.

ROBUSTNESS: "Light editing probably won't remove the watermark completely; a complete rewrite where every word is replaced will." So any pipeline stage that regenerates text through another model destroys the mark.

WHAT A POSITIVE DETECTION MEANS, stated by Anthropic and worth quoting to anyone proposing to build policy on it: it "can only determine that Claude was likely involved with the content at some point", and cannot distinguish "Claude wrote this" from "Claude heavily edited this". It cannot establish human authorship and does not detect other systems' output. It is a likelihood signal about one vendor's involvement, not an authorship test.

STATUS AND MODALITY: the post says the watermark applies to future Claude models at launch and that a detection API is coming — "We will soon be offering a watermark detection API" — with no implementation detail, and mentions no mechanism for disabling it. The stated driver is EU AI Act compliance. Confidence is held at 0.75 because the post supplies no detection rates, no false-positive rate and no minimum length, so every quantitative property here is qualitative in the source; re-check once the detection API documents its thresholds.
