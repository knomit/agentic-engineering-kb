# A spend cap set too low on a scheduled agent presents as a quiet day, not as an error — start at three to five times a normal run

"Start at three to five times the cost of a normal run, then tighten it as you see real numbers." The cap is expressed in minor units in the deployment config (`amount: "500"` with `currency: USD`, i.e. five dollars).

The trap is in how the limit presents: "a run that reaches it pauses with a `budget_reached` stop reason" rather than failing, so a cap set too low produces a short or empty report on a day that had material in it. For an agent whose correct output on a quiet day is nothing, a truncated run and a genuinely quiet one look the same from the outside.

Operational consequence: treat `budget_reached` as a monitored event in its own right, not as a benign stop, and set the first cap generously from measured runs rather than from a budget target. The same reasoning applies to any limit whose exhaustion degrades output instead of raising an error.
