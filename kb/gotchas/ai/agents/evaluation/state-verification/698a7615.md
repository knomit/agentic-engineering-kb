# Two-thirds of an agent's check-failing attempts end cleanly with no tool error — 67.24% of 79,853 failing attempts across 507 stateful workflows terminated cleanly, invoked a state-changing tool and reported no final error

ThinkingBox (built by Microsoft's Copilot Studio team with Toloka, published on the Hugging Face blog in October 2026) grades agents on executable checks against the BACKEND'S FINAL STATE rather than on the agent's closing message or its tool-call trajectory. "477 of the 507 tasks are graded on state alone"; the remaining few requirements, which have no clean database value, use a narrow binary rubric. Each attempt runs in an isolated MCP session from a freshly initialised state, and a side-effect extractor compares what actually changed against the required end state, rejecting wrong, missing AND extra effects.

The measurement is why a state check is not optional. In "a common-set ablation covering 121,680 valid trials across 12 LLM models", "79,853 attempts failed the executable checks" — and of those failures, "67.24% still terminated cleanly, invoked a state-changing tool, and reported no final tool error". The composition of the failures, which the post says overlaps: "Executable checks nevertheless found wrong field values in 77.61% of them", "unintended extra effects in 43.30%", "missing required effects in 25.36%".

OPERATIONAL CONSEQUENCE: a grader keyed on the agent's own report, on the absence of tool errors, or on whether a plausible tool sequence was emitted is blind to roughly two in three of this failure population — a wrong field value, a missing update and an unintended extra write all present to such a grader as a clean finish, and the extra-effect class is invisible to a checker that only verifies the required effects happened. An agent that writes to a system of record has to be graded by reading that system of record back, with the check rejecting effects it did not ask for. The post's own line: "A trajectory is a claim. Database state is the evidence."

WHAT THIS DOES NOT MEAN. The 67.24% is a share of FAILING attempts, not of all attempts. It is also not a production measurement: "every task in the public benchmark is a synthetic reconstruction" and "the customers are not real", with the workflows drawn from retail, auto insurance, travel, neobank and consulting domains. And it does not establish the remedies the post goes on to suggest — check terminal state before committing, classify tool errors so retries target recoverable ones, reduce the tool surface, require human approval for hard-to-reverse changes — which the authors say they have not measured.
