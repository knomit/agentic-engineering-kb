# About 30% of SWE-bench Pro's public split is broken, in four named ways, and OpenAI retracted its own recommendation to adopt it

OpenAI audited SWE-bench Pro's "731-task public split" and concluded "we estimate that ~30% of SWE-bench Pro tasks are broken". Two independent passes bracket that estimate: the automated-plus-agent pipeline "flagged 200 (27.4%) broken tasks" and "the human annotation campaign identified 249 (34.1%)". On no flagged task was "not broken" the most common human label.

Four distinct defect classes, which fail in opposite directions and so cannot be treated as one error bar:

- Overly strict tests enforce implementation details the prompt never specified, so a correct solution fails. The worked example is a `TocEntry.to_markdown()` task whose prompt shows one leading space while the hidden tests require two.
- Underspecified prompts omit requirements the hidden tests check and that are not reasonably inferable, so a reasonable solution fails.
- Low-coverage tests never exercise the requested feature, so a partial or wrong fix PASSES. This is the direction that inflates a score.
- Misleading prompts point at the wrong behaviour or contradict the tests.

The stated root cause is structural rather than sloppy authorship: tests harvested from pull requests validate one specific change rather than defining an implementation-agnostic standard, so a problem description, a merged diff and that diff's tests do not compose into a clean task.

The operational consequence: do not read a frontier pass rate on this benchmark as a capability measurement without auditing the tasks yourself, and do not read a gap of a few points between two systems as real. Because two of the four classes produce false failures and one produces false passes, the defects do not cancel and the direction of the bias depends on which class dominates your slice.

What this does NOT mean: it is not a claim that the reported frontier progress on this split (23.3% to 80.3% over eight months, per the same post) is fabricated, and it is not a general claim about every SWE-bench variant. The audit is of SWE-bench Pro's public split specifically.

A transcription trap in the source: the automated filter "flagged 286 potentially broken tasks" as CANDIDATES, and the pipeline then confirmed 200 of them. Do not quote 286 as the broken count.
