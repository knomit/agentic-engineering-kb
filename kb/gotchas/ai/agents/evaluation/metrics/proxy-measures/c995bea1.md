# Code volume is a weak proxy for agent effort, measured: a line-count predictor reached r_log^2 0.27 against 0.54 for a full session-trace estimator on the same held-out set

The temptation when instrumenting a coding agent is to count the diff, because lines changed are free to collect and session traces are not. Cognition measured the substitution and reported the loss: a regression on line counts "performed poorly, with an R^2_log of 0.27, confirming that code volume is a weak proxy for engineering effort", against r_log^2 = 0.54 for their trace-based estimator on the same held-out evaluation set.

THE STATED MECHANISM. Effort "often comes from" work that does not land as code volume — the article names investigation and iteration that is "not always in the final code change". A one-line fix after a long diagnosis and a large mechanical refactor are indistinguishable by diff size and far apart in effort.

CONSEQUENCE. Lines, commits and PR counts are availability metrics, not effort metrics; a dashboard built on them will rank the agent's cheapest work highest. If you need an effort signal, it has to come from the trajectory.

SCOPE AND CAVEATS. The line-count comparison is not a clean head-to-head on the full set: "The regression results below are for the 129 sessions in our evaluation dataset for which we have line-count data", out of "170 sessions in our evaluation dataset [that] created PRs", because some customers' git-hosting integrations do not return diff statistics. Both numbers are correlations against self-reported human hour estimates rather than against measured time, so this establishes that volume tracks that target worse than traces do, not that either tracks real effort.
