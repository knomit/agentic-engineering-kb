# 0% pass@100 almost always means the task is broken, not that the agent is weak

Anthropic's rule of thumb for reading agent eval results: a task scoring 0% pass@100 is most often a signal of a broken task rather than a genuine capability ceiling. The usual cause is an ambiguous specification — the success criteria are not stated clearly enough for any agent to satisfy them, so the agent fails through no fault of its own. Before concluding a model cannot do something, read the transcripts for that task.

Adjacent numbers from the same source, which are what make eval results interpretable:

- Dataset size to start: 20-50 simple tasks drawn from REAL observed failures is a good initial set. You do not need hundreds.
- Target pass rates differ by eval purpose and conflating them is a mistake. A CAPABILITY eval should start at a LOW pass rate — if it starts high it has no headroom to measure improvement. A REGRESSION eval should sit at nearly 100%, because its job is to catch breakage.
- Eval saturation is the failure at the other end: once a suite is at 100% there is no improvement signal left, and large real capability gains show up as tiny score movements.

Other named grading failure modes worth checking before trusting a low score: brittle grading that rejects valid variation (marking 96.12 wrong when 96.124991 was expected), class imbalance from testing only cases where the behaviour SHOULD fire — which over-optimises the agent into doing it everywhere — and grader bypasses, where the agent finds an unintended loophole instead of solving the problem.
