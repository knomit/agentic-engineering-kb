# The same model scores differently on the same benchmark across eval harnesses

A published benchmark number is a property of the model AND the harness that produced it, not of the model alone. The documented case: the same model gets significantly different MMLU scores under the HELM implementation, the EleutherAI implementation, and the original paper's implementation — differences arising from prompt formatting, answer extraction, and scoring choices rather than from anything about the model.

The practical rules that follow: never compare a number you measured to a number someone else published unless you ran the identical harness; when citing a competitor's or a vendor's benchmark claim, cite the implementation too; and when you build an internal eval, freeze the harness before you start tuning, because a harness change and a model change produce the same-looking delta on your dashboard.

This generalises past MMLU to agent benchmarks, where the surface area for harness divergence is larger still — scaffold, tool set, retry policy, and step limit all move the score, which is why agentic leaderboards separate native function-calling from prompt-based workarounds rather than pooling them.
