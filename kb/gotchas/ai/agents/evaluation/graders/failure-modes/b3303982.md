# A broken grader scores zero rather than erroring: a Python grader's exception or non-float return is graded 0, a score model's non-numeric answer is graded 0, and the sandbox that causes those failures is 256kB, no network, two minutes, two CPU cores

In OpenAI's grader API, a grader's own failure is indistinguishable from the model failing the test, because both come out as a zero on the same 0-to-1 scale.

THE TWO DOCUMENTED PATHS. For a Python grader: it "expects a grade function to be present that takes in two arguments and outputs a float value", and "Any other result (exception, invalid float value, etc.) will be marked as invalid and return a 0 grade." For a score-model grader: "The output of the grader will be truncated to the given range, and default to 0 for all non-numeric outputs" — so a judge that answers in prose, hedges, or wraps its number in an explanation scores 0, and a judge that returns a number outside the range is silently clamped rather than rejected.

THE LIMITS THAT PRODUCE THOSE FAILURES, which are tight enough to hit by accident: "Your uploaded code must be less than 256kB and will not have network access", "The grading execution itself is limited to 2 minutes", and "There's a limit of 2 CPU cores—any usage above this amount will result in throttling" (with 2GB memory and 1GB disk). A grader that calls out to an API, loads a large model, or runs a slow comparison does not report that it could not run; it reports that the sample failed.

CONSEQUENCE. A regression in your grader presents exactly like a regression in your system, and in the same direction, so the usual reaction — investigating the model — is wrong. Any eval run worth acting on needs a grader self-test: a known-good input that must score 1 and a known-bad input that must score 0, run alongside the suite. A score that drops while the known-good control holds is the cheap way to tell the two apart.

AN ADJACENT UNDEFINED FIELD. `pass_threshold` appears in the grader schema and in the documented examples, and no prose on the page defines what it does for any grader type. Do not assume it gates, filters or weights anything.

SCOPE. These are documented behaviours of one vendor's grader API, read from its reference page; nothing here measures how often the failure occurs. The page also publishes no accuracy, agreement or validation figures for any grader type, and gives no reason for any of the sandbox limits.
