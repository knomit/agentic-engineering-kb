# Eval trials that share state produce correlated failures that look like model regressions

Anthropic names shared state between trials as a distinct eval failure mode: "Unnecessary shared state between runs (leftover files, cached data, resource exhaustion) can cause correlated failures due to infrastructure flakiness rather than agent performance." Its prescription is explicit — "Each trial should be “isolated” by starting from a clean environment" — and its diagnostic is that a shared cause shows up as a shared symptom: "If multiple distinct trials fail because of the same limitation in the environment (like limited CPU memory)," the limitation is the finding. The symptom is a run where later trials degrade, or where a suite's score shifts between runs with no model or prompt change — and the natural but wrong reading is that the model regressed.

Each trial needs a fresh environment, not merely a fresh conversation. This is the eval-harness analogue of test pollution, and it is easy to miss because the agent under test is the thing that dirties the environment: it writes files, installs packages, and consumes quota as a normal part of doing the task.

CONTAMINATION IS THE SECOND, SHARPER CONSEQUENCE, AND THE SOURCE NAMES THE MECHANISM: "we observed Claude gaining an unfair advantage on some tasks by examining the git history from previous trials." So shared state does not only depress scores through flakiness, it can INFLATE them — a repository that carries earlier trials' commits is a leak of the answer, and the direction of the resulting bias depends on which trial the agent is in. A suite whose scores look suspiciously good deserves the same isolation audit as one whose scores look suspiciously bad.

The closely related trap is stochastic tasks. The source records them as something it ran into — "and stochastic tasks that were impossible to reproduce exactly" — and states the general requirement that "the environment itself doesn’t introduce further noise," but it gives no remedy for them. PACK ANALYSIS, not the source's advice: such a task yields an unreliable signal regardless of how good the grader is, so the two options worth considering are pinning the environment or excluding the task from the scored set.

This compounds with the separately measured finding that agentic coding eval scores move several points on CPU and RAM allocation alone: between infrastructure noise and trial contamination, a large share of apparent score movement in agent evals is not the agent.
