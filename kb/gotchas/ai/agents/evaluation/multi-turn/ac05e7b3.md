# Every turn can pass while the conversation fails — the failure is a property of the sequence, so it needs a thread-level evaluator that fires after the conversation ends

A turn-level eval suite can show a flat, healthy pass rate while the experience degrades, because each turn looks fine in isolation and the failure belongs to the whole exchange. LangChain's own example of such a property is the question "Did the user have to repeat themselves?" — which cannot be answered from any single turn, no matter how well that turn is scored.

The mechanism for catching it has two parts. Pass a thread ID in trace metadata so the turns of one conversation group together; then attach online evaluators that score the whole thread once the conversation has ended, rather than per turn. For offline testing the equivalents are storing full conversations as dataset examples, or simulating the user with an LLM so a multi-turn exchange can be replayed.

The same reasoning extends past the final message: check the path — the sequence of messages and tool calls — and the final state, such as a booking record or a file written, not only the last reply.

The operational consequence: do not read a stable turn-level score as evidence that the agent is working. Until a thread-level evaluator exists, an entire class of user-visible failure is outside what the suite can express, and adding more per-turn examples will not surface it.
