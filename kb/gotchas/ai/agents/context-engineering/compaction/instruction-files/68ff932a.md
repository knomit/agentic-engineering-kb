# Compaction re-reads only the project-root instruction file from disk — a rule that lived in a subdirectory file or in the conversation is gone after /compact, and the symptom is the agent quietly reverting to its defaults

Instruction persistence across a context-window transition is asymmetric, and only one half of it is automatic. "Project-root CLAUDE.md survives compaction: after `/compact`, Claude re-reads it from disk and re-injects it into the session." The other half: "Nested CLAUDE.md files in subdirectories are not re-injected automatically."

So a rule's survival depends on which file it was written in, not on whether it was followed before the compaction. The documented symptom, and the diagnostic, is that "If an instruction disappeared after compaction, it was either given only in conversation or lives in a nested CLAUDE.md that hasn't reloaded yet".

CONSEQUENCE. A long session is the exact case where subdirectory-scoped conventions are most needed and least likely to still be in force. If a rule must hold for the whole of a long run, it belongs in the project-root file, or in an enforcement mechanism, not in the subdirectory it is about. An instruction given only in the conversation does not persist at all: the documentation's remedy is to "Add conversation-only instructions to CLAUDE.md to make them persist."

WHAT THIS DOES NOT MEAN. This is not a claim that nested files never come back — they are included again when the model next reads a file in that subdirectory. It is a claim that nothing re-injects them at the moment of compaction, so there is a window in which they are absent, and nothing in the transcript marks it.
