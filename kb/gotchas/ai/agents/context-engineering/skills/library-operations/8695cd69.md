# A skill library fails silently in three directions as it grows: every checked-in skill taxes context, a skill referencing an uninstalled skill is a no-op with no dependency check, and a skill nobody triggers looks identical to a skill nobody needs

Three operational properties of Claude Code skills, reported by the team running a large internal library. Each is invisible until you go looking.

**Checked-in skills are not free.** Skills committed to a repository under `./.claude/skills` are the right distribution for a small team, and every one of them adds to the model's context — so the arrangement degrades as the library grows rather than failing at a threshold. Their answer past that point is an internal plugin marketplace, from which a skill is installed rather than being present by virtue of being in the tree. The decision variable is the size of the library you are asking every session to carry, not the number of people on the team.

**Cross-skill references have no dependency management.** A skill can reference another skill by name and the model will invoke it — if that skill is installed. There is no native dependency mechanism, so a composed skill whose dependency is absent does not error: the reference is just prose the model cannot act on, and the composite silently does less than it says. Anything you ship that references another skill by name needs its own check that the referenced skill is present.

**Under-triggering is unobservable without instrumentation.** A `PreToolUse` hook that logs skill usage is what tells you which skills are popular and, more usefully, which ones never fire. That matters because the description is the entire selection surface ([[e9b7eef3]]): a skill that is never selected and a skill that is never needed produce exactly the same signal — nothing — and only usage logging separates "the description does not match how people ask" from "this skill is dead weight".

The governance shape they report alongside these: no central team gatekeeps skills; people share them from a sandbox folder, and once one gains traction its owner opens a PR to promote it into the marketplace. That is a stated practice at one organisation, not a measured result.

WHAT THIS DOES NOT MEAN. The context tax is not an argument against progressive disclosure — the body of a skill is still read on demand, and it is the always-loaded metadata that accumulates. Nor does a marketplace remove the tax; it moves the choice of what to load from "whatever is in the repo" to an explicit install.
