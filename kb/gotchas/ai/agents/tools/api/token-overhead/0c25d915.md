# Forcing tool_choice costs extra system-prompt tokens on every request, and the overhead is per-model

Enabling tools on the Claude Messages API silently injects a tool-use system prompt that is billed as input tokens on every request, on top of the tool definitions themselves (names, descriptions, schemas) and the `tool_use` / `tool_result` blocks in the transcript. Two things about it are easy to miss:

- The cost depends on the tool_choice mode, not just on how many tools you pass. `auto` and `none` use the cheaper prompt; `any` and `tool` use a larger one. On Claude Opus 5 that is 286 tokens versus 406 tokens; on Sonnet 5, 354 versus 474. So reaching for forced tool use as a reliability fix imposes a standing ~120-token tax per request.
- The overhead varies substantially and non-monotonically across model versions — Opus 4.7 sat at 675/804 tokens while both its predecessor (Opus 4.5, 496/588) and its successors (Opus 4.8, 290/410; Opus 5, 286/406) are far lower. Do not carry a cost estimate across a model upgrade.

The one way to pay nothing: pass no `tools` at all with tool_choice `none`, which costs 0 additional system-prompt tokens. Passing tools and setting `none` does not get you back to zero.

What this does NOT mean: these figures are not the total tool-use cost. They exclude the tool definitions and every tool_use/tool_result block, which in an agentic loop dominate. Check the numbers against the live docs rather than trusting a cached value — they have changed with every model release.
