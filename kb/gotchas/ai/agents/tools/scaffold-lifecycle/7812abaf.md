# A tool built to correct a model weakness inverts when the model improves: Claude Code's todo reminders began making the model follow a stale list instead of revising it

Claude Code's TodoWrite tool existed to keep the model on track, reinforced by a system reminder inserted every 5 turns. The team reports that as models improved the same mechanism inverted: the todo reminders made the model stick to the list instead of REVISING it when it needed to change course. The scaffold's mechanism is adherence, and adherence is precisely what a stronger model needs less of.

A second pressure arrived with the same upgrade. Better subagent use (the post names Opus 4.5) raised a question the todo list had no answer for — how several subagents share one list.

The replacement separates the two jobs rather than extending the first. Todos keep a single model on track; the Task tool is a communication substrate, with dependencies, updates shared across subagents, and model-driven edits and deletes. The team's stated rule: "As model capabilities increase, the tools that your models once needed might now be constraining them."

The operational consequence is a testing obligation rather than a design rule: any scaffold that exists to correct a model weakness is stamped with the model version it was built against, and belongs on the upgrade checklist as a candidate for DELETION, not only for re-tuning.

The symptom to look for is the hard part. It is not an error and not a wrong answer — it is the model doing the scaffolded thing too faithfully, which reads as compliance rather than as a regression, and will pass an eval that scores adherence to the scaffold.
