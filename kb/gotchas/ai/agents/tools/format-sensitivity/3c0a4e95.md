# A published tool-calling score can move by more than 80 points on prompt format alone for the same model, and the sensitivity is not confined to small or open models

BFCL V4 carries a Format Sensitivity column group, reported as a maximum delta and a standard deviation across formats. It is populated for only some entries and reads N/A for most, but where it is reported the magnitudes dwarf the differences the ranking is built on. From the 2026-04-12 revision:

- Phi-4 (Prompt) max delta 81.5, SD 23.34; ToolACE-2-8B (FC) 81.5, SD 27.92; CoALM-8B 79.0, SD 34.18; Llama-3.1-8B-Instruct (Prompt) 74.5, SD 29.10; Gemma-3-12b-it (Prompt) 67.5, SD 22.41
- and it is not only small open models: Claude-Haiku-4-5-20251001 (Prompt) max delta 67.5, SD 20.07
- frontier entries in prompt mode sit an order of magnitude lower: Gemini-3-Pro-Preview (Prompt) 8.5 with SD 1.70, o3-2025-04-16 (Prompt) 8.5 with SD 2.75, Qwen3-235B-A22B (Prompt) 8.0 with SD 1.95, Claude-Opus-4-5 (Prompt) 13.0 with SD 3.65

Operational consequence: for any model whose reported delta runs into the tens, the single accuracy figure is a sample from a wide distribution, and your own prompt format decides where in that distribution you land. Treat format as a tuned parameter with its own measurement, and do not compare two such models on their headline numbers at all.

This does NOT mean format insensitivity is a capability ranking: the column is unreported for most entries, including every top-ranked FC entry, so a missing value says nothing either way.

Scope: as published on 2026-04-12. The leaderboard page states the column group's name and values; it does not state on that page which formats were varied, so the delta's span is uncharacterised and the number is a floor on sensitivity rather than a measurement of a specific change.
