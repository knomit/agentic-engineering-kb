# Diffs and JSON-wrapped code are expensive formats for a model to emit

Some tool input formats are structurally hard for a model to produce correctly, independent of how capable it is. Anthropic names two: diffs, which require the model to know line counts before it has written the new code; and code embedded in JSON, which forces escaping of newlines and quotes throughout. Both spend model attention on bookkeeping instead of the task, and both fail in ways that look like the model being careless.

The design rule: keep tool formats close to text the model has seen naturally occurring, and leave it enough tokens to think before it commits to a structure it cannot back out of.

Evidence that this dominates prompt tuning: building their SWE-bench agent, Anthropic spent more time optimising tools than the overall prompt. One concrete instance — the model kept mishandling relative filepaths; changing the tool to require absolute paths fixed it outright, after which the model used the method flawlessly. That is poka-yoke: rather than instructing the model harder, change the argument so the mistake is unrepresentable.
