# Two tool-design failures from one shipped tool: a second purpose bolted into an existing call with its interaction undefined, and structure requested as free text and then parsed

Claude Code's team describes three attempts at one tool — letting the agent ask the user a question mid-task — and the two failures name defects that are easy to repeat.

**Attempt one: add a `questions` array to the existing ExitPlanTool.** It confused the model, and the stated reason is not schema size. The call now asked for a plan AND questions about that plan at once, with no defined behaviour for what follows: what happens if the answers conflict with the plan just submitted, and whether the tool has to be called twice. Two purposes in one call with their interaction undefined is what broke it. That shape also carries a timing defect the post names separately — questions attached to the plan arrive too late, after the plan is already formed.

**Attempt two: have the model emit modified Markdown and parse it into UI.** Unreliable: the model would "append extra sentences, drop options, or abandon the structure altogether." Structure requested in free text is not enforced, so anything parsing it downstream is parsing best-effort output.

**What shipped:** a dedicated tool callable at any point, prompted especially in plan mode, which shows a modal and BLOCKS the agent loop until the user answers, returns structured output with multiple options, and is composable through the Agent SDK and skills. Blocking is what makes the answer usable at all — an answer that arrives after the agent has moved on is attempt one's timing defect again.

The team's framing is a spectrum from no structure (free but messy) to too rigid (structure bolted to another tool's lifecycle), with the working design in the middle, and the rule that gates all of it: "even the best designed tool doesn't work if Claude doesn't understand how to call it."

What this does NOT mean: not that multi-purpose tools never work, and not that Markdown output is unusable. The two defects are specific — an undefined interaction between two purposes sharing one call, and a parser that depends on structure the model was only asked for, not held to.
