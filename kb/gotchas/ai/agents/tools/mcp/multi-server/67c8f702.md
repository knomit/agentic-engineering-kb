# Two MCP servers connected to one client create a path neither server's review covers: one server's output can trigger the other's tools

OWASP's cheat sheet for consuming third-party MCP servers names five risk classes, and four of them are properties of a single server — tool poisoning (malicious commands in a tool's description or parameters, "a form of indirect prompt injection"), rug pull ("a legitimate tool is secretly replaced with a malicious version"), prompt injection, and memory poisoning. The fifth is a property of the SET of connected servers: **tool interference**, which it defines as one server's output triggering another server's tool, with three stated consequences — data leakage, accidental operations, and denial-of-service loops between servers.

The operational consequence is that the unit of review is the set of servers a client has connected, not each server on its own. A per-server audit cannot see this class however thorough it is, because the interaction does not exist in either server; the client creates it by placing one server's results in a context where the model can act on them with another server's tools. A team that approves servers one at a time, each by a different reviewer, has no step at which this is examined.

The mitigations OWASP names for it are three and they are not interchangeable, because they address different halves of the mechanism: **Require Human-in-the-Loop** for actions that follow from another server's output, **Separate Context** so one server's output is not presented to the model as material the other may act on, and **Set Timeouts** so a loop between two servers terminates. Context separation is the only one that prevents the trigger; the other two bound the damage after it fires.

WHAT THIS DOES NOT MEAN. It is not prompt injection under another name, and reading it that way loses the cases that matter. The triggering output need not be adversarial or crafted — a benign result that reads like an instruction is enough to select the second server's tool — and the denial-of-service case needs no attacker at all, only two servers whose outputs each look to the model like a reason to call the other.
