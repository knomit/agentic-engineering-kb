# The MCP confused-deputy attack needs four conditions together — a static client ID is only one of them

MCP proxy servers (an MCP server that fronts a third-party API and acts as a single OAuth client to it) can be turned into a confused deputy that hands an attacker an authorization code without the user ever seeing a consent screen. The spec is precise that the vulnerability requires ALL FOUR of these simultaneously — checking only one will not tell you whether you are exposed:

1. the proxy uses a static client ID with the third-party authorization server;
2. the proxy lets MCP clients dynamically register, each getting its own client_id;
3. the third-party authorization server sets a consent cookie after the first authorization;
4. the proxy does not enforce its own per-client consent before forwarding to the third party.

The flow: the user legitimately authorizes once, which leaves a consent cookie scoped to the proxy's static client ID. The attacker dynamically registers a client with `redirect_uri: attacker.com` and sends the user a crafted authorization link. The third-party server sees the existing cookie, skips consent entirely, and the resulting MCP authorization code is redirected to the attacker, who exchanges it for a token and impersonates the user.

The mandated fix is a consent gate the proxy owns, running BEFORE the third-party redirect, with per-client consent stored server-side and checked by client_id. Supporting MUSTs: exact-string redirect_uri matching against the registered value (no wildcards or pattern matching), re-registration required if it changes, CSRF protection and anti-framing on the consent page, `__Host-` prefixed / Secure / HttpOnly / SameSite=Lax signed consent cookies bound to the specific client_id rather than to "user has consented".

The subtlest requirement concerns ordering: the `state` tracking cookie or session MUST NOT be set until after the user approves the MCP-level consent screen, and must be set immediately before the redirect to the third-party IdP. Setting it earlier makes the consent screen decorative — an attacker can craft a request that sails past it.
