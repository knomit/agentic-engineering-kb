# MCP deprecated Roots, Sampling and Logging — and every suggested migration routes around MCP rather than through it

Revision `2026-07-28` moved three long-standing MCP features into the Deprecated state (SEP-2577). They remain fully functional during the deprecation window — at least twelve months, or ninety days under the expedited-removal exception — but new implementations should not adopt them.

The striking part is **where the spec points you instead**. In all three cases the suggested migration leaves MCP rather than using another MCP mechanism:

- **Roots** → pass directories or files via tool parameters, resource URIs, or server configuration.
- **Sampling** → integrate directly with the LLM provider's API. In other words: if your MCP server wants model inference, call the model yourself; do not borrow the client's.
- **Logging** → write to `stderr` (on stdio) or use OpenTelemetry.

Read alongside the removal of server-initiated requests, the pattern is clear and worth planning against: MCP is narrowing to a **tool-and-resource protocol**, shedding the features that made the client a service the server could call. If your architecture assumed the client would lend the server its model or its filesystem view, that assumption now has a removal clock on it.

Also newly Deprecated in this revision:

- **OAuth 2.0 Dynamic Client Registration (RFC 7591)** as a client registration mechanism, in favour of **Client ID Metadata Documents**. DCR stays available for backwards compatibility with authorization servers that do not support CIMD. Note this interacts with the confused-deputy attack surface, where a statically-registered client ID is one of the preconditions.
- **HTTP+SSE transport** — deprecated since `2025-03-26`, now formally reclassified under the lifecycle policy (SEP-2596). Migrate to Streamable HTTP.
- **`includeContext` values `"thisServer"` and `"allServers"`** — soft-deprecated in `2025-11-25`, now formally Deprecated. Omit the field or use `"none"`. These will be removed no later than Sampling itself, which is the tell that they were only ever meaningful as Sampling inputs.

For tracking, the revision also established a published **registry of currently-deprecated features**, so this list is checkable rather than something to reconstruct from changelogs.
