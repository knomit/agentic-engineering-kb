# MCP deprecated Roots, Sampling and Logging — and every suggested migration routes around MCP rather than through it

Revision `2026-07-28` moved three long-standing MCP features into the Deprecated state (SEP-2577). They remain fully functional during the deprecation window — at least twelve months, or ninety days under the expedited-removal exception — but new implementations **SHOULD NOT** adopt them and existing ones **SHOULD** migrate before the earliest removal.

The striking part is **where the spec points you instead**. In all three cases the suggested migration leaves MCP rather than using another MCP mechanism:

- **Roots** → pass directories or files via tool parameters, resource URIs, or server configuration.
- **Sampling** → integrate directly with the LLM provider's API. In other words: if your MCP server wants model inference, call the model yourself; do not borrow the client's.
- **Logging** → write to `stderr` (on stdio) or use OpenTelemetry.

Read alongside the removal of server-initiated requests, the pattern is clear and worth planning against: MCP is narrowing to a **tool-and-resource protocol**, shedding the features that made the client a service the server could call. If your architecture assumed the client would lend the server its model or its filesystem view, that assumption now has a removal clock on it.

Also newly Deprecated in this revision:

- **OAuth 2.0 Dynamic Client Registration (RFC 7591)** as a client registration mechanism (PR #2858), in favour of **Client ID Metadata Documents**. DCR stays available for backwards compatibility with authorization servers that do not support CIMD. Note this interacts with the confused-deputy attack surface, where a statically-registered client ID is one of the preconditions.
- **HTTP+SSE transport** — deprecated since `2025-03-26`, now formally reclassified under the lifecycle policy (SEP-2596). Migrate to Streamable HTTP. Its earliest removal is the nearest of any entry: **three months after SEP-2596 reaches Final**, not the twelve-month default.
- **`includeContext` values `"thisServer"` and `"allServers"`** — soft-deprecated in `2025-11-25`, now formally Deprecated. Omit the field or use `"none"`. Their removal *follows Sampling's*, which is the tell that they were only ever meaningful as Sampling inputs.

**Concrete dates, from the deprecated-features registry.** Roots, Sampling, Logging and DCR all carry the same earliest removal: **the first revision released on or after 2027-07-28**. Two things about that phrasing are load-bearing. First, "earliest removal" marks when a feature becomes *eligible* for removal — actual removal is a Core Maintainer decision taken during release preparation and may happen later, so the date is a floor on your migration deadline, not a prediction of it. Second, because MCP revisions are dated and irregular, the trigger is the next revision after that date, not the date itself.

As of this revision **no feature has ever been removed under this policy** — the registry's Removed section is empty. So the twelve-month window is a stated commitment with no track record behind it yet; do not treat observed stability as evidence the policy will be honoured generously.

For tracking, the registry is a published, derived view kept consistent with the per-feature deprecation notices and changelog entries, **which remain the normative records** — so the registry is the convenient checkable list, not the authority.
