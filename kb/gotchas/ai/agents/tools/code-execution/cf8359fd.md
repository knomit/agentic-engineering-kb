# Returning only the aggregated artifact removes the model's ability to notice the aggregation was wrong — the context you saved is the evidence that would have caught it

Sourcegraph describes running a sandboxed script around its search APIs for code migrations: the script issues several searches, cross-references and filters the results, computes totals and emits an artifact such as a CSV checklist of every repository still importing an old package. "The LLM then receives only the aggregated findings and the final artifact" — the intermediate results never enter context. The stated benefits are cost, structure, and keeping the model on "synthesizing conclusions rather than acting as a data processor".

THE DEFECT THIS NAMES is not in the pattern's economics, which hold; it is in what the pattern removes. The script's filtering, cross-referencing and join logic is now the only thing standing between the raw search results and the answer, and the model — the component that would otherwise have read the raw results and noticed a suspicious shape — no longer sees them. An over-narrow filter does not surface as an error; it surfaces as a shorter checklist that looks finished. For a migration checklist that is precisely the failure that matters, because a silently incomplete list of call sites reads exactly like a complete one.

The source does not close this. It expresses confidence that the report is "comprehensive and accurate" without stating how that is verified, and it does not discuss what happens when the script's logic is wrong.

WHAT TO DO, and it is one step: when you adopt script-mediated aggregation for context economy, add a check that does not depend on the model having seen the data. Reconcile the artifact's count against an independent query, or spot-check a sample of raw results against the artifact. The check has to be external precisely because the model's own review is what the pattern traded away.

SCOPE, as the source states it: it frames the approach for "any search-driven artifact generation" and makes no claim for tasks that require reading or reasoning over full file contents.

WHAT THIS DOES NOT MEAN: it is not an argument against programmatic tool calling, which kb/architecture/ai/agents/tools/code-execution/fc911d9c.md documents along with the conditions where it wins and the vendors' own statement that hiding intermediate results is wrong when the model should reason over them. This fact is about the case where the pattern IS the right choice, and names the verification step that case still owes.
