# A retrieval tool's filter argument is a model-controlled string that gets EVALUATED — Semantic Kernel's vector-store search (CVE-2026-26030, CVE-2026-25592) is the worked example, and its sandbox shipped its own file-transfer escape

Two Semantic Kernel vulnerabilities disclosed on 7 May 2026, with fixes preceding publication, recorded in OWASP's Q2 2026 exploit roundup. They affect Semantic Kernel Python and .NET configurations, and the pair makes one general point about where a model's output lands.

- **In the In-Memory Vector Store search path, MODEL-CONTROLLED search arguments reached unsafe Python filter EVALUATION**, bypassing the intended restrictions. Microsoft identifies Python `semantic-kernel` 1.39.4 or later as the fix for the vulnerable vector-store path.
- **In `SessionsPythonPlugin`, a file-transfer helper had an unrestricted HOST destination**, so output produced inside the sandbox could be written outside its boundary.

The tracked identifiers for the pair are CVE-2026-26030 and CVE-2026-25592; the roundup does not state which number attaches to which of the two paths, so cite them as the pair rather than splitting them.

The first is the one that generalises. A retrieval tool reads like the safe kind — it returns documents, it changes nothing — and its filter argument looks like data. But that argument is written by the model, the model's input includes untrusted text, and the argument is EVALUATED, so the path from a poisoned document to code execution runs entirely through a read-only-looking tool with no write capability anywhere in it. Treat any tool parameter that reaches an evaluator, a query compiler or a template engine as an injection sink regardless of what the tool itself does.

The second names a sandbox anti-pattern worth checking for by name: an escape hatch shipped WITH the sandbox. A helper whose purpose is moving files between sandbox and host is, by construction, a hole in the boundary unless its destination is constrained — the sandbox is only as strong as the most permissive helper shipped alongside it, and that helper is usually in the same package and enabled by default.

OWASP's stated mitigations: apply the SDK fixes, allowlist tool arguments and filesystem roots, remove unnecessary helpers, and isolate host credentials.
