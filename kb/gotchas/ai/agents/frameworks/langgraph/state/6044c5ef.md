# In LangGraph, two parallel nodes writing the same state key without a reducer is an error, not a last-write-wins

LangGraph executes on Pregel-style supersteps: nodes that run in parallel within one superstep all propose updates, which are then merged at the superstep boundary. Each state key is a typed channel, and the channel's reducer decides how concurrent updates combine — `LastValue` (keep the most recent, the default for a plain field), `BinaryOperatorAggregate` (fold, e.g. sum or list-concat), `add_messages` (append to a message list with id-based dedup), `Topic` (event-stream semantics).

The failure this produces: fan out to several nodes that each write the same key, leave that key on the default `LastValue` channel, and the run raises `InvalidUpdateError` at the superstep boundary rather than silently picking a winner. The fix is to declare a reducer on any key that more than one concurrently-running node writes — which means the fan-out shape of your graph, not just the data type, determines the correct state annotation.

The corollary that catches people: a graph that works fine sequentially can break the first time you parallelise a branch, because the same state schema was legal under one-writer-per-superstep. Decide reducers when you add the fan-out, and note that `Send` (dynamic fan-out to N instances of a node, the map half of map-reduce) always produces concurrent writers by construction.
